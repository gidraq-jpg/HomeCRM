# API дел и быстрая строка — R1c.1–2

Требования TASK-1, TASK-2, TASK-8; решение — [ADR-0038](adr/0038-tasks-quickline-api.md). Все маршруты требуют входа и используют существующие проверки CSRF и RLS. Скрытый UUID даёт 404; отказ в действии над видимой записью — 403.

## Поля дела

`title` — 1–200 символов; `description` — до 20 000, по умолчанию пусто. `planOn`, `dueOn`, `checkOn` — `YYYY-MM-DD` или `null`; `planTime`, `dueTime` — `HH:mm` или `null`, требуют соответствующей даты. Время относится к поясу дома. `status`: `open`, `done`, `cancelled`, `not_done`, `waiting`, по умолчанию `open`. У `waiting` обязательны дата проверки и ровно один из `waitingContactId`, `waitingAccountId` (UUID). После физического удаления контакта прежнее ожидание допускает обычную правку без нового адресата; повторно установить такое ожидание нельзя. Скрытый или удалённый адресат в ответе — `null`, `waitingFrom` содержит доступные `{id,title}` либо `null`.

`checklist` — до 100 пунктов `{id: UUID, title: string, done: boolean, position: integer}`; UUID уникальны, название 1–500 символов, порядок 0–1000. Правка заменяет весь массив. Даты без времени остаются датами; `doneAt` — UTC-момент выполнения, сбрасывается при возврате в другой статус. Прежний `dueAt` доступен для совместимости и не принимается для новой правки.

Карточка также содержит общие поля записи, `householdId`, `files`, `createdAt`, `updatedAt`, `deletedAt`. Датированному личному делу нужен дом участника для пояса: по умолчанию выбирается первый UUID активного членства, при создании можно явно передать `householdId`.

## Маршруты

| Метод и путь | Запрос и результат |
|---|---|
| `GET /api/tasks` | Массив карточек; `filter=mine\|assigned\|undated\|waiting`, `status`, `objectId`, `scope=all\|personal\|household`, `trash=true\|false`, `limit=1…100` (50), `offset=0…50000` (0). «Моё» — исполнитель текущий участник; «назначил» — автор текущий, исполнитель другой; «без даты» — нет даты плана. |
| `GET /api/tasks/:id` | Карточка, включая доступную запись корзины. |
| `POST /api/tasks` | Поля дела; необязательные `placement:{spaceId,audience}`, `assigneeId`, `householdId`, `objectId`, `links:[{type,id,role}]`, `idempotencyKey`. 201. Без объекта и placement создаётся в личном. Объект задаёт размещение по умолчанию и связь. |
| `PATCH /api/tasks/:id` | Частичные поля дела, `assigneeId`, `expectedUpdatedAt`, `idempotencyKey`. 200. Пропуск поля сохраняет значение. |
| `POST /api/tasks/:id/status` | `status`, необязательные поля ожидания, `expectedUpdatedAt`, `idempotencyKey`. 200; повтор текущего статуса не создаёт историю. |
| `GET /api/tasks/:id/history` | История с прежней аудиторией снимка; адресаты ожидания скрыты, смена отмечена `waiting_changed`. |
| `POST /api/tasks/:id/move` | `{spaceId,audience?,assigneeId?,confirmed:true}`. Каскад файлов и сроков; чужой содержательный вклад запрещает перенос общего в личное. |
| `POST /api/tasks/:id/trash` или `DELETE /api/tasks/:id` | Пустое тело; корзина. |
| `POST /api/tasks/:id/restore` | Пустое тело; восстановление с общими правилами авторства и администратора. |

`links.type` — `object`, `contact`, `document`, `utility_charge`. Для последующей правки связей действуют общие `/api/links` и `/api/records/task/:id/links`; обычная правка дела их не заменяет. Новые концы должны быть живыми и видимыми. Файлы используют существующий контракт `/api/tasks/:id/files` и `/api/files/:id` (загрузка и чтение); корзина и восстановление файла — `/api/tasks/:id/files/:fileId/trash|restore`. Поиск `/api/search` возвращает тип `task`, раздел «Дела». Экспорт включает `tasks`, `task_files`, историю и производные сроки.

Невидящий назначаемый исполнитель: `409 {code:"ASSIGNEE_NOT_VISIBLE",requiresAudienceExpansion:true}`. Неверная версия: 409; неверный или повторно использованный с другим телом ключ: существующий конфликт идемпотентности. Расширение аудитории выполняется отдельным явным переносом, автоматически API его не делает. `HOUSE_REQUIRED` — 400 при датированном личном деле без дома.

В `GET /api/deadlines` добавлены `taskId` и `sourceKind=task_plan|task_due|task_waiting`. Статусы `done`, `cancelled`, `not_done` и корзина выключают напоминания. Для изменения дат и выполненности используются маршруты дела. Без времени предупреждение в 09:00 по поясу дома, с временем — в указанный час. В push не читается название дела; скрытие текста даёт существующий общий текст приложения.

## Общая функция

`parseQuickline(input, {now: Date, timeZone: string, members: [{id,name}], objects: [{id,name}]})` возвращает `{title,planOn,planTime,assigneeId,objectId,fragments}`. Фрагмент: `{kind,start,end,text,value}`, `kind=date|time|assignee|object`, диапазон `[start,end)` в UTF-16 исходной строки. Клиент может вернуть `text` в строку при снятии чипа; запросов к API для разбора нет.

Поддерживаются сегодня, завтра, послезавтра, через неделю/число дней, «в пятницу»/«в пт», календарные даты словами и числами, время, `@имя`, `#объект`. «В 5» — 05:00; прошедшая дата без года — следующий год; день недели — ближайший следующий, включая +7 при совпадении. Неизвестное и неоднозначное сохраняется. Одно распознанное значение каждого вида; последующие остаются в названии. Повторы дел и интерфейс вынесены в следующие задачи.
