# API дел, повторы и назначение — R1c.1–4

Требования TASK-1…11; решения — [ADR-0038](adr/0038-tasks-quickline-api.md) и [ADR-0039](adr/0039-task-repeats-assignment.md). Все маршруты требуют входа и используют существующие проверки CSRF и RLS. Скрытый UUID даёт 404; отказ в действии над видимой записью — 403.

## Поля дела

`title` — 1–200 символов; `description` — до 20 000, по умолчанию пусто. `planOn`, `dueOn`, `checkOn` — `YYYY-MM-DD` или `null`; `planTime`, `dueTime` — `HH:mm` или `null`, требуют соответствующей даты. Время относится к поясу дома. `status`: `open`, `done`, `cancelled`, `not_done`, `waiting`, по умолчанию `open`. У `waiting` обязательны дата проверки и ровно один из `waitingContactId`, `waitingAccountId` (UUID). После физического удаления контакта прежнее ожидание допускает обычную правку без нового адресата; повторно установить такое ожидание нельзя. Скрытый или удалённый адресат в ответе — `null`, `waitingFrom` содержит доступные `{id,title}` либо `null`.

`checklist` — до 100 пунктов `{id: UUID, title: string, done: boolean, position: integer}`; UUID уникальны, название 1–500 символов, порядок 0–1000. Правка заменяет весь массив. Даты без времени остаются датами; `doneAt` — UTC-момент выполнения, сбрасывается при возврате в другой статус. Прежний `dueAt` доступен для совместимости и не принимается для новой правки.

Карточка также содержит общие поля записи, `householdId`, `files`, `createdAt`, `updatedAt`, `deletedAt`. Датированному личному делу нужен дом участника для пояса: по умолчанию выбирается первый UUID активного членства, при создании можно явно передать `householdId`.

## Маршруты

| Метод и путь | Запрос и результат |
|---|---|
| `GET /api/tasks` | Массив карточек; `filter=mine\|assigned\|undated\|waiting`, `status`, `objectId`, `scope=all\|personal\|household`, `trash=true\|false`, `limit=1…100` (50), `offset=0…50000` (0). «Моё» — исполнитель текущий участник; «назначил» — автор текущий, исполнитель другой; «без даты» — нет даты плана. |
| `GET /api/tasks/:id` | Карточка, включая доступную запись корзины. |
| `POST /api/tasks` | Поля дела; необязательные `placement:{spaceId,audience}`, `assigneeId`, `householdId`, `objectId`, `links:[{type,id,role}]`, `idempotencyKey`. 201. Без объекта и placement создаётся в личном. Объект задаёт размещение по умолчанию и связь. |
| `PATCH /api/tasks/:id` | Частичные поля дела, `assigneeId`, `expectedUpdatedAt`, `idempotencyKey`. 200. Пропуск поля сохраняет значение. |
| `POST /api/tasks/:id/status` | `status`, необязательные поля ожидания, `expectedUpdatedAt`, `idempotencyKey`. 200; повтор текущего статуса не создаёт историю. |
| `GET /api/tasks/:id/history` | История с прежней аудиторией снимка; адресаты ожидания скрыты, смена отмечена `waiting_changed`. |
| `POST /api/tasks/:id/move` | `{spaceId,audience?,assigneeId?,confirmed:true}`. Каскад файлов и сроков; чужой содержательный вклад запрещает перенос общего в личное. |
| `POST /api/tasks/:id/trash` или `DELETE /api/tasks/:id` | Пустое тело; корзина. |
| `POST /api/tasks/:id/restore` | Пустое тело; восстановление с общими правилами авторства и администратора. |

`links.type` — `object`, `contact`, `document`, `utility_charge`. Для последующей правки связей действуют общие `/api/links` и `/api/records/task/:id/links`; обычная правка дела их не заменяет. Новые концы должны быть живыми и видимыми. Файлы используют существующий контракт `/api/tasks/:id/files` и `/api/files/:id` (загрузка и чтение); корзина и восстановление файла — `/api/tasks/:id/files/:fileId/trash|restore`. Поиск `/api/search` возвращает тип `task`, раздел «Дела». Экспорт включает `tasks`, `task_files`, историю и производные сроки.

Смена исполнителя дела в той же транзакции меняет ответственного его файлов, включая отдельно удалённые; размещение и аудитория также следуют делу (PRD 7.3.7). Старые дела с `householdId=null` получают дом при первой правке с `planOn`, `dueOn` или `checkOn`, в том числе через `/status`: общее — своё пространство при действующем членстве автора, личное — единственный действующий дом автора. При отсутствии или неоднозначности членства возвращается `400 HOUSE_REQUIRED`, правка не сохраняется. Размещение и аудитория дела при этом не меняются.

Невидящий назначаемый исполнитель: `409 {code:"ASSIGNEE_NOT_VISIBLE",requiresAudienceExpansion:true}`. Неверная версия: 409; неверный или повторно использованный с другим телом ключ: существующий конфликт идемпотентности. Ответ также содержит `suggestedPlacement:{spaceId,audience}` либо `null`. Повтор создания или PATCH с `expandAudience:true` явно подтверждает предложенное расширение; права переноса и изменения аудитории сохраняются. Ребёнку предлагается только «Вся семья», взрослому при переносе личного — «Взрослые». `HOUSE_REQUIRED` — 400 при датированном личном деле без дома.

В `GET /api/deadlines` добавлены `taskId` и `sourceKind=task_plan|task_due|task_waiting`. Статусы `done`, `cancelled`, `not_done` и корзина выключают напоминания. Для изменения дат и выполненности используются маршруты дела. Без времени предупреждение в 09:00 по поясу дома, с временем — в указанный час. В push не читается название дела; скрытие текста даёт существующий общий текст приложения.

## Общая функция

`parseQuickline(input, {now: Date, timeZone: string, members: [{id,name}], objects: [{id,name}]})` возвращает `{title,planOn,planTime,assigneeId,objectId,fragments}`. Фрагмент: `{kind,start,end,text,value}`, `kind=date|time|assignee|object`, диапазон `[start,end)` в UTF-16 исходной строки. Клиент может вернуть `text` в строку при снятии чипа; запросов к API для разбора нет.

Поддерживаются сегодня, завтра, послезавтра, через неделю/число дней, «в пятницу»/«в пт», календарные даты словами и числами, время, `@имя`, `#объект`. «В 5» — 05:00; прошедшая дата без года — следующий год; день недели — ближайший следующий, включая +7 при совпадении. Неизвестное и неоднозначное сохраняется. Одно распознанное значение каждого вида; последующие остаются в названии. Интерфейс вынесен в следующую задачу.

## Повторы и выполнение

`repeatRule`: `null` (по умолчанию) либо один из объектов:

| Правило | Поля |
|---|---|
| Ежедневно | `{kind:"daily"}` |
| Дни недели | `{kind:"weekly",weekdays:[1,3,5]}`, 1 = понедельник, уникальные 1…7 |
| Ежемесячно | `{kind:"monthly",day:31}` или `day:"last"` |
| Ежегодно | `{kind:"yearly",month:2,day:29}` |
| Каждые N дней | `{kind:"every_days",days:1…3650}` |
| После выполнения | `{kind:"after_done",days:1…3650}` |

Повтор требует `planOn` и дом для часового пояса; начальный статус — `open` или `waiting`. Следующая дата строго позже опорной даты; 31-е и 29 февраля ограничиваются последним днём нужного месяца. `after_done` использует местный день выполнения в текущем поясе дома. `overduePolicy`: `keep` (по умолчанию), `roll_forward`, `not_done`. После местной полуночи обработчик сохраняет факт прохода за день: оставляет просроченным, переносит на сегодняшний день с прежним расстоянием до срока либо закрывает как «не сделано» и создаёт ближайший следующий экземпляр. После простоя пропущенные даты не создают пачку экземпляров. История обработчика имеет `actor_id:null`.

Карточка дополнена `seriesId`, `repeatRule`, `overduePolicy`, `isMain`, `completionEventId`, `completionUndoneAt`, `nextTaskId` (только видимый живой следующий). В серии один живой `open|waiting`; завершение в `done` или `not_done` создаёт следующий атомарно. Повтор запроса и конкурентное выполнение возвращают тот же следующий. Его чек-лист сбрасывается; файлы, связи и адресат ожидания относятся к отдельному экземпляру и не копируются.

В PATCH `repeatScope:"this"` (по умолчанию) сохраняет шаблон, включая опорную дату расписания, исполнителя и политику просрочки; `"following"` меняет этот экземпляр и шаблон следующих. Изменение правила у существующего повтора требует `following`; правка шаблона завершённого экземпляра — `409 NOT_CURRENT_INSTANCE`. `repeatRule:null` с `following` прекращает следующие повторы. Перенос или расширение аудитории обновляет шаблон из текущего содержимого, чтобы следующий экземпляр не раскрывал прежний личный текст.

| Метод и путь | Контракт |
|---|---|
| `POST /api/tasks/:id/undo` | `{eventId: UUID}` — отмена `done` в течение 7 секунд. Возвращает прежний `open|waiting`, убирает созданный следующий в корзину. Повтор того же события идемпотентен. `409` при истёкшем сроке, другом событии или уже изменённом следующем экземпляре. |
| `POST /api/tasks/:id/series/trash` | `{}` — все доступные экземпляры серии в корзину, включая завершённые. |
| `POST /api/tasks/:id/series/restore` | `{}` — восстановление группы, удалённой этим действием; отдельно удалённые экземпляры и следы отмены не возвращаются. Конфликт при двух текущих экземплярах. |
| `POST /api/tasks/:id/main` | `{selected:boolean}` — одно главное активное дело текущего исполнителя, выбрано вручную. Выполнение, корзина и передача снимают выбор. |
| `POST /api/tasks/from-radar` | `{occurrenceId:UUID}` — 201, создаёт дело со связью «Источник радара» и сохранённым наступлением; повтор/гонка возвращает прежнее дело. Для наступления уже существующего дела возвращается оно. Невидимый или завершённый источник — 404. |

## Ленты и передача

`GET /api/tasks/today?householdId=UUID&scope=all|personal|household` возвращает `{today,main,tasks,completed,radar,recalculating}`: главное, сегодня и просроченные, выполненные сегодня отдельным массивом, открытые окна и срочное из радара. Пояс берётся из выбранного дома (без параметра — первого активного дома по UUID). Все данные — одним HTTP-запросом; детали карточек читаются пакетами.

`GET /api/tasks/plan` принимает те же фильтры плюс `days=1…31` (14), `cursor=YYYY-MM-DD` (сегодня). Ответ `{today,from,days:[{date,tasks}],undated,nextCursor}`. Курсор не раньше сегодня и не дальше десяти лет; дни включают начало и исключают `nextCursor`. Без даты — отдельный массив; каждая серия представлена текущим активным экземпляром. `GET /api/tasks` сохраняет прежние фильтры «Все дела».

Исполнитель при создании — `assigneeId`, передача — PATCH с новым `assigneeId`; история содержит действовавшего участника и старого/нового исполнителя. Для объекта и документа: `POST /api/objects/:id/assignee`, `POST /api/documents/:id/assignee`, тело `{assigneeId:UUID}`. Для ручного срока: `POST /api/deadlines/:id/assignee` с тем же телом; его отдельная ответственность записывается в историю источника, источник не меняется. Производный срок отвечает `409 EDIT_SOURCE`. Назначаемый должен видеть живую запись; иначе 409. При последующем переносе источника невидящий ответственный ручного срока сбрасывается к ответственному источника.

Push использует существующие подписки, тихие часы, бюджет и повтор доставки: новому исполнителю при назначении, автору при выполнении другим участником. Уведомление автору ожидает 7 секунд для отмены; перед отправкой вновь проверяются доступ, ответственный и событие. Названия и тексты записей не читаются worker; при скрытии текста — «В HomeCRM есть новое». Экспорт сохраняет правила, шаблон, события и ответственность срока; скрытые ссылки на предшественника и наступление обнуляются. Поиск и история используют прежние RLS дела, корзина и файлы следуют существующим правилам.
