# Покупки и офлайн — клиент R1c.7–8

Клиент использует слитые контракты [покупок](api-shopping.md), [офлайна](api-offline.md)
и [ADR-0041](adr/0041-shopping-offline-receipts.md). PostgreSQL остаётся источником истины.
Локальное сохранение не создаёт серверную карточку и не считается подтверждением API.

## Покупки

Маршруты `/more/shopping` и `/more/shopping/:id` работают с настоящим API. Сохранены
Calm Focus, исходные строки [Claude Shopping](../apps/web/src/prototype/screens/Shopping.tsx),
значки доступа и каркас PR #53. Есть быстрый ввод, количество, заметка, магазин,
категория, связи с делом/объектом, выбранный дом, личное и общее пространство.
Ребёнок добавляет общую покупку по каноническим правилам доступа и серверной проверке.

«Куплено», отмена, корзина и восстановление выполняются сервером; купленное свёрнуто отдельно.
Сроки очистки объяснены в интерфейсе. Правка сохраняет исходную базовую версию и локальный ввод
при 409; отдельное осознанное применение использует показанную свежую серверную карточку.
Поиск отправляет `includeShopping=true`, проверяет строгий тип `shopping_item` и открывает
настоящую карточку. Фильтр выбранного дома и личный список читаются отдельно: серверный
`spaceId` не должен случайно отфильтровать личные покупки.

## Локальные данные и чтение

Service worker остаётся `injectManifest`. Cache Storage содержит только оболочку сборки
и возврат общего index.html для навигации; API, файлы, auth и пользовательские ответы
в Cache Storage не попадают. Новая оболочка активируется штатно после закрытия старых вкладок,
без `skipWaiting`, прерывающего открытый ввод.

Dexie **4.4.6** (версия закреплена lockfile) реализует принятое в ADR-0008 решение:
атомарные транзакции нескольких таблиц и обновление IndexedDB в окне и service worker.
Дополнительных библиотек для очереди нет. API транзакций и `version().stores()` проверен
по Context7 и [официальной документации Dexie](https://dexie.org/docs/Dexie/Dexie.transaction%28%29),
[обновление схемы](https://dexie.org/docs/Dexie/Dexie.version%28%29).
Внешние запросы документации не содержали сведений проекта.

| Таблица | Что хранит | Ограничение |
|---|---|---|
| identity | UUID аккаунта, generation и минимальный me для офлайн-метки | Один активный аккаунт; без username/email/passwordReset и секретов |
| snapshots | Проверенные карточки/списки и версии из того же API snapshot | До 80 снимков, 7 суток, 8 MiB JSON |
| drafts | Черновики форм дела/заметки и ввод сохранённых намерений | До 100 черновиков форм; у каждого намерения свой черновик |
| outbox | Стабильный ключ, владелец, маршрут, база, зависимости, состояние и квитанция | До 300 неподтверждённых; до 200 незадействованных подтверждённых |
| blobs | Исходные фото и имена multipart | До 60 MiB суммарно, до 20 MiB одно фото; штатный выбор до 3 фото на показание |
| leases | Восстанавливаемая блокировка отправителя окна/SW | 45 секунд; обновляется перед отправкой, тайм-аут запроса 20 секунд |

Allowlist чтения закрыта и совпадает с `api-offline.md`; параметры запроса сортируются
и включаются в ключ снимка вместе с владельцем. Чтение сохраняет только уже доступные поля:

| GET /api/… | Назначение |
|---|---|
| tasks, tasks/today, tasks/plan, tasks/:id | Сегодня, дела, последние карточки |
| deadlines | Радар с исходными фильтрами |
| notes, notes/:id | Заметки и чек-листы |
| objects, objects/:id, objects/:id/meters, meters/:id | Объекты и счётчики |
| meters/:id/readings, readings/:id | Показания |
| shopping, shopping/:id | Последний список/карточка покупок, только чтение без сети |
| documents, documents/:id, documents/:id/versions | Штатно замаскированные поля документа |
| contacts, contacts/:id, contacts/:id/interactions | Доступные контакты и взаимодействия |
| accounts, accounts/:id, objects/:id/accounts | Доступные лицевые счета |

PDF, preview/байты файлов, unmask, поиск, экспорт, настройки, устройства, приглашения,
сбросы и auth/session/security не входят в allowlist. Файлы документов без сети — R2.

Перед записью и выдачей снимка сверяются accountId ответа, владелец запроса и generation.
Проверка нужна и до broadcast: cookie уже могла перейти другому аккаунту.
Точная версия заменяет updatedAt карточки только внутри того же согласованного snapshot.
Отдельное позднее чтение версии не прикрепляется к старому тексту.
Снимок без точной версии пригоден для чтения; запись требует согласованной базы.

Сеть недоступна — доступны сохранённые снимки и офлайн-метка me. Плашка показывает время
последнего сохранения и объясняет, что сервер мог измениться; отсутствующий снимок даёт
явное состояние. Ответы 401/403/404 не заменяются успешным кэшем.
Истечение сессии блокирует cached identity; для replay нужен правильный новый вход.

Смена аккаунта атомарно удаляет прежние снимки, намерения, Blob и черновики; generation
и BroadcastChannel защищают поздние результаты и другие вкладки/SW. Смена ролей очищает
старые снимки, но оставляет локальный ввод и очередь для явного решения. Маршрут/UUID и
исходное placement/пространство операции не меняются при выборе другого дома.

## Запись и решения

Закрытая allowlist записи: создание/правка дела и чек-листа, выполнение; создание/правка
заметки и её чек-листа; загрузка фото объекта перед single/batch показаниями.
Доступ, назначение существующей серии, деньги, переносы, безопасность и покупки
без сети не отправляются: интерфейс требует подключение.

В одной rw-транзакции сохраняются намерения, их черновики и все исходные Blob. Quota,
ошибка IndexedDB и лимиты не показывают успех: ввод остаётся в форме.
Черновик формы хранит ввод вместе с исходной точной базовой версией и автоматически
сохраняется после изменения (300 мс); повторный ввод
после первого autosave также переживает reload. Обновление локальной схемы 1→2
добавляет индекс nextAttempt, не удаляя таблицы или ожидающие записи/формы/Blob.

Кэшированный me — метка локальных данных, не разрешение отправки. Перед replay и каждой
отправкой нужен свежий серверный me того же аккаунта; JSON несёт ownerAccountId,
multipart — X-Owner-Account-Id. Квитанция проверяется по владельцу, ключу и виду операции.
Cookie, CSRF и пароли в IndexedDB не сохраняются.

Локальное создание имеет устойчивый временный ID; потомки получают серверный UUID
и точную базу из квитанции предшественника. clientId новых пунктов заметки сопоставляется
с серверными UUID, в том числе через несколько зависимых правок.
Перед первой отправкой фиксируются окончательные path/body; после неизвестного COMMIT
исходный ключ и содержимое сохраняются. Повторы независимо от вкладки используют
общий durable lease, восстановление после его истечения и bounded backoff до 60 секунд.

Состояния панели: «В очереди», «Отправляется», «Исход неизвестен», «Подтверждено»,
«Нужно решение», «Ошибка». 409 сохраняет локальный ввод и приостанавливает только
зависимые изменения; независимые цепочки продолжаются. Сравнение дела/заметки показывает
свежую серверную карточку, осознанное применение создаёт новый ключ.
403/404 сохраняют намерение и предлагают исходный повтор или явную отмену;
401 останавливает отправителя до входа, 429 учитывает Retry-After.
Намерение с неизвестным исходом нельзя отменить как якобы неотправленное.
Отмена родителя запрещена при существующих зависимых намерениях.

Фото отправляются последовательно. База следующего фото того же объекта — точный
receipt.parent.updatedAt предыдущей загрузки, а не текущий updatedAt чужой правки.
Изначальный Blob, имя и результат загрузки сохраняются до подтверждения зависимого
показания; неизвестный single или batch не превращается в новые ключи.
Утраченное фото при replay — явный серверный отказ, локальные значения/Blob остаются.
После восстановления исходный запрос может подтвердить ту же квитанцию.
Панель показаний показывает локальные дату/значения/число фото, позволяет прочитать
свежий серверный ряд и открыть объект для отдельного осознанного ввода.

Офлайн-отмена ещё не отправленного done отменяет намерение. Подтверждённое выполнение
использует прежнее окно undo **7 секунд** и настоящий eventId. Метка cached snapshot
или поздний replay это окно не продлевает; свежий HTTP Date сохраняется для обычного undo.
Перед выходом при pending требуется явный выбор удаления, затем данные аккаунта удаляются
во всех вкладках. Предупреждение предшествует и массовому отзыву сессий.

## Исправления единственного ревью B1–B4

Кандидат 87751f5 получил четыре воспроизведённых блокера; исправлены только они по
[точному брифу](tasks/R1c.7-8b-review-fixes.md), без второго общего аудита.

- B1: локальный envelope формы связывает изменённый ввод с исходными UUID/точной версией.
  Восстановленный V1 не получает V2 из позднего GET. Эта сохранённая база остаётся доступной
  проверке очереди, когда текущий путь снимка уже обновился. Legacy draft без базы блокирует
  сохранение до явного применения к показанной серверной версии; создание сохраняет прежнюю
  семантику. Версия сохраняется вместе с вводом в owner-scoped транзакции.
- B2: freeze в транзакции перечитывает row и допустимое состояние. Удалённое pending
  не восстанавливается из ранее прочитанного объекта и не отправляется. Попытанные payload/key
  по-прежнему остаются неизменными.
- B3: конфликт потомка local create разрешается по frozenPath/серверному UUID. Новый ключ
  использует точную показанную базу, а независимое намерение подтверждается отдельно.
- B4: sender окна/SW применяет проверенный свежий Me на обеих проверках, включая изменение
  роли/personalSpace между ними. Права отзывают snapshots и generation во всех контекстах;
  pending, черновики и Blob того же аккаунта сохранены для решения.
