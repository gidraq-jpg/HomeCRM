# Объекты, связи и лента: API R0.5a

Требования: OBJ-1…3, OBJ-5, OBJ-6, SPACE-4, SPACE-6 и PRD 7.3. Решения — [ADR-0023](adr/0023-objects-links-timeline.md). Сервер возвращает JSON. Нужна действующая сессия; администратору — включённый второй фактор. Изменяющие запросы требуют своего `Origin` или `Referer`. Все чтения и изменения выполняются ролью `homecrm_app` в транзакции участника под RLS.

## Объекты

| Метод и путь | Тело или параметры | Ответ |
|---|---|---|
| `GET /api/objects` | `scope=all\|personal\|household`, `spaceId`, `objectType`, `trash=true\|false`, `limit=1…100` (50), `offset=0…50000` | Массив кратких карточек доступных объектов |
| `GET /api/objects/:id` | UUID объекта | Карточка с массивом `fields` |
| `POST /api/objects` | `title`, необязательные `objectType`, `assigneeId`, `placement`, `fields` | 201, карточка |
| `PATCH /api/objects/:id` | Хотя бы одно из `title`, `objectType`, `assigneeId`, `fields`; необязательный `expectedUpdatedAt` | Обновлённая карточка |
| `POST /api/objects/:id/access-preview` | `{action:"personal"}` или `{action:"audience", audience:"adults"}` | `updatedAt`, `losesAccess: [{accountId, displayName}]` |
| `POST /api/objects/:id/share` | `{spaceId, audience?}` | Карточка после переноса своего личного в дом |
| `POST /api/objects/:id/personal` | `{confirmed:true}` | Карточка после переноса общего в своё личное |
| `POST /api/objects/:id/copy` | `{}` | 201, личная копия с новыми id и автором |
| `POST /api/objects/:id/audience` | `{audience, confirmed?}` | Карточка; сужение требует `confirmed:true` |
| `POST /api/objects/:id/trash` | `{}` | Карточка в корзине |
| `POST /api/objects/:id/restore` | `{}` | Восстановленная карточка |
| `GET /api/objects/export` | Без параметров | JSON экспорта этого модуля, `version:1` |

По умолчанию новый объект личный. `placement` — `{spaceId, audience?}`; у личного аудитории нет, у общего по умолчанию `household`. Аудитории: `household` — «Вся семья», `adults` — «Взрослые». Типы: `property` — недвижимость, `car` — машина, `appliance` — техника, `other` — другое (по умолчанию). `title` — непустое название до 200 символов. Произвольные поля типа, файлы и неподдерживаемые ключи отклоняются.

Краткая карточка содержит `id`, `title`, `objectType`, `spaceId`, `spaceKind`, `audience`, `authorId`, `assigneeId`, `createdAt`, `updatedAt`, `deletedAt`. Даты и моменты создания, изменения и корзины — ISO UTC. Служебный признак чужого вклада и вычисляемые колонки API не выдаёт.

`fields` — упорядоченный массив до 50 элементов `{id?, name, value}`. Название до 100 символов, значение до 4000. При создании `id` запрещён; при правке известный id сохраняет поле, отсутствующий id создаёт новое. Пропущенные старые поля уходят в корзину; пустой массив очищает живые поля. Повторные id и id чужого поля запрещены. Ответ дополнительно содержит `position`, `deletedAt`. Удалённые поля можно вернуть, прислав их id, если участник вправе их восстановить.

Ребёнок пишет только личные объекты. Любой взрослый дома пишет доступные общие; личное другого не видит даже администратор. Ответственный обязан видеть объект; нельзя сузить доступ при ответственном ребёнке. «Сделать личной» доступно автору без чужого содержательного вклада в объект и его дочерние строки. Перенос меняет место полей и событий в той же транзакции. Копия включает живые поля и видимые живые ручные события; связи, корзина и прежняя история не копируются.

В ответе preview перечислены только участники прежнего дома, теряющие доступ. Preview и подтверждение не обходят повторную проверку права переноса. `expectedUpdatedAt` в PATCH предотвращает устаревшую правку. Конкурентное изменение между чтением и блокировкой переноса возвращает конфликт.

## Связи любых записей

Ссылка имеет вид `{type, id}`. Виды: `object`, `note`, `note_item`, `task`, `shopping_item`, `object_field`, `object_event`. Все соответствующие таблицы подключены через `attach_record_table`.

| Метод и путь | Тело или параметры | Ответ |
|---|---|---|
| `POST /api/links` | `{left:{type,id}, right:{type,id}, role?}` | 201, связь |
| `PATCH /api/links/:id` | `{role}` | Обновлённая связь |
| `GET /api/records/:type/:id/links` | `trash`, `limit` (50, до 100), `offset` | Только связи с видимыми обоими концами |
| `POST /api/links/:id/trash` | `{}` | Связь в отдельной корзине |
| `POST /api/links/:id/restore` | `{}` | Восстановленная связь |

Подпись роли — до 200 символов, можно пустую. Самоссылка запрещена. Для изменения связи необходимо видеть обе записи и писать хотя бы в одну живую. В обычном списке скрыты связи с концом в корзине. Сужение доступа конца немедленно скрывает связь от потерявших доступ, без раскрытия другого id или количества скрытых связей. Связь возвращает `id`, `left`, `right`, `role`, `authorId`, `createdAt`, `updatedAt`, `deletedAt`. Концы неизменяемы: для другой пары создаётся новая связь.

## Лента и ручные события

| Метод и путь | Тело или параметры | Ответ |
|---|---|---|
| `GET /api/objects/:id/timeline` | `limit` (50, до 100), `cursor?` | `{items, nextCursor}` |
| `POST /api/objects/:id/events` | `occurredOn`, `text`, необязательные `amountKopecks`, `rating`, `contact` | 201, ручное событие |
| `PATCH /api/objects/:id/events/:eventId` | Непустой набор тех же полей; `expectedUpdatedAt?` | Обновлённое событие |
| `POST /api/objects/:id/events/:eventId/trash` | `{}` | Событие в корзине |
| `POST /api/objects/:id/events/:eventId/restore` | `{}` | Восстановленное событие |

Дата `occurredOn` — существующая календарная дата `YYYY-MM-DD`. `text` — непустой текст до 10 000 символов. Сумма — целые копейки, включая отрицательные, абсолютное значение до 9 007 199 254 740 991. Отсутствующее значение и `null` означают отсутствие суммы; PATCH с `null` очищает её. Оценка — целая 1–5 или `null`. `contact` — ссылка на видимую запись или `null`; ручное событие как контакт запрещено. Ссылки на файлы добавятся в R0.5b.

Лента сортируется по убыванию времени, источника и id. Источники: `object` — создание и изменение ключевых полей объекта из истории, `field` — создание и содержательные изменения своего поля, `manual` — ручное событие. Автоматическое событие содержит `operation`, `actorId`, `changes`; поля — ещё `fieldId`. Ручное событие содержит дату, текст, сумму, оценку, контакт, автора и даты. Все элементы имеют `id`, `at`, `source`.

Страница собирается одним `UNION ALL` после проверки объекта. Курсор непрозрачен клиенту: следующий запрос передаёт `nextCursor` как `cursor`. Он сохраняет микросекунды времени базы, источник и id; равные даты не вызывают пропусков и повторов. `nextCursor:null` завершает обход. У даты ручного события ключ сортировки — полночь UTC, календарная дата не переводится в другой часовой пояс. Будущие модули добавят источники с такой же видимостью.

История и ручные события требуют доступа к объекту сейчас и к месту события на момент создания. Личные события, созданные до переноса объекта в общее, видит прежний владелец. Ребёнок не получает прежние события «Взрослые» после открытия объекта всей семье. Контакт не влияет на видимость события: невидимая или отсутствующая ссылка возвращается как `contact:null`, без id, названия и признака прежнего контакта. При окончательной очистке контакта ссылка обнуляется; событие остаётся в ленте, корзине и экспорте. Копия сохраняет событие, но не скрытый контакт. Отдельная корзина события хранится 30 дней. Корзина объекта каскадная; восстановление родителя возвращает все поля и события, удалённые его каскадом, включая чужие. События, удалённые отдельно раньше, остаются в корзине; их прямое восстановление по-прежнему требует автора или администратора. То же правило каскада действует для пунктов заметок.

## Экспорт, ошибки и расширение

Экспорт модуля содержит собственное личное, включая корзину, и общее домов, где участник администратор. Объекты включают поля и `events` — видимые ручные события с автоматической историей; `links` содержит видимые связи экспортируемого пространства. Чужое личное в общем экспорте отсутствует. Единый ZIP и подключение к общему `/api/export` — R0.10; модуль авторизации в R0.5a не изменён.

Одинаковый ответ `404 {code:"NOT_FOUND"}` получают скрытые и отсутствующие объекты, концы связей, события и контакты. Нет счётчиков скрытых записей и подробностей SQL. `400 INVALID_INPUT` — нарушение схемы; `403 ACCESS_DENIED` — нет права на видимое действие; `409 CONFIRMATION_REQUIRED`, `409 ASSIGNEE_CANNOT_SEE`, `409 STALE_VERSION`, `409 CONFLICT` — подтверждение, ответственный, устаревшая версия или конфликт целостности. Неожиданная ошибка — `500 INTERNAL_ERROR`; в журнале только классификация и SQLSTATE. Сессию и происхождение проверяет общая служба входа.

Поиск R0.6 использует `search_text` объекта, поля и события. Контекст создания заметки теперь принимает `{object:{type:"object",id}}` вместе с прежним `task`; место и аудитория выбираются по видимому объекту, постоянная связь создаётся отдельным запросом `/api/links`.
