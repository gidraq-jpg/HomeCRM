# D12 · правка чипов Studio 2

Снимки получены в Linux, образ Playwright `v1.63.0-noble`, только вымышленная семья.
`w360` — 360 × 740 px, `w412` — 412 × 915 px. В имени `100` или `200` — размер текста в процентах.

Сценарий `apps/web/e2e/app/studio2-chips.e2e.ts` проверяет каждый выбор, обновление чипов и блока «Получится», сброс правок при изменении строки и снятие исправленного времени. После повторной правки сохранённое дело проверяется через API: дата, время, исполнитель и связь со вторым объектом; связи с первым объектом нет. Также проверяются показания `1 245,3 м³`, отсутствие повторения названия объекта в главном деле и переход в полную форму из «+».
Каждое снятое состояние проверено с axe, без горизонтальной прокрутки, с целями нажатия от 44 × 44 px. При 200% лист прокручивается; снимок показывает видимую часть экрана.

Запуск выбранных сценариев из корня worktree:

```powershell
docker compose -f apps/web/e2e/studio2-chips/compose.yaml build playwright
docker compose -f apps/web/e2e/studio2-chips/compose.yaml run --rm playwright pnpm --filter @homecrm/web test:e2e:auth e2e/app/studio2-chips.e2e.ts e2e/app/studio2.e2e.ts e2e/app/objects.e2e.ts --grep 'D12:|ребёнку не раскрываются|четыре действия|объект, четыре чипа' --workers=2
```

Compose-проект имеет отдельное имя с суффиксом `-e2e`, чтобы штатная подготовка `pnpm check` его не пересоздавала. Для полного локального `pnpm check` использовались `VITEST_MAX_WORKERS=2` и `HOMECRM_TEST_PG_ADMIN_URL` этой одноразовой PostgreSQL (`max_locks_per_transaction=1024`): первый запуск со стандартным лимитом PostgreSQL упёрся в `out of shared memory`. Конфигурация рабочего окружения не менялась.

Контрольные поломки проверены вручную в одноразовых контейнерах, исходники worktree не менялись:

| Подстановка | Ожидаемое падение штатного теста |
|---|---|
| В `ObjectOverview.tsx` условие `abilities.trash` заменено на `true` | `objects.e2e.ts`: внутри «Ещё» ребёнку видна «В корзину»; ожидалось 0, получено 1 |
| В `ObjectAccess.tsx` условие `abilities.share` заменено на `true` | `objects.e2e.ts`: внутри «Доступ к объекту» ребёнку видно «Поделиться…»; ожидалось 0, получено 1 |
| В ответ радара ребёнка подставлены настоящие тестовые строки взрослого: начисление 7 429,13 ₽ и окно показаний | `studio2.e2e.ts`: `.today-hints`; ожидалось 0, получено 1 |

При подстановке радара сохранялась офлайн-оболочка ответа ребёнка, менялось только её `data`; перед отрицательной проверкой подтверждалось появление «к оплате». Это исключает ложное падение на формате ответа или смене владельца. Для перехвата запросов в этом контрольном запуске service worker был отключён. Все подстановки остались внутри удалённых после проверки контейнеров.

Физический Android и экранная клавиатура этим прогоном не проверялись.
