# R1c.4d. Сравнение экранов дел

Все снимки сделаны в Linux-контейнере Playwright 1.63.0 (Chromium) на вымышленной семье. Рабочее окружение не использовалось.

- `reference/prototype-today-412.png` и `prototype-today-1440.png`: исходный экран HomeCRM из PR #2 (`94c6b9d`) **в текущем каркасе** `ad87a37`. Сам `prototype/screens/Tasks.tsx`, токены и базовые стили с PR #2 не менялись. Настольное меню и перенос вкладок — принятые позднейшие изменения.
- `before/today-empty-412.png` и `today-empty-1440.png`: пустое приложение на `ad87a37`, участник Анна.
- `before/today-main-412.png` и `today-main-1440.png`: приложение до правки с личным главным делом Бориса «Подготовить документы для ремонта».
- `after/today-main-412.png` и `today-main-1440.png`: парное сравнение после правки с теми же данными, размерами окна и плотностью пикселей.
- Остальные `after`: пустые и заполненные «Сегодня», «План», «Все дела», длинное название, четыре распознанных чипа и ошибка быстрой строки на 360/412 px; три настольные ленты на 1440/1718 px при 100% и 200%.

Регрессионный сценарий на исходном коде измерил оба отступа формы по 0 px и `scrollWidth=1277` при окне 412 px. После правки отступы не меньше 8 px, горизонтальной прокрутки нет, цели нажатия от 44 px, axe без серьёзных и критичных замечаний.

Масштаб 200% в Playwright воспроизведён уменьшением CSS-окна вдвое при удвоенной плотности пикселей: 1440 → 720 CSS px, 1718 → 859 CSS px. Это проверка раскладки и читаемости; интерфейс управления масштабом настоящего браузера и Android остаются проверкой владельца.

Возвращены исходные дата, заголовок раздела с акцентом и `.focus__*`. Реальные метаданные, доступ, кнопка выполнения и отмена сохранены. В пустом фокусе ссылка ведёт к созданию либо к списку дел; выбор главного остаётся готовым действием карточки. Быстрая строка — новая функция рабочего приложения: она стоит после фокуса и ограничена существующим токеном ширины колонки. Диапазон «Плана» берётся из загруженных страниц API; его пагинация и фильтры «Всех дел» не менялись.
