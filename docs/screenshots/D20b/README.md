# D20b — строки «Сегодня» и радара

Снимки сделаны Chromium в Linux, на вымышленной семье, в отдельном compose-проекте
`homecrm-test-d20b`. Рабочее окружение не использовалось.

| Экран | До, 360 px (`4c75f06`) | После, 360 px | После, 412 px |
|---|---|---|---|
| Сегодня | [До](before-today-w360.png) | [После](after-today-w360.png) | [После](after-today-w412.png) |
| Радар | [До](before-radar-w360.png) | [После](after-radar-w360.png) | [После](after-radar-w412.png) |

Остальные снимки показывают меню с клавиатуры, выполненное дело, известного другого
ответственного, отсутствие действий у ребёнка в чужом деле, выбор даты в поясе дома,
перенос повторного главного дела и отмену без сети.

Приёмка: `apps/web/e2e/app/today-rows.e2e.ts`, проекты `w360` и `w412`.
На каждом проверяемом экране выполняются axe, проверка горизонтальной прокрутки
и целей нажатия. Для исходных снимков тот же сценарий запускается с
`D20B_PHASE=before`, до проверок нового поведения.

После слияния PR #71 в ветку включён `origin/main` (`f0dff86`). Повторный Linux-прогон
затронутых экранов: 88/88, в том числе 14/14 проверок D20b; ширины 360 и 412 px,
axe, цели нажатия и отсутствие горизонтальной прокрутки. `TodayHero.tsx` и расчёт
суммы «к оплате» сохранены из #71.

Старые сценарии изменены только под удалённую нижнюю кнопку, перенос действий радара
в меню, переход к источнику и расположение меню рядом с компактной строкой.
Полный CI выявил ещё один прежний локатор: «Продлить» документа теперь тоже в меню.
Проверка адреса продления сохранена; исправленный сценарий прошёл в Linux на обеих
ширинах (2/2). Рабочий код для этого исправления не менялся.
