# Проверка SRCH-5

7 октября 2026, локальная Windows-машина владельца, Node 24, одноразовая PostgreSQL 18 в Docker. В тестах используется только вымышленная семья. Замер сделан через Fastify `inject` с настоящими входом, сессией, транзакцией и RLS; сеть телефона и рабочая база в него не входят.

Источник: `apps/server/src/search/routes.test.ts`, сценарий SRCH-5. Созданы 10 000 общих заметок; 20 содержат «спектрометр». Для каждой строки измерения — 5 прогревочных и 30 учитываемых полных запросов API, p95 — 29-е значение по возрастанию.

| Проверка | Результат |
|---|---|
| API, поиск «спектрометр» на 10 000 записях | p95 **20,0 мс** при лимите 300 мс |
| «невидимыймаркер», пока таких строк нет | p95 25,3 мс |
| Тот же запрос после добавления 10 000 личных заметок другого участника | p95 29,6 мс; 0 результатов |
| Разница времени скрытых совпадений | +4,3 мс при проверяемом пороге 30 мс |
| Часть номера из чужого личного | 0 результатов |

`EXPLAIN (ANALYZE, BUFFERS)` выполняется от `homecrm_app` с тем же запросом, что использует API (`searchRowsQuery`), без отключения RLS, `enable_seqscan` или других способов принудить план. Короткая форма плана:

```text
Limit → Result → Sort → Bitmap Heap Scan on search_index
  BitmapOr
    Bitmap Index Scan on search_index_document_idx
      Index Cond: access_key = ANY(<видимые места>) AND document @@ plainto_tsquery(...)
    Bitmap Index Scan on search_index_content_idx
      Index Cond: access_key = ANY(<видимые места>) AND content ILIKE ...
    Bitmap Index Scan on search_index_digits_idx
      Index Cond: access_key = ANY(<видимые места>) AND digits LIKE ...
Execution Time: 0.871 ms
```

После добавления скрытых совпадений используются те же три составных индекса; каждый возвращает 0 строк, `Execution Time: 0.794 ms`. Совпадения чужого пространства не доходят до чтения строк таблицы. Сортировка начинается с названия, чтобы LIMIT не выбирал упорядоченный обход PK по виду записи; GIN создаются с `fastupdate=off`, чтобы общий pending list не влиял на задержку. Проверка живого видимого родителя события сохранена через `SECURITY INVOKER`; JIT отключён только на время транзакции поиска. Обоснование — ADR-0027.

Матрица поискового индекса: **2280 сравнений с `access.ts`, 0 расхождений**, дополнительно — историческая аудитория события, скрытый/отсутствующий родитель, запрет прямого изменения индекса, сброс контекста пула и откат записи вместе с индексом. Проверка обновления непустой базы сохраняет исходные записи и историю без изменений.
