# D19a — исправления пилота

Снимки сняты в Linux Chromium (Playwright 1.63), только на вымышленной семье,
на ширинах 360 и 412 px. Изменения охватывают пункты 1–14 брифа D19.

## Проверяемое поведение

| Пункты | Проверка |
|---|---|
| 1 | Кружок повторяющегося дела в окне отмены вызывает ту же отмену по событию, что тост. Следующий экземпляр уходит в корзину. После перезагрузки окно заново вычисляется по HTTP Date сервера. |
| 2 | Старое дело, выполненное без сети, остаётся зачёркнутым в своём дне. Обновление старого снимка не затирает ожидающее подтверждения выполнение; конфликт и ошибка не маскируются локальным статусом. |
| 3 | В кэш ленты попадают только поля схемы. Служебные `undoUntil`, `repeatScope`, `expectedUpdatedAt` отбрасываются. Выполненное название использует текущий `--muted`, axe проверяет контраст. |
| 4 | Ошибка GET после успешного PATCH не превращает сохранённую правку в ошибку мутации. Следующее обновление повторяет чтение. |
| 5 | «План» работает без IntersectionObserver, кнопкой и с Tab подгружает дни; календарь не принимает день раньше сегодняшнего в поясе дома. |
| 6 | Группировка покупок работает без `Map.groupBy`, сохраняет порядок, не требует зависимости или полифилла. |
| 7–8 | Серверные тесты покрывают названия действий для всех типов сроков и первый видимый объект после скрытой связи; доступ и RLS не меняются. |
| 9–11 | «Назад» завершает правку объекта; dock радара зависит от state перехода; ошибка копии остаётся в листе; фокус возвращается к своему триггеру, в том числе после вложенного листа. Метка без действий — обычная подпись. Копирование общей заметки ребёнком остаётся доступным. |
| 12–13 | Заголовки месяца идут без пропуска уровня, пустой текст заканчивается точкой; дата рождения и состояние напоминания человека находятся вместе в шапке, повторной строки в теле нет. Ручка убрана, личное пространство имеет замок; контраст кольца тоста измеряется в браузере и не ниже 3:1. |
| 14 | Единая таблица `shell/section-add.ts`: меню только на «Сегодня», в разделах — форма или быстрое дело; покупки фокусируют ввод; из новой формы объекта доступна ссылка на шаблон. Проверены списки, карточки и служебные экраны. |

**Просрочка «Плана».** PRD TASK-5 не задаёт отдельного определения. Счётчик и
метка строки используют одно правило: статус `open`/`waiting` и `dueOn` раньше
сегодняшнего дня дома. Прошедший `planOn` без крайнего срока сам по себе не
увеличивает этот счётчик.

**Пояс радара.** `/api/me.timeZone` берётся из конфигурации сервера, а не из
таблицы домов. Подписи рассчитываются по `timeZone` каждого наступления.
Горизонт запроса строится от UTC с запасом одного дня для границы дат домов.
Регрессия проверяет границу года в Pacific/Kiritimati при другой дате UTC.

## Прогоны

- Клиент: `pnpm exec vitest run --project @homecrm/web` — 54 файла, 428 тестов.
- Сервер: `radar-title.test.ts`, `plan-studio2.test.ts`, `repeats.test.ts` — 55 тестов.
- Новый e2e: `pnpm --filter @homecrm/web test:e2e:auth pilot-fixes.e2e.ts --workers=1`.
  Он проверяет 360/412 px, отсутствие горизонтальной прокрутки, цели от 44 px и axe.
- Для намеренного обновления этих снимков в Linux задайте `D19_CAPTURE=1`.
  Без этой переменной снимки идут в `apps/web/test-results/screens/D19`, в том
  числе в CI и полном прогоне; эталоны в документации не перезаписываются.
- Использовалось отдельное окружение `homecrm-test-pilot1-ui`; рабочее окружение
  и данные семьи не менялись. Проверка на физических телефонах — после выпуска.

По исключению из брифа минимально обновлены существующие e2e, сломанные пунктом
14: `objects`, `documents`, `notes`, `templates`, `plan-studio2`, `tasks-layout`,
`studio2-lists`, `desktop` и общий помощник открытия меню/быстрого дела.
Сценарии нестабильности D19b и конфигурация проверок не менялись.
