# API файлов (R0.5b)

Все маршруты требуют сессию; изменяющие — допустимый Origin. Доступ проверяется к файлу и карточке-родителю, под ролью `homecrm_app` и RLS. Отсутствующий и чужой id дают 404. Все ответы этих маршрутов имеют `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.

| Маршрут | Результат |
|---|---|
| `GET /api/notes/:id/files`, `GET /api/objects/:id/files` | Список метаданных живых файлов; в карточке корзины — с удалёнными |
| `POST /api/notes/:id/files`, `POST /api/objects/:id/files` | Один multipart file, 201 с метаданными |
| `GET /api/files/:id` | Основной файл с `Content-Disposition: attachment` и безопасным UTF-8 именем |
| `GET /api/files/:id/preview` | WebP-превью; у PDF — 404 |
| `POST /api/notes/:id/files/:fileId/trash`, аналогично для objects | В корзину, 200 |
| `POST /api/notes/:id/files/:fileId/restore`, аналогично для objects | Восстановить отдельно удалённый файл, 200 |

Загрузка принимает JPEG, PNG, WebP, HEIC/HEIF и PDF по содержимому. Один файл, без дополнительных multipart-полей; до 25 МиБ включительно. Неподдерживаемый или повреждённый формат — 415, превышение — 413, недопустимая форма — 400. Фотографии перекодируются без EXIF/GPS/XMP с сохранением встроенного ICC-профиля в основном изображении и превью; JPEG с небольшими дефектами, вызывающими только предупреждение декодера, принимается. HEIC сохраняется JPEG, превью — WebP до 480 px. MIME из multipart и расширение имени не определяют формат.

Файл принимается, декодируется, получает превью и шифруется до транзакции записи. Короткая предварительная проверка отсекает недоступного родителя; перед INSERT сервер блокирует родителя `FOR UPDATE` и заново проверяет доступ и корзину. Изменение родителя во время передачи не оставляет файловой строки или блоков.

Метаданные: `id`, `name`, `mimeType`, `sizeBytes`, `hasPreview`, `authorId`, `createdAt`, `deletedAt`. Ключи хранения, конверты и главный ключ клиенту не передаются. Карточки заметок и объектов дополнены массивом `files` той же формы.

Перенос/смена аудитории/корзина/восстановление родителя каскадно меняют файлы. Отдельно удалённый файл остаётся в корзине при восстановлении родителя. Копия получает новые файлы и блоки; файлы в корзине не копируются. «Кто потеряет доступ» использует аудиторию родителя: у файлов она совпадает. Чужое добавление или отдельное удаление файла запрещает делать родителя личным (необратимый вклад).

Если тело транзакции завершилось, но ответ COMMIT потерян или COMMIT отклонён, блоки сохраняются до фоновой сверки с `file_blobs`: компенсация не может стереть содержимое живой строки. Ошибка внутри тела компенсируется сразу. Подробности — [ADR-0025](adr/0025-api-review-consistency.md).

Обработчик раз в час и при запуске физически удаляет файлы, пробывшие в корзине 30 дней, затем убирает блоки без ссылок старше часа. Окончательная очистка родителя также удаляет дочерние строки и их ссылки на блоки. Само содержимое доступных файлов в корзине можно скачать до окончательной очистки.

`PATCH /api/me/profile` принимает `photoFileId` только своего живого изображения при живом родителе. Скрытое или удалённое фото при чтении профиля/состава возвращается `null`, исходная ссылка сохраняется в базе. Общая семейная проекция не расширяет доступ к личному фото.

Поиск, экспорт R0.10, главный ключ и резервирование — [ADR-0024](adr/0024-files-storage-lifecycle.md), [runbook](runbook.md).
