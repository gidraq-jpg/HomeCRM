# Бриф R0.4a. Заметки: база и API

- **Задача:** первая половина R0.4 из [плана](../03-dev-plan.md) — заметки как первый сквозной модуль на сервере: таблица, правила доступа, API, перенос между пространствами, корзина. Экраны — отдельной задачей R0.4b, после проверки прототипа 0.5 (навигация и «Кто видит» могут измениться).
- **Требования:** NOTE-1…3, SPACE-7; PRD, раздел 7.3 (правила 3, 5–8, 11, 13). Эталон правил — `packages/shared/src/access.ts`.
- **Ветка:** `feat/note-1-notes-api`, в своём worktree от свежего `main`. Схему и `access.ts` в это время меняет только этот исполнитель.

## Сделать

1. **Таблица заметок — рабочая, на образце R0.1.** Таблица-пример `notes` из R0.1 становится настоящей: заголовок, текст с простым форматированием (хранить как разметку, формат обосновать в ADR), чек-лист, закрепление. Подключение — одним вызовом помощника `attach_record_table`: политики, триггеры, история, корзина, строки матрицы. Файлы, связи и теги (NOTE-1) — только поля и места под них, если без них схема потом сломается; сами модули — R0.5 и позже, отметить в отчёте.
2. **`canMove` (бэклог «К R0.4»).** Перенос записи между пространствами сейчас разрешён всем, кто может писать в обоих местах, — шире PRD. Добавить в `access.ts`, затем в SQL:
   - «Поделиться» (личное → общее) — только владелец; вместе с записью переходят дочерние (правило 5);
   - «Сделать личной» — только автор и только без вклада других участников в запись и дочерние записи; вклад определяется по истории (правило 6);
   - «Скопировать в личное» — любой, кто видит запись; копия — новая запись, автор — копирующий, история не копируется;
   - смена аудитории — по правилу 7, со строкой в истории.
3. **API** в `apps/server`: список, карточка, создание, правка, закрепление, три действия переноса, смена аудитории, в корзину и восстановление. Для сужения доступа (правило 8) — запрос «кто потеряет доступ» без раскрытия чужого личного. Проверка доступа — на сервере и в RLS одновременно, без служебных обходов. Границы — схемы zod.
4. **NOTE-2:** по умолчанию личная; созданная с указанием общего объекта — в его пространстве и не шире его аудитории (правило 3). Сами объекты появятся позже — проверить на таблице-примере из R0.1.
5. **Решения, которые нужны каждой новой сущности (AGENTS.md):** поиск — колонка или индекс под будущий поиск R0.5 (NOTE-3), без самого поиска; экспорт — что попадёт в личный и общий экспорт R0.10; корзина — 30 дней, дату ставит база. Записать в ADR-0004 или новый ADR.
6. **Журналы:** ни заголовков, ни текстов заметок (PRD, раздел 13).

## Готово, когда

- Матрица доступа охватывает заметки и все действия переноса; расхождений нет; ослабленная политика или лишний перенос роняют тест.
- Интеграционные тесты API на вымышленной семье: взрослый, второй взрослый, ребёнок, администратор не видит чужое личное; «Сделать личной» отказывает при чужом вкладе; копия не тянет историю.
- Пункт бэклога «К R0.4» закрыт тестом и вычеркнут.
- `pnpm check` и CI проходят.
