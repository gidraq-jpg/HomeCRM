# Бриф D31. Быстрее проверки: ловушка, CI, только документы

- **Задача:** сократить время проверок без ослабления (решение владельца 26 октября 2026). Один PR, исполнитель — Codex. Можно параллельно с D29 и D30: только настройки проверок.
- **Требования:** AGENTS «Тесты», [ADR-0019](../adr/0019-agent-workflow.md); runbook, раздел 12.
- **Ветка:** `chore/faster-checks`, worktree `../HomeCRM-d31`.
- **Область:** `.githooks/pre-push`, `scripts/` (новый маленький скрипт выбора проверок), `.github/workflows/ci.yml`, `apps/web/playwright*.config.ts` и `apps/web/e2e/run.ts` только для разбиения на части, `AGENTS.md` (таблица команд и раздел «Тесты»), `docs/runbook.md`, `docs/adr/0019-agent-workflow.md` (дополнение). **Не трогать:** сами тесты и их тайм-ауты, повторные попытки, матрицу доступа, `test:perf`, рабочее окружение.

## Сейчас

- Ловушка `pre-push` всегда запускает `pnpm check`: 7–9 минут, даже если изменены только `.md`.
- CI: «pnpm check» ~17 минут и «Вход · 360 и 412 px · axe» (все браузерные сценарии) 37–45 минут одной очередью, на каждом PR и на каждом push в `main`, включая коммиты только с документами. Бесплатный тариф — 2000 минут в месяц.

## Что сделать

1. **Ловушка.** Если в отправляемых коммитах (относительно `origin/<ветка>` или, для новой ветки, `origin/main`) изменены только документы — `*.md`, `docs/**` кроме `docs/screenshots/**`, `CHANGELOG.md` — запускать только `pnpm check:encoding` и проверку формата этих файлов. Иначе — `pnpm check`, как сейчас. Определение «только документы» — одна чистая функция с модульными тестами (пустой список, смешанный набор, переименование, файлы `AGENTS.md`/`CLAUDE.md`, удалённые файлы). Если git не может определить базу — полный `pnpm check`.
2. **CI для документов.** Задание `changes` определяет тот же набор (та же функция или `paths-filter` с теми же правилами). При «только документы» тяжёлые шаги не выполняются, но задания завершаются **зелёным** с понятной пометкой (не «пропущено» без статуса): проверки остаются видимыми при слиянии. Кодировка проверяется всегда.
3. **Разбиение браузерных тестов.** Задание браузерных сценариев — матрица из 3 частей (`--shard=1/3…3/3`), каждая со своей базой и портами; итоговое задание с прежним именем «Вход · 360 и 412 px · axe» зелёное, только если зелёные все части (так ведущий смотрит одно имя). Артефакты снимков — из каждой части. Лимит каждой части — 30 минут.
4. **Замеры скорости** (`test:perf`) — без изменений: отдельный шаг после остальных тестов.
5. **Документы:** AGENTS.md и runbook — что делает ловушка для документов, как запустить полный прогон вручную (`pnpm check`); дополнение в ADR-0019 с причиной.

**Готово, когда:** push коммита только с `.md` проходит ловушку меньше чем за минуту, а коммит с кодом — полным `pnpm check`; на PR только с документами CI зелёный за несколько минут; на PR с кодом браузерные сценарии идут тремя частями, итог — одно зелёное задание с прежним именем, время шага в отчёте до/после; модульные тесты функции «только документы»; ни один тест не удалён и не пропущен; `pnpm check` и CI зелёные.

**Общие правила:** без новых зависимостей, если хватает `git diff --name-only` (для `paths-filter` — обоснование в PR); `--no-verify` запрещён; коммиты `0.19: …` (ADR-0019); PR открыть, не сливать; отчёт до 15 строк по шаблону `AGENTS.md`.
