# Бриф R0.5b. Файлы с шифрованием и превью: база и API

- **Задача:** вторая половина R0.5 из [плана](../03-dev-plan.md) — файлы записей. Объекты, связи и лента готовы (R0.5a, PR #16, [ADR-0023](../adr/0023-objects-links-timeline.md)).
- **Требования:** OBJ-4, OBJ-1 (файлы в карточке), OBJ-5; PRD разделы 7.2, 7.3 (корзина, перенос, копия), 13 (журналы), таблица безопасности «Файлы»; [ADR-0010](../adr/0010-files-encryption.md), [ADR-0004](../adr/0004-access-code-and-rls.md).
- **Ветка:** `feat/obj-4-files`, в своём worktree от свежего `main`. Параллельно Sonnet делает экраны объектов (R0.5c, только `apps/web`) — туда не заходить.

## Сделать

1. **Сущность «файл»** — дочерняя запись объекта и заметки: лежит в пространстве родителя, аудитория не шире родителя (OBJ-5), поля доступа как у остальных дочерних записей; RLS ENABLE + FORCE, политики на все операции, двойники в `access.ts` и строки матрицы доступа. Вклад (PRD 7.3.6): добавление и удаление файла другим участником — вклад.
2. **Хранилище за интерфейсом** «положить, взять, удалить по ключу» (ADR-0010): реализация — папка на томе (`/data/files` в контейнере), ключ хранения случайный и не связан с именем. Имя файла, размер и тип — только в базе.
3. **Шифрование конвертом:** у каждого файла и каждого превью свой ключ AES-256-GCM; ключ файла зашифрован главным ключом; у главного ключа есть номер (для будущей смены). Главный ключ читается из файла, путь — из переменной окружения (zod); без ключа сервер не стартует с понятным сообщением без значения ключа. Тестовый ключ — только в тестах.
4. **Загрузка** `POST` в карточку записи: фото (JPEG, PNG, WebP, HEIC) и PDF до 25 МБ; тип определяется по содержимому, а не по расширению и заголовку; иначе 415. Превью фото — через sharp, из фото удаляются метаданные (EXIF и GPS). Запись в базу и в хранилище согласованы: при сбое транзакции нет «висящего» блока, при сбое записи блока нет строки в базе; осиротевшие блоки убирает фоновая очистка.
5. **Выдача** `GET` файла и превью — только после проверки доступа к записи-родителю; чужой и несуществующий id — одинаковый 404; `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Content-Disposition` с безопасным именем; файлы не отдаются как HTML. Публичных ссылок нет.
6. **Корзина и перенос:** файл уходит в корзину и возвращается вместе с родителем (как поля и события в R0.5a); окончательная очистка стирает и блоки в хранилище. Перенос и копия родителя (SPACE-7) переносят и копируют файлы; предпросмотр «кто потеряет доступ» учитывает файлы.
7. **Фото профиля:** `photoFileId` в профиле (`apps/server/src/household`) принимает только свой файл (бэклог, ревью PR #11).
8. **Решения о поиске и экспорте** записать в ADR (новый, номер 0024 или выше): что из файла попадает в поиск (имя — да или нет), как файлы попадают в экспорт R0.10. Отказ 23503 не раскрывает чужие записи — тест.
9. **Эксплуатация:** том `/data/files` в compose и в копиях restic (сейчас копия файлов не работает — бэклог «Отчёт R0.11a»), создание главного ключа — в скрипте первого включения и в runbook (раздел 7): ключ в `E:\HomeCRM-data\secrets`, владелец сохраняет его вне компьютера вместе с паролем restic. Рабочее окружение не включать.

## Готово, когда

- Матрица доступа для файлов без расхождений; тесты: загрузка и выдача для каждой роли, чужой файл — 404, подмена типа — 415, 25 МБ + 1 байт — отказ, EXIF удалён, блок в хранилище не читается без ключа, корзина и очистка стирают блоки, перенос и копия.
- В журналах нет имён файлов, ключей и путей хранения.
- Миграция безопасна для существующей базы; `pnpm check` и CI проходят.
- Новые зависимости (sharp, разбор multipart, определение типа по содержимому) — с обоснованием в описании PR.
