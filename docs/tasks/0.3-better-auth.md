# Бриф 0.3. Проверка Better Auth

- **Задача:** 0.3 из [плана](../03-dev-plan.md) — решить, подходит ли Better Auth ([ADR-0005](../adr/0005-better-auth.md)).
- **Требования:** AUTH-1…9.
- **Ветка:** `spike/0.3-better-auth`, в своём worktree. Начинать после слияния 0.4: обе задачи меняют схему базы, а её меняет один исполнитель за раз.

## Сделать

Прототип на Fastify и Drizzle поверх схемы из 0.4. Проверить каждый пункт таблицы ADR-0005:

- вход по имени пользователя без e-mail; хэш паролей Argon2id вместо scrypt по умолчанию;
- приглашение с ролью: одноразовое, на 72 часа; открытая регистрация выключена;
- TOTP, обязательный для администратора; 10 одноразовых кодов восстановления;
- сессии до 90 дней с продлением; список устройств; «Выйти на всех устройствах»;
- повторный ввод пароля перед сменой пароля, второго фактора и экспортом;
- ограничение попыток с временной блокировкой; журнал входов;
- сброс пароля: администратор — только ребёнку; ребёнок видит отметку о сбросе;
- cookie `Secure`, `HttpOnly`, `SameSite`; защита от CSRF;
- таблицы библиотеки получают политики RLS по ADR-0004.

## Готово, когда

- По каждому пункту — «да», «да, но своим кодом» с объёмом этого кода, или «нет». На каждый пункт есть тест.
- Решение записано в ADR-0005: принято или отклонено с запасным вариантом.
- `pnpm check` проходит.
