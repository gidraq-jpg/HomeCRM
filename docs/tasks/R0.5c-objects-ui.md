# Бриф R0.5c. Объекты: экраны

- **Задача:** экраны объектов на готовом API (R0.5a, PR #16; [ADR-0023](../adr/0023-objects-links-timeline.md), [описание API](../objects-api.md)). Каркас (R0.3b) и заметки (R0.4b) готовы — брать их приёмы: `apps/web/src/notes`, `shell`, `ui`.
- **Требования:** OBJ-1…3, SPACE-5…7, TPL-4; PRD разделы 7.2, 7.3, 13, 14 (раздел «Дом», «Карточка объекта»). Файлы (OBJ-4) — не здесь: их API делает Codex в R0.5b; в карточке оставить место под вкладку «Файлы», без вымышленных данных.
- **Ветка:** `feat/obj-1-objects-ui`, в своём worktree от свежего `main`. Параллельно Codex меняет `packages/db`, `access.ts`, `apps/server` (R0.5b) — туда не заходить.

## Сделать

1. **Раздел «Дом»** (нижнее меню): список объектов под переключателем «Всё · Общее · Личное», группировка или подпись по типу (недвижимость, машина, техника, другое), значок и подпись «Кто видит», статус объекта (например «живём», «сдаётся» — как в прототипе) рядом с названием; пустое состояние по TPL-4. Пример оформления — `apps/web/src/prototype/screens/Home.tsx`: брать оформление, не данные.
2. **Создание** («+» → «Объект» и из «Дома»): название (единственное обязательное поле), тип, строка «Кто видит» над «Сохранить» — значение по таблице PRD 7.2 (недвижимость — «Взрослые») и режиму переключателя. Ребёнку — только то, что разрешает `access.ts`.
3. **Карточка объекта** по PRD раздел 14: название и статус в заголовке, вкладки переносятся на вторую строку (`ui/LinkTabs`), порядок: «Обзор», «Лента», затем остальные. «Обзор»: поля типа, свои поля «название — значение» (добавить, изменить, удалить), автор, ответственный, «Кто видит». Сохранение с `expectedUpdatedAt` и выбором при конфликте — как у заметок.
4. **«Лента»** (OBJ-3): события объекта по дате, ручное событие — текст, дата, сумма в рублях (хранится в копейках), оценка, контакт; правка и корзина своего события. Невидимый контакт API отдаёт как `contact: null` — показывать событие без контакта, без намёка, что он был.
5. **Связи** (OBJ-2): список связанных записей с подписью роли, «Связать…» с выбором видимой записи (объекты и заметки), удаление связи. Связь появляется в карточках обеих записей, в том числе в карточке заметки.
6. **Действия SPACE-7:** «Поделиться…», «Сделать личным…», «Кто видит…», «Скопировать в личное» — по правилам `access.ts`, с экраном «кто потеряет доступ» из access-preview и `confirmed`, как у заметок. Недоступное — не показывается.
7. **Корзина:** «В корзину» с отменой 7 секунд; объекты — в общем разделе «Корзина» рядом с заметками, «Восстановить» возвращает и поля, и события.
8. **Журналы и кэш:** ни названий, ни значений полей, ни текстов событий в консоли, адресах, localStorage и кэше сервис-воркера; черновик — только в памяти страницы.

## Готово, когда

- Playwright на 360 и 412 px (и 1280 px для бокового меню) с axe: список, пустое состояние, создание, карточка с вкладками на второй строке («Лента» видна без прокрутки на 360 px — бэклог, ревью PR #15), свои поля, конфликт, лента и ручное событие, связь с заметкой, четыре действия, корзина и восстановление. Цели нажатия от 44 px, без горизонтальной прокрутки, без серьёзных замечаний axe. Скриншоты — в `docs/screenshots/R0.5c/` и в описании PR.
- Сквозной тест на вымышленной семье: объект «Взрослые» не виден ребёнку ни в «Доме», ни в связях заметки; личный объект не виден второму взрослому и администратору.
- Тексты по PRD раздел 13 (суммы в рублях, даты «5 окт.», формы множественного числа); `pnpm check` и CI проходят.
- Чего не хватает в API — не менять сервер, записать в отчёте.
