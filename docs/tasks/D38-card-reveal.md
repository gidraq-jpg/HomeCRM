# Бриф D38. Раскрытие карточки без искажения

- **Задача:** владелец 31 октября 2026 после выпуска v0.5.12 (PR #97): «анимация карточки какая-то кривая, очень резкая». Исполнитель — агент Claude.
- **Требования:** UI-8 (уточнение 31 октября), ADR-0045 «Уточнение 31 октября 2026», стиль — сдержанный, как в iOS.
- **Ветка:** `fix/ui-8-card-reveal`, worktree `../HomeCRM-d38`, порты `PORT=8430`, `WEB_PORT=5290`, compose-проект `homecrm-test-fix-ui-8-card-reveal`.
- **Область:** `apps/web/src/shell/motion.tsx`, `apps/web/src/styles/motion.css`, `apps/web/e2e/**`, ADR-0045 (абзац уточнения). **Не трогать:** сервер, базу, правила доступа, CI, раскрытие раздела из значка панели (`changeDockScreen`), возврат к месту списка (`useNavigationPosition`), D30 для форм, D32, улёт дел, рабочее окружение `homecrm`.

## Почему криво

`motion-card-in` / `motion-card-out` масштабируют **весь снимок экрана** неравномерно: `scale(ширина строки / ширина экрана, высота строки / высота экрана)` — по вертикали ≈ 0,08, по горизонтали ≈ 1. Текст и шапка сплющены, затем рывком вытягиваются. Новый экран начинает с `opacity: 0.25`, старый гаснет за всё время, название (`card-title`) меняется за 160 мс — получается резко.

## Сделать

1. **Раскрытие окном, а не растяжением.** Новый экран (`::view-transition-new(screen)`) не масштабируется неравномерно. Он открывается через `clip-path: inset(top right bottom left round R)` от границ строки до `inset(0 round 0)`. Допустимо равномерное `scale(0.97 → 1)`. Радиус ≈ 16 px → 0.
2. **Содержимое проявляется** в первой половине раскрытия (`opacity` 0 → 1 примерно за 60 % времени), а не с 0,25. Список под карточкой не исчезает резко: слегка темнеет или гаснет вместе с раскрытием.
3. **Возврат** — обратное движение: окно сжимается к заново измеренной строке, список проявляется; строка коротко подсвечивается, как сейчас.
4. **Время и кривая:** `--motion-screen` (400 мс) мало — нужна новая переменная, например `--motion-card: 480ms`, и плавная кривая без пружины (`--ease-sheet` или похожая). Название переходит в шапку одним движением, без мигания за 160 мс. Если общий переход названия выглядит хуже — убрать его, оставив раскрытие окна.
5. **Только `clip-path`, `transform` (равномерный), `opacity`.** При «Уменьшить движение» — только смена прозрачности. Без View Transitions навигация работает.
6. Обновить абзац ADR-0045: раскрытие окном через `clip-path`, без неравномерного масштаба.

**Готово, когда:** e2e на 360 и 412 px с axe проверяет, что во время раскрытия у `::view-transition-new(screen)` нет неравномерного `scale` (или анимация идёт через `clip-path`), первый кадр окна совпадает с границами строки, а при `reducedMotion: 'reduce'` геометрии нет. Существующие сценарии `spatial-motion`, `dock-motion`, D30 и D32 зелёные. `pnpm check:changed` и CI зелёные.
