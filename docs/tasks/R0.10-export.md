# Бриф R0.10. Экспорт личного и общего

- **Задача:** R0.10 из [плана](../03-dev-plan.md) — выгрузка данных в JSON с файлами в ZIP: каждый выгружает своё личное, администратор — общее дома. Это гарантия «данные мои» и основа будущего импорта из LifeOS.
- **Требования:** DATA-2; PRD 7.2, 7.3 (кто что видит), 13 (журналы без текстов); AGENTS.md — у каждой сущности есть решение об экспорте (в ADR модулей: 0022 заметки, 0024–0026 объекты и файлы, 0027 поиск, 0028 сроки, 0029 уведомления — проверь фактические номера).
- **Ветка:** `feat/data-2-export`, в своём worktree от свежего `main`. Параллельно на ревью PR #30 (сроки, миграция 0026) — `apps/server/src/deadlines`, `apps/server/src/notifications` и `apps/web/src/deadlines` не менять.

## Сделать

1. **Состав:** «Моё личное» — все записи участника с аудиторией «Только я» (заметки с чек-листами, объекты со своими полями, связями и лентой событий, файлы, сроки), его профиль «Обо мне», настройки уведомлений. «Общее дома» (только администратор) — записи пространства дома, которые он видит, вместе с составом дома без секретов. Чужое личное не попадает ни в один экспорт; записи «Взрослые» — только в экспорт дома. Решения по каждой сущности — таблица в новом ADR (номер 0030 или выше); то, что не выгружается (сессии, подписки push, журнал доставки, индекс поиска, служебные таблицы), — с причиной.
2. **Формат:** ZIP с `manifest.json` (версия формата, дата, часовой пояс дома, что выгружено, число записей по видам), JSON по видам записей и папкой `files/` с исходными файлами в открытом виде (расшифрованы при выгрузке). Схема — zod в `packages/shared`, версия формата для будущего импорта. Деньги — копейки, даты — как в базе (`date`, `timestamptz`).
3. **Доступ:** выгрузка идёт под RLS запрашивающего (роль app, контекст участника), без служебных обходов; права — функция в `access.ts` (`canExportHouse` и т. п.) с двойником в матрице. Запуск — после подтверждения паролем или вторым фактором через существующий `sensitiveSessionMiddleware` (как сброс пароля ребёнку). Ограничение частоты — как у входа.
4. **Безопасность:** архив собирается потоком в ответ или во временный файл внутри контейнера с удалением сразу после отдачи; на диске не остаётся расшифрованных файлов. В журналах — только вид экспорта, число записей и размер, без названий и текстов. Отметка в истории изменений: кто и когда выгружал.
5. **Экран:** «Ещё» → «Мои данные» (или существующие настройки): «Скачать моё личное», у администратора — «Скачать общее дома»; подтверждение, ход выгрузки, ошибка с повтором. Тексты по PRD раздел 13.

## Готово, когда

- Тесты на вымышленной семье: экспорт ребёнка, взрослого и администратора — ровно ожидаемые записи; чужое личное и чужие файлы не попадают ни при каких ролях; «Взрослые» не попадают к ребёнку; записи в корзине — по решению ADR; файлы в архиве совпадают с исходными (хеш).
- Матрица доступа для прав экспорта без расхождений; архив на 1000 записей и 50 файлах собирается без загрузки всего в память.
- Playwright экрана на 360 и 412 px с axe; `pnpm check` и CI проходят; новая зависимость для ZIP — с обоснованием в PR.
- Без миграций базы, если можно; если нужна — сначала вопрос ведущему.

`apps/server/src/deadlines`, `apps/server/src/notifications`, `apps/web/src/deadlines` (PR #30), рабочее окружение: compose-проект `homecrm`, порты 8300, 8301 и 8309, `E:\HomeCRM-data`.
