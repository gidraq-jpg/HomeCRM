# Бриф D21. Голосовой ввод: дела и покупки

- **Задача:** идеи А3 и А4 из [идей R2](../04-ai-capture-ideas.md), решение владельца 21 октября 2026. Один PR, исполнитель — агент Claude.
- **Требования:** TASK-2 (абзац о диктовке), SHOP-4; PRD 13; WCAG 2.2 AA; [контракт Studio 2](../design/studio.md).
- **Ветка:** `feat/task-2-voice-input`, worktree `../HomeCRM-voice`, порты `PORT=8371`, `WEB_PORT=5233`.
- **Область:** только `apps/web` (`src/tasks/Quickline.tsx`, `QuickAddSheet.tsx`, `src/shopping/*`, новый общий модуль, например `src/voice/`). Новые e2e — `apps/web/e2e/app/voice-input.e2e.ts`.
- **Не трогать:** сервер, миграции, `access.ts`, RLS, `deploy`. Новых зависимостей нет — только Web Speech API браузера.

1. **Общий модуль распознавания речи** (`src/voice/`): обёртка над `SpeechRecognition` / `webkitSpeechRecognition`, `lang='ru-RU'`, `interimResults` для живого текста, один вызов — одна фраза, стоп по второму нажатию или по тишине. Определение поддержки; ошибки `not-allowed`, `network`, `no-speech`, `audio-capture` → понятные русские сообщения (PRD 13). Без поддержки — кнопки нет совсем. Звук нигде не сохраняется и на наш сервер не уходит; в журналы текст не пишется.
2. **Кнопка микрофона** — общий компонент: цель 44 px, доступное имя «Надиктовать» / «Остановить запись», `aria-pressed`, видимое состояние записи (не только цветом), объявление `aria-live` о начале и конце. Работает с клавиатуры.
3. **Дела (TASK-2):** кнопка в строке быстрого добавления (`Quickline`, `QuickAddSheet`). Распознанный текст вставляется в поле (дописывается к уже введённому через пробел); дальше — существующий разбор с чипами, сохраняет человек. Ничего не сохраняется автоматически.
4. **Покупки (SHOP-4):** кнопка в строке добавления «Покупок». Чистая функция разбора `splitShoppingDictation(text)` → `{ title, quantity? }[]`: разделители — запятые, «и», «ещё», «а также», «потом»; количество в начале позиции — числа цифрами и словами (один…десять, «пару», «десяток», «два десятка» → 20 шт.), единицы «кг», «килограмм», «грамм», «литр», «пачка», «батон», «бутылка» и т. п. Не делить внутри устойчивых названий там, где «и» стоит без пробелов вокруг (тест на «хлеб и соль» как две позиции допустим — правило простое и описано в отчёте). Перед добавлением — лист черновиков: правка названия и количества, удаление строки, «Добавить N позиций» с правильной формой множественного числа; дубли проверяются тем же `duplicates.ts`. Пространство и аудитория — как у строки ввода.
5. **Офлайн:** распознавание без сети не работает — сообщение «Распознавание речи недоступно без интернета»; добавление позиций офлайн идёт существующей очередью.

**Готово, когда:**
- юнит-тесты разбора покупок — не меньше 20 фраз, включая количества словами и цифрами, пустые и лишние разделители;
- e2e на 360 и 412 px с axe: подмена `SpeechRecognition` в `addInitScript` (фиктивный распознаватель выдаёт заданный текст и ошибки); сценарии — дело голосом → чипы даты и объекта → сохранение; покупки голосом → три черновика → правка → добавление; отказ в микрофоне; браузер без поддержки — кнопки нет;
- `pnpm check` и CI проходят; снимки 360 px — в `docs/screenshots/D21/`.

**Общие правила:** вымышленная семья; один перезапуск упавшего e2e; коммиты `TASK-2: …` / `SHOP-4: …` с `Co-Authored-By: Claude <noreply@anthropic.com>`; PR открыть, не сливать; отчёт — до 15 строк по шаблону `AGENTS.md`.
