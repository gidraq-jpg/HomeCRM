# Бриф R0.9a. Состав дома: база и API

- **Задача:** первая половина R0.9 из [плана](../03-dev-plan.md) — состав дома на сервере, без экранов, и связанные с ним долги R0.4a и R0.2. Экраны — R0.9b вместе с навигацией после проверки прототипа 0.5.
- **Требования:** SPACE-8…10, AUTH-5; PRD, раздел 7.3 (правила 1, 6, 12). Эталон правил — `packages/shared/src/access.ts`.
- **Ветка:** `feat/space-8-household`, в своём worktree от свежего `main`. Схему и `access.ts` в это время меняет только этот исполнитель.

## Сделать

1. **Состав дома без служебных обходов** (бэклог «К R0.9», два пункта):
   - участник дома видит состав своего дома: имя, роль, взрослый или ребёнок, «бывший участник»; чужие дома и чужое личное — нет. Правило — сначала в `access.ts`, затем RLS (таблица состава дома или политика без рекурсии, ADR-0004), строки в матрице;
   - перевести предпросмотр «кто потеряет доступ» и выбор места переноса в заметках (`apps/server/src/notes/routes.ts`) с `homecrm_auth` на это правило;
   - профиль SPACE-10: имя, фото (поле под будущий файл), дата рождения, телефон — видны семье; остальные поля — только владельцу.
2. **API состава дома (SPACE-8, SPACE-9):** список участников; приглашение (уже есть в R0.2 — подключить к составу); смена роли и исключение — только администратор; уход из дома — сам участник; последний администратор уйти или потерять роль не может. Уход и исключение — по правилу 12: личное остаётся у человека, общие записи — в доме с пометкой «бывший участник», ответственность — администратору (`reassign_responsibility()` из R0.1).
3. **Сброс пароля ребёнку из состава (AUTH-5):** API, по которому администратор выдаёт ссылку сброса конкретному ребёнку из списка — для будущего экрана; взрослому — отказ.
4. **Вклад в заметку — по решению владельца** (PRD 7.3.6): вкладом считаются только правка заголовка или текста и пункты чек-листа; закрепление, аудитория, корзина и восстановление — нет. Миграция пересчитывает признак по истории.
5. **Долги из бэклога, которые сейчас в той же области:**
   - правило 7 дней для отметки о сбросе — в политике `password_resets_ack`, не только в маршруте; сортировка отметок в `GET /api/me`;
   - ветка `pg_trigger_depth() > 0` в политике `note_items` — записать в ADR и закрыть мутационным тестом;
   - `routes.ts:142–144` заметок — двойная проверка и 400 вместо 409 `CONFIRMATION_REQUIRED`;
   - история: «аудитория только у общего пространства».
   Закрытые пункты вычеркнуть.

## Готово, когда

- Матрица охватывает состав дома, профиль и новые действия; расхождений нет; ослабленная политика роняет тест.
- Интеграционные тесты на вымышленной семье: ребёнок и взрослый видят состав без чужого личного; не-администратор не меняет роли; последний администратор не уходит; после исключения личное у человека, общие — в доме с пометкой.
- В коде заметок нет чтения состава через `homecrm_auth`.
- `pnpm check` и CI проходят; ADR-0004 дополнен.
