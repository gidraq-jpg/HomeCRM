- **Задача:** R1b.2 и R1b.3 из [плана](../03-dev-plan.md), серверная часть, одним PR (две задачи на бриф). Экраны — отдельной задачей на готовом API.
- **Требования:** DOC-3, DOC-4; CONT-1…5; PRD 7.2, разделы 12 и 13, приложение Б; [ADR-0031](../adr/0031-property-accounts.md) (организации в `contacts`, связи OBJ-2), [ADR-0035](../adr/0035-month-documents-api.md) (документы, источник `document`), [ADR-0028](../adr/0028-deadline-engine.md).
- **Ветка:** `feat/doc-3-passport-people`, в своём worktree от свежего `main` — после слияния PR #43.

## Сделать

### R1b.2 Сроки документов

1. **Предупреждения по типу** (DOC-3): значения по умолчанию — данными в `packages/shared` по приложению Б; в документе их можно переопределить (как `warnings` у сроков R0.8). Существующие документы получают значения по умолчанию без переписывания данных.
2. **Паспорт РФ по возрасту** (DOC-4): если известна дата рождения владельца (участник — из профиля «Обо мне», контакт — поле CONT-1), срок действия вычисляется по 20 и 45 годам; предупреждения — за 60 и 30 дней до дня рождения; после дня рождения — 90 дней на замену. Явно введённый срок действия имеет приоритет; смена даты рождения пересчитывает срок. Даты без времени, в часовом поясе дома; 29 февраля — решите в ADR.

### R1b.3 Люди

3. **Человек** (CONT-1) — вид `person` в `contacts`: ФИО, категории из закрытого списка, телефоны, e-mail, ссылки на мессенджеры, адрес, день рождения (дата без времени, год необязателен — решите в ADR), организация (ссылка на контакт-организацию), заметка. Место по умолчанию — по таблице PRD 7.2 (личные контакты — «Только я»).
4. **Организация** (CONT-2): дополнить существующий вид `organization` полями CONT-2, которых нет (сайт, часы работы, подписи телефонов) — без поломки данных v0.2.0.
5. **Связь с объектом** (CONT-3): уже есть через OBJ-2 — проверить роль-подпись и блок `peopleAndOrganizations` для людей.
6. **Взаимодействия** (CONT-4) — дочерняя запись контакта: вид (звонок, визит, сообщение, работа), дата, текст, сумма в копейках, «звать снова», объект (необязательно). Видны в ленте контакта и связанного объекта — только тем, кто видит и взаимодействие, и объект.
7. **Быстрые действия** (CONT-5): API отдаёт нормализованные `tel:`/`mailto:`/ссылки мессенджеров и адрес для карты; в журналы номера и адреса не попадают.
8. **Для каждой новой сущности и поля** (AGENTS.md): RLS ENABLE + FORCE, двойник в `access.ts`, строки матрицы, история, корзина и восстановление (взаимодействия — вместе с контактом), перенос, поиск (ФИО и организация — да; телефоны, e-mail, адрес — решите в ADR по разделу 12), экспорт; в журналах нет ФИО, телефонов, адресов и сумм.

## Готово, когда

- Тесты: паспорт по 20 и 45 годам с предупреждениями до дня рождения и 90 днями после; явный срок важнее вычисленного; смена даты рождения пересчитывает срок в радаре; переопределённые предупреждения документа. Человек с организацией; взаимодействие видно в ленте объекта только тому, кто видит оба; ребёнок не видит контакты и взаимодействия «Взрослых».
- Матрица доступа без расхождений; `GET /api/deadlines` и список контактов — без N+1 и в пределах замера G4.
- Миграции безопасны для рабочей базы с данными v0.2.0 и PR #43 (после 0042); ADR (0036 или выше); контракт API в `docs/`; `pnpm check` и CI проходят.
