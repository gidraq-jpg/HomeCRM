# Бриф R0.8c. Сроки: доработки по ревью

- **Задача:** закрыть замечания ревью PR #26 и #27 из [бэклога](../backlog.md) до импорта из LifeOS: радар без лишних запросов, восстановление срока из корзины, расхождения прав и обработчика.
- **Требования:** DEAD-1, DEAD-3, DEAD-6; PRD 7.3 (сроки видит тот, кто видит запись), 13 (переход до 300 мс), 14 (сбой блока не ломает экран); [ADR-0028](../adr/0028-deadline-engine.md), [ADR-0029](../adr/0029-notification-dispatcher.md).
- **Ветка:** `fix/dead-3-radar-api`, в своём worktree от свежего `main`.

## Сделать

1. **Радар без N+1:** пункты `GET /api/deadlines` несут источник (`noteId` или `objectId`) и название записи — под тем же RLS, что и сама запись. Клиент (`apps/web/src/deadlines/useRadar.ts`) уже читает эти поля: убрать обход списков и запросы по каждой записи, оставить один запрос; `staleTime` вместо `gcTime: 0` для радара.
2. **Восстановление срока:** `POST /api/deadlines/:id/restore` по правилам `access.ts`; в клиенте «В корзину» удаляет сразу, «Отменить» восстанавливает (вместо отложенного DELETE в `pending.ts`). Срок в корзине — в «Корзине» вместе с остальными записями, если это уже не так.
3. **Права (ревью PR #26):** `canViewDeadline` и RLS дают один ответ для срока, источник которого в корзине (`access.ts:66`); личный срок можно изменить после ухода второго участника из дома (миграция 0023:152 — «house unavailable»); `deadlines.assignee_id` обновляется вместе с `reassign_responsibility()`.
4. **Обработчик (ревью PR #26):** предупреждение, добавленное к существующему сроку, не ставит в очередь уже прошедшие моменты (`engine.ts:181`); пока идёт пересчёт, радар отдаёт прежние наступления или признак «идёт пересчёт», а не пустой список; UPDATE наступлений обработчиком не трогает `completed_at`.
5. **Уведомления до выпуска v0.2.0 (ревью PR #28):** без ключей VAPID worker стартует и считает сроки, а отправка выключена с одной строкой в журнале (`worker.ts:15`); доставка, отменённая в окно пересчёта или при смене ответственного A→B→A, не теряет напоминание — движок и диспетчер создают новую, а не переоткрывают отменённую каждые 5 минут (`dispatcher.ts:27`, `:105`); подписка с тем же адресом от другого участника переходит к нему, а не даёт 409 и не оставляет устройству push по чужим записям (`notifications/routes.ts:56`).
6. **Экран радара (ревью PR #27):** ошибка одного запроса не роняет «Радар» и блок на «Сегодня»; при признаке пересчёта — «Идёт пересчёт» вместо «Сроков пока нет»; пояс пункта — из ответа сервера, а не из `me` (`radar.ts:98`).
