# Бриф R1a.4–5. Счётчики и показания: база и API

- **Задача:** R1a.4 и серверная часть R1a.5 из [плана](../03-dev-plan.md): счётчики с поверкой и заменой, показания с проверками и передачей. Экран «Показания» — отдельной задачей на готовом API.
- **Требования:** UTIL-3, UTIL-4, UTIL-5, UTIL-6, UTIL-8, UTIL-14, OBJ-3 (показания в ленте объекта), OBJ-5; PRD 7.2 (общее, «Взрослые»), сценарий S3, раздел 13; приложение А (интервалы поверки); [ADR-0028](../adr/0028-deadline-engine.md); ADR задачи R1a.1–3.
- **Ветка:** `feat/util-3-meters-readings`, в своём worktree от свежего `main` — после слияния R1a.1–3.

## Сделать

1. **Счётчик** (UTIL-3) — дочерняя запись объекта (OBJ-5) со ссылкой на лицевой счёт того же объекта: ресурс (ХВС, ГВС, электроэнергия, газ, тепло), модель, заводской номер, место установки, тарифность 1–3 зоны с названиями зон, разрядность (целая и дробная часть), единица измерения, дата установки, дата последней поверки, межповерочный интервал (по умолчанию из приложения А), дата следующей поверки — вычисляется, но её можно поправить; статус: работает, заменён, снят.
2. **Показание** (UTIL-4) — дочерняя запись счётчика: дата, значения по зонам, фото (файлы R0.5), кто снял, статус передачи («не передано» или «передано» с датой и способом), комментарий. Значения — точные десятичные (`numeric` или целые в минимальных долях по разрядности), без плавающей точки. Расход с прошлого показания считает сервер.
3. **Проверки** (UTIL-5): значение меньше прошлого не сохраняется, кроме «замены счётчика» и «перехода через ноль» (расход по разрядности); расход на 40% и больше выше среднего за 6 месяцев — предупреждение «Проверьте, нет ли утечки или ошибки» в ответе API (сохранение не блокируется). Начальное заполнение (UTIL-14): одного последнего показания достаточно.
4. **Замена** (UTIL-6): одна операция — конечное показание старого счётчика, статус «заменён», новый счётчик с начальным показанием; история и расход не прерываются.
5. **Пакетный ввод по объекту** (S3, UTIL-7): `GET` активных счётчиков объекта с прошлым значением и местом установки; `POST` нескольких показаний разом — всё или ничего; ответ с расходом и предупреждениями.
6. **Передача** (UTIL-8): значения к передаче, сгруппированные по лицевым счетам, со способом передачи и ссылкой; «Отметить переданными» — пакетом. Событие «показания» в ленте объекта (OBJ-3).
7. **Для каждой сущности** (AGENTS.md): поля доступа, RLS ENABLE + FORCE, двойник в `access.ts`, строки матрицы, история, корзина и восстановление вместе с родителем, перенос вместе с объектом, поиск (по заводскому номеру), экспорт.

## Готово, когда

- Тесты: переход через ноль на разных разрядностях, замена счётчика с непрерывным расходом, аномалия 40% на истории 6 месяцев и при меньшей истории, многозонный счётчик, пакетный ввод «всё или ничего», дата следующей поверки при ручной правке.
- Матрица доступа без расхождений; ребёнок не видит счётчики и показания объекта «Взрослые» ни в списках, ни в ленте, ни в поиске.
- Сценарий S3 через API: четыре счётчика — один запрос на ввод и один на передачу.
- Миграции безопасны для рабочей базы; `pnpm check` и CI проходят; ADR, если решения выходят за ADR задачи R1a.1–3.
