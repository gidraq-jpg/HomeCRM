- **Задача:** владелец 1 ноября 2026: «при распознавании картинки, текста из файла, если добавляется объект, то автоматически этот файл прикрепляется к объекту». Исполнитель — Codex.
- **Требования:** INBOX-3, INBOX-4, AI-2, AI-5, AI-9; поведение корзины и экспорт — как у вложений сейчас.
- **Ветка:** `feat/inbox-4-file-attach`, worktree `../HomeCRM-d40`, порты `PORT=8450`, `WEB_PORT=5310`, compose-проект `homecrm-test-feat-inbox-4-file-attach`.
- **Область:** `docs/02-prd.md` (INBOX-4, сначала), `apps/server/src/inbox/**`, `apps/server/src/files/**`, `apps/server/src/ai/drafts.ts`, экран «Входящих» и черновика в `apps/web/src/**`, тесты, `apps/web/e2e/**`, `docs/screenshots/d40/`.
- **Не трогать:** анимации и `apps/web/src/shell/**`, `styles/motion.css` (там параллельно D39), правила доступа `packages/shared/src/access.ts` и миграции — без крайней необходимости; если без миграции не обойтись — написать в PR почему, политика RLS и строки матрицы доступа обязательны.

## Сначала разобраться

INBOX-4 уже требует: «Исходное фото или файл прикладывается к созданной записи». Проверить, как это работает сейчас, и найти дыры. Ожидаемая дыра — новый объект из черновика (INBOX-3): человек создаёт его по предложению ИИ, а файл к объекту не попадает. Проверить также: файл, загруженный не через «Входящие», а при создании объекта или документа с распознаванием, если такой путь есть.

## Сделать

1. **PRD, INBOX-4** — уточнение 1 ноября 2026 (одним абзацем):
   - если из элемента создан новый объект — исходный файл прикрепляется к объекту (в его документы);
   - если создана запись с вложениями, привязанная к объекту (документ, показание, начисление, заметка), — файл у записи и виден в карточке объекта через неё; если запись — дело, файл прикрепляется к делу, а при новом объекте — к объекту;
   - в черновике есть отметка «Прикрепить исходный файл», по умолчанию включена; снятая — файл удаляется вместе с элементом «Входящих» (AI-5);
   - покупки — без изменений (вложений нет).
2. **Сервер:** сохранение элемента «Входящих» переносит файл к созданной записи и/или новому объекту в одной транзакции; при ошибке ничего не теряется и не остаётся файла-сироты. Аудитория и пространство файла — как у записи, к которой он прикреплён: личное не попадает в общее, «Взрослые» — только взрослым. Если запись в личном, а объект в общем пространстве дома, файл остаётся у записи и в общее не переносится — проверить тестом.
3. **Клиент:** отметка «Прикрепить исходный файл» в черновике (цель нажатия от 44 px, подпись по PRD, раздел 13); после сохранения — короткое сообщение, куда прикреплён файл.
4. Журналы — без названий файлов и содержимого (PRD, раздел 13; AI-5).

**Готово, когда:**
- Интеграционные тесты: новый объект из элемента получает файл; запись с объектом — файл у записи; снятая отметка — файл удалён; личный элемент + общий объект — файл не виден другому участнику; ошибка в середине — ни сироты, ни потери.
- e2e черновика на 360 и 412 px с axe; скриншоты в `docs/screenshots/d40/`, только вымышленная семья.
- `pnpm check:changed` и CI зелёные; если задеты файлы и доступ — полный `pnpm check`.
