- **Задачи плана:** R1d.2 и R1d.3. Один PR, исполнитель — Codex. Параллельно идёт D23b (выпуск и копии) — области не пересекаются.
- **Требования:** TPL-5 (с оговоркой из раздела 7.5 PRD), SRCH-5; PRD 13; WCAG 2.2 AA; [контракт Studio 2](../design/studio.md).
- **Ветка:** `feat/tpl-5-first-entry-perf`, worktree `../HomeCRM-d23a`, порты `PORT=8375`, `WEB_PORT=5237`.
- **Область:** `apps/web` (первый вход), `apps/server` (флаг первого входа, ускорение запросов), `packages/db` (одна миграция), perf-тесты и генератор данных. **Не трогать:** `apps/server/src/ops`, `deploy`, `access.ts` и политики RLS чужих таблиц.

## 1. Первый вход (R1d.2, TPL-5)

1. Экран «Как устроены личное и общее» уже есть (`apps/web/src/screens/SpacesScreen.tsx`, ссылки из «Ещё», «Сегодня», шапки). Его нужно **показать автоматически при первом входе каждого участника**: после входа и до «Сегодня», один раз. Кнопка внизу «Понятно» (цель 44 px) ведёт на «Сегодня»; при уходе по ссылке или закрытии экран тоже считается показанным.
2. Отметка «показано» — личная, на сервере, а не в localStorage (вход с другого телефона не показывает экран повторно): новая колонка в существующей личной таблице настроек участника (как `today_main_enabled` в миграции 0065) с `GRANT UPDATE` только на неё; у уже существующих участников миграция ставит «показано», чтобы экран не выскочил семье после выпуска. Новая колонка — в экспорте, если настройки экспортируются; матрица доступа — по существующим правилам таблицы.
3. Текст экрана сверить с TPL-5 и разделом 7.5 PRD (оговорка обязательна); ребёнок видит тот же экран с формулировками для его роли, если PRD их различает.
4. e2e `apps/web/e2e/app/first-entry.e2e.ts` на 360 и 412 px с axe: новый участник видит экран один раз; повторный вход и второй браузер — не видят; существующий участник после миграции — не видит.

## 2. Производительность (R1d.3, SRCH-5)

1. Генератор вымышленных данных на **10 000 записей** вымышленной семьи: дела (с повторами), заметки, контакты, документы, объекты, покупки, сроки радара, начисления; личное и общее в реалистичной пропорции, часть в корзине. Детерминированный (seed), используется perf-тестами; в рабочую базу не попадает.
2. Perf-тесты на этом наборе: `/api/search` (несколько типичных запросов, включая одну букву и фразу), `/api/tasks/today`, лента «План», радар. Предел — **p95 ≤ 300 мс**, запуск — `pnpm test:perf`.
3. `/api/tasks/today` сейчас даёт 305 мс на CI (бэклог 20 и 21 октября, `apps/server/src/tasks/feeds.ts`) — разобрать запросы (`EXPLAIN ANALYZE` в отчёт), убрать лишние обращения, при необходимости индексы в той же миграции. Цель — запас не меньше 30 % от предела на CI.
4. Правила доступа не ослаблять: ускорение не обходит RLS и проверки сервера.

**Готово, когда:** e2e первого входа на 360 и 412 px с axe; `pnpm test:perf` зелёный на 10 000 записях с p95 в отчёте по каждому запросу (до и после); `pnpm check`, матрица доступа и CI проходят; снимки 360 px — в `docs/screenshots/D23a/`.

**Общие правила:** вымышленная семья; один перезапуск упавшего e2e; коммиты `TPL-5: …` / `SRCH-5: …`; PR открыть, не сливать; отчёт — до 15 строк по шаблону `AGENTS.md`.
