# Бриф R0.8b. Сроки и радар: экраны

- **Задача:** экраны сроков и первый радар на готовом API (R0.8, PR #26; [ADR-0028](../adr/0028-deadline-engine.md)). Полный радар с действиями и закрытием пунктов — R1c.5; здесь — то, что даёт ядро.
- **Требования:** DEAD-1, DEAD-3 (группы и переключатель «Моё · Весь дом»), DEAD-6; заготовка под DEAD-4; PRD разделы 7.3, 13 (даты «5 окт.», «через 3 дня», время дома), 14 (раздел «Сегодня», «Радар» в «Ещё»).
- **Ветка:** `feat/dead-3-radar-ui`, в своём worktree от свежего `main`. Параллельно Codex может менять сервер (R0.7) — туда не заходить.

## Сделать

1. **Срок в карточке записи** (объект и заметка): блок «Сроки» — список сроков записи с ближайшим наступлением; «Добавить срок» с выбором вида правила DEAD-1 (дата; окно «с — по» со временем начала; повтор ежемесячно в день N или ежегодно, каждые N дней или месяцев; «через N после события») и предупреждений за N дней; правка и «В корзину» с отменой 7 секунд — по `access.ts`. Понятные подписи правила: «каждый месяц 20–25 числа с 9:00», «ежегодно 14 нояб.», «за 7 дней».
2. **Радар** («Ещё» → «Радар» и блок на «Сегодня»): группы «Просрочено», «Сейчас», «7 дней», «30 дней», «90 дней» по времени дома; у пункта — название записи, что за срок, когда, значок пространства, переход в карточку. Переключатель «Моё · Весь дом» и общий переключатель «Всё · Общее · Личное». Пустые состояния по TPL-4. Действий DEAD-4 пока нет — только переход в карточку.
3. **Часовой пояс дома** в настройках дома (администратор меняет, остальные видят); все даты на экранах — по нему.
4. **Журналы и кэш:** названия записей и сроков не попадают в консоль, адреса, localStorage и кэш сервис-воркера.
