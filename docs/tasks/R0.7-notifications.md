# Бриф R0.7. Уведомления: подписки и диспетчер

- **Задача:** R0.7 из [плана](../03-dev-plan.md) — серверная основа уведомлений: подписки Web Push, диспетчер с тихими часами и бюджетом, скрытие текста, журнал доставки, досылка после простоя. Первый источник — строки «к отправке» движка сроков (R0.8, [ADR-0028](../adr/0028-deadline-engine.md)). Экраны (разрешение уведомлений, настройки, журнал) — отдельной задачей R0.7b на готовом API.
- **Требования:** NOTIF-1, 2, 4, 6, 7; PRD 7.3.9 (получатель — ответственный, только если видит запись), 13 (журналы без текстов); [ADR-0009](../adr/0009-web-push.md), [ADR-0006](../adr/0006-pg-boss.md), [ADR-0004](../adr/0004-access-code-and-rls.md).
- **Ветка:** `feat/notif-1-push`, в своём worktree от свежего `main`.

## Сделать

1. **Подписки:** таблица подписок на устройство (адрес, ключи, название устройства, последняя успешная доставка) — видит и меняет только сам участник: RLS ENABLE + FORCE, двойник в `access.ts` при необходимости, строки матрицы. API: `GET /api/push/key` (публичный ключ VAPID), подписать, отписать, список своих устройств. Уход из дома и отзыв сессии устройства убирают подписки.
2. **Настройки уведомлений участника:** тихие часы (по умолчанию 22:00–8:00, время дома), дневной бюджет push (по умолчанию 5), включение по видам, «Скрывать текст на экране блокировки» (по умолчанию включено). API чтения и изменения — только своих.
3. **Диспетчер** в `worker`: берёт строки «к отправке»; перед каждой отправкой заново проверяет, что получатель в доме и видит запись (бэклог «Ревью PR #26»); в тихие часы откладывает до их конца; сверх бюджета — помечает «в сводку» (сами сводки NOTIF-5 — позже); со скрытием текста отправляет только «В HomeCRM есть новое». Содержимое push минимальное: вид, идентификатор записи, короткий текст.
4. **Доставка** (NOTIF-7): библиотека `web-push`; повтор с растущей паузой; 404 и 410 удаляют подписку; защита от дублей — уникальный ключ «наступление + предупреждение + устройство». После простоя пропущенное уходит один раз; старше суток — в сводку, а не пачкой push.
5. **Журнал доставки:** таблица попыток (когда, вид, устройство, итог, код ошибки) с правами только своего участника; `GET` своих последних записей; очистка старше 90 дней обработчиком.
6. **Ключи VAPID:** `new-app-secrets.ps1` добавляет их, только если их ещё нет, в `worker.env` (закрытый ключ) и в окружение app (только публичный); повторный запуск безопасен; то же для предпросмотра; шаг описан в runbook, раздел 7. Если ключи этапа 0 уже лежат в секретах, скрипт берёт их, а не создаёт новые.

## Готово, когда

- Тесты: тихие часы через полночь и в часовом поясе дома, бюджет и перенос «в сводку», повтор и удаление подписки на 404/410, отсутствие дублей при повторном запуске задачи, перепроверка доступа (ушёл из дома, запись стала личной, ребёнок и «Взрослые»), скрытие текста, досылка после простоя.
- Матрица доступа для подписок, настроек и журнала без расхождений; чужие подписки и журнал не видны никому, включая администратора.
- В журналах сервера нет текстов уведомлений, названий записей и адресов подписок (адрес подписки — секрет устройства).
- Миграция безопасна для существующей базы; `pnpm check` и CI проходят; ADR о диспетчере (номер 0029 или выше), если решения выходят за ADR-0009.

## Не трогать

`apps/web` (параллельно идут экраны сроков и радара R0.8b), `apps/server/src/auth` — кроме удаления подписок при отзыве сессии, рабочее окружение: compose-проект `homecrm`, порты 8300, 8301 и 8309, `E:\HomeCRM-data` (только через скрипт, который запускает владелец). Выпуск — только по команде владельца.

Отчёт — по шаблону из `AGENTS.md`, в описании PR.
