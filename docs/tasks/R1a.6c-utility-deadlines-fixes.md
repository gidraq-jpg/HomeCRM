# Бриф R1a.6c. Сроки коммуналки: исправления до выпуска

- **Задача:** замечания ревью PR #38 (строка бэклога «Ревью PR #38») — до выпуска с коммуналкой: после выпуска радар не должен заполниться прошлыми окнами, а настройки уведомлений должны работать по видам.
- **Требования:** UTIL-13, DEAD-1, DEAD-5, NOTIF-2, NOTIF-4; приложение Б («Все значения меняются в карточке записи»); [ADR-0033](../adr/0033-utility-deadlines.md) — обновить решения.
- **Ветка:** `fix/util-13-deadlines-fixes`, в своём worktree от свежего `main`.

## Сделать

1. **Настройки по видам** (NOTIF-4, `dispatcher.ts:139`): `deadline` — только обычные сроки заметок и объектов; прежнее значение `['deadline']` одной безопасной миграцией разворачивается в полный список видов, чтобы выбор пользователя не изменился.
2. **Без прошлого при выпуске** (`engine.ts:78`): коммунальные наступления считаются с момента создания источника (счёта или счётчика) или заполнения миграцией, а не от «сейчас − 90 дней»; прошлые окна и оплаты не становятся просроченными и не уходят в сводку.
3. **Пустые предупреждения** (`0033:392`, `0033:434`): явный пустой `warnings` выключает предупреждения; умолчание — только когда поле не задано.
4. **Окно без счётчиков — решение владельца 8 октября:** напоминать. Окно счёта без активных счётчиков открывается в радаре и push с подсказкой «Добавьте счётчики»; закрывается по концу окна или отметкой «Передано» на уровне счёта (новый вызов). ADR-0033 — поправить.
5. **Личные коммунальные сроки** (`0033:361`, `dispatcher.ts:29`, `engine.ts:173`): движок и диспетчер проверяют получателя одинаково — владелец, ушедший из выбранного дома, не копит отменённых доставок.
6. **Вид push по правилу, а не по дате:** пользовательское предупреждение до открытия окна не получает текст конца окна; в коротком окне «закрывается завтра» не теряется.
7. **Понятные ошибки:** `POST /api/meters/:id/verify` для счётчика в корзине — код ошибки, а не ошибка триггера; отметка передачи показания в корзине — так же.
8. **Ручные отметки оплаты** не удаляются при снятии правила оплаты больше чем на 30 дней — срок уходит в корзину источника или сохраняет историю.
9. `docs/adr/README.md:42` — пустая строка разрывает таблицу.

## Готово, когда

- Тесты на каждый пункт: старое `['deadline']` после миграции включает те же виды; выпуск на базе с прошлыми окнами — в радаре нет просроченных коммунальных; пустой `warnings` — нет предупреждений; окно без счётчиков открыто и закрывается отметкой; ушедший владелец — нет постановки в очередь.
- Матрица доступа без расхождений; миграции безопасны для рабочей базы, после 0034; `pnpm check` и CI проходят.
