# D4. Studio: итоговая готовность к выпуску

Роль: новый агент приёмки, после слияния UI-1…3. Код не меняет.
Модель: gpt-6-luna; при конкретной функциональной проблеме сообщает лидy доказательства.
Точный итоговый SHA и отдельный worktree выдаёт лид; рабочие compose/база/8300/8301/8309 не трогать.

## Приёмка

1. Прочитать AGENTS, docs/design/studio.md, утверждённый снимок и отчёты трёх PR.
2. Убедиться, что итоговый commit содержит все принятые изменения и зелёный CI.
3. Если финальный полный визуальный Linux-прогон точного SHA уже имеется, использовать его артефакты.
   Если его нет — выполнить один требуемый перед выпуском полный существующий набор в собственном
   Linux-контуре, со своей временной PostgreSQL и без постоянных портов. Не дублировать модульный
   pnpm check и матрицу доступа; они проверены pre-push и CI.
4. Проверить по артефактам соответствие «Сегодня», логотипа и основных семейств компонентов контракту;
   зафиксировать 360/412, один десктоп, доступность, отсутствие ошибок консоли.
5. Никаких новых тестовых матриц, повторов зелёных сценариев и изменения тайм-аутов/assertions.
   Если прогон красный — назвать точный отказ и причину, повторять только после обоснованного исправления.
6. Подготовить отчёт о готовности до 15 строк: SHA, проверки, число/возможные штатные пропуски,
   утверждённые экраны, проблемы и остаточная проверка на настоящих телефонах.

Выпуск делает лид отдельным шагом через существующий deploy/scripts/release.ps1.
Предыдущая рабочая версия на старте задачи: v0.5.0-pilot.1, health/database ok.
Перед выпуском: зафиксированный commit/образ, обязательная копия, штатная процедура,
проверка health/версии/нового клиента и возможность возврата к предыдущему образу.
Рабочие данные в браузере не снимать на скриншоты; UI-доказательства только на вымышленной семье.
Нельзя объявить проверенными настоящие Android/PWA/push по одному локальному прогону.
