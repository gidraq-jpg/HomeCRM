# Бриф R1a.4b–5b. Счётчики и показания: экраны

- **Задача:** экраны R1a.4–R1a.5 на готовом API (PR #35; [ADR-0032](../adr/0032-meters-readings.md), [контракт API](../meters-readings-api.md)). Карточка недвижимости, «Счета» и организации уже есть (R1a.1b, PR #36) — расширять их, брать приёмы `apps/web/src/accounts`, `property`, `objects`, `ui`. Цель — к окну 20–25 ноября семья вносит показания четырёх счётчиков за минуту (сценарий S3).
- **Требования:** UTIL-3…8, UTIL-14, OBJ-3; PRD 7.2, разделы 13 и 14, сценарий S3, приложение А; итог прототипа 0.5 (PRD, раздел 14): название объекта крупно в заголовке «Показаний» — в тесте посторонний ошибся квартирой.
- **Ветка:** `feat/util-7-readings-ui`, в своём worktree от свежего `main`. Параллельно Codex делает R1a.6 в `apps/server`, `packages/db`, `packages/shared` — туда не заходить. Сервер разработки — `PORT=8335`, `WEB_PORT=5197`.

## Сделать

0. **Сначала — клиентские замечания ревью PR #36** (строка бэклога): кадастровый номер — `inputMode="text"`; «Связать с организацией…» — только при праве `canWriteLink`; фильтр «Организаций» без замены экрана на «Загружаем…» (`keepPreviousData`); `parseArea` принимает «54,» и «,5»; `deriveTitle` не заменяет введённое название; поломанный комментарий в `ObjectForm.tsx:43`; `search.e2e` не перезаписывает снимки `docs/screenshots/R0.6`.
1. **Вкладка «Счётчики»** в карточке недвижимости (UTIL-3): список — ресурс, место, заводской номер, последнее показание, следующая поверка; создание с начальным показанием (UTIL-14), лицевой счёт из счетов объекта, зоны 1–3 с названиями, разрядность, интервал поверки по умолчанию из приложения А, дата следующей поверки с ручной правкой. Статус «заменён» и «снят» — в свёрнутой группе.
2. **Замена** (UTIL-6): одна форма — конечное показание старого, данные и начальное показание нового.
3. **Экран «Показания»** (UTIL-7, S3): из карточки объекта и из «Ещё»; в заголовке название объекта крупно и статус, переход к другому объекту с открытым окном (если окон пока нет — к другой недвижимости). Все активные счётчики: место, прошлое значение, поле с цифровой клавиатурой (`inputMode="decimal"`, запятая и точка), зоны отдельными полями, фото (файлы R0.5), «Сохранить всё» одним запросом. Ошибки — у поля («Меньше прошлого: 123,4»), с выбором «замена счётчика» или «переход через ноль»; предупреждение 40% — «Проверьте, нет ли утечки или ошибки», сохранение не блокирует. Черновик — только в памяти страницы.
4. **Передача** (UTIL-8): после сохранения и отдельным разделом — значения по лицевым счетам, кнопка «Скопировать» для каждого значения и всего счёта, кнопка способа передачи (ссылка — только http(s); телефон — номер виден и копируется), «Отметить переданными».
5. **Лента** (OBJ-3): событие «показания» — счётчик, значения, расход.
6. **Журналы и кэш:** ни значений, ни заводских номеров, ни названий в консоли, адресах страниц, localStorage и кэше сервис-воркера.
