# Бриф R0.8d. Клиент сроков и уведомлений: замечания ревью

- **Задача:** закрыть клиентские замечания ревью PR #29 и #30 из [бэклога](../backlog.md) до выпуска v0.2.0. Сервер не меняется: всё нужное API уже есть.
- **Требования:** DEAD-1, DEAD-4, NOTIF-1, NOTIF-2, SPACE-7; PRD 6 (корзина и отмена), 13, 14 (ошибки и ожидание).
- **Ветка:** `fix/dead-4-client-fixes`, в своём worktree от свежего `main`. Сервер разработки — на портах `PORT=8331`, `WEB_PORT=5193`.

## Сделать

1. **«Отменить» после «В корзину»** — только если срок можно восстановить (`canRestore` из ответа API). Взрослый на чужом сроке не видит кнопку, которая закончится 403.
2. **Опрос радара при `recalculating`** — с пределом: интервал растёт (2, 4, 8 с…), после ~1 минуты — текст «Пересчёт затянулся. Обновите страницу позже» и кнопка «Обновить»; на скрытой вкладке опрос не идёт.
3. **Кэш при смене участника:** при смене `me.id` в `AuthRoot` — `client.clear()`, чтобы после входа другого участника в соседней вкладке не мелькали прежние названия.
4. **Переход из уведомления до входа:** нажатие на уведомление при открытом экране входа сохраняет маршрут (`#/open/<id>`) и открывает его после входа; сейчас `PushBridge` живёт только в `Workspace`.
5. **Отказ от карточки уведомлений на «Сегодня»** — по участнику, а не на весь браузер.
6. **`InstallApp.tsx:87`:** при ошибке `prompt()` — показать подсказку (`setHelp(true)`), а не переключить.
7. **`resubscribe` в `sw.ts`** (`pushsubscriptionchange`) — сначала проверка сессии, потом новая подписка; без сессии подписка не создаётся.
8. **Тесты:** открытие по `#/open/<id>` записи, которую участник не видит (сообщение «Запись недоступна», без названия); режим «скрывать текст»; тишина консоли воркера; отмена корзины по `canRestore`; предел опроса радара.
