# Бриф D23b. Надёжный выпуск: копия перед миграцией и ожидание migrate

- **Задача:** проблемы выпуска v0.5.6-pilot.1 из [бэклога](../backlog.md) (20 октября 2026). Один PR, исполнитель — Codex. Параллельно идёт D23a — области не пересекаются.
- **Требования:** DATA-3, DATA-4, [ADR-0021](../adr/), [runbook](../runbook.md), раздел 7.
- **Ветка:** `fix/data-3-release-backup`, worktree `../HomeCRM-d23b`, порты `PORT=8377`, `WEB_PORT=5239`.
- **Область:** `apps/server/src/ops`, `deploy/scripts`, `deploy/compose.yaml`, `docs/runbook.md`. **Не трогать:** миграции, код приложения, рабочее окружение — compose-проект `homecrm`, его тома, `E:\HomeCRM-data`. Выпуск и проверка на рабочем окружении — только ведущим по команде владельца.

## Что случилось 20 октября

Яндекс Диск не отвечал; `restic` (через `rclone`) висел бесконечно на облачном хранилище. `BACKUP_PRE_MIGRATION_CLOUD=skip` не помог: `runBackup` (`apps/server/src/ops/backup.ts:209`) всё равно пытается писать во все хранилища, `skip` влияет только на итоговое `ok`. При этом `release.ps1` поднял `app` новой версии и написал «Готово», пока `migrate` ещё не применил миграцию, — приложение ~20 минут работало без новой колонки.

## Что сделать

1. **Тайм-ауты restic.** Каждый вызов `restic`/`rclone` для облака — с тайм-аутом (настраиваемый, по умолчанию разумный для дампа семейной базы, например 15 минут на `backup` и 2 минуты на служебные команды); по истечении процесс и его дочерние процессы завершаются, результат хранилища — ошибка «cloud timeout» без секретов в тексте.
2. **`skip` действительно пропускает.** При `kind = 'pre-migration'` и `BACKUP_PRE_MIGRATION_CLOUD=skip` облачное хранилище не трогается вовсе; в статусе — явная отметка «пропущено по настройке».
3. **Без `skip` облачная неудача не держит выпуск бесконечно:** после тайм-аута `migrate` либо останавливается с понятным сообщением (если облако обязательно), либо продолжает с локальной копией — поведение по ADR-0021; если ADR не говорит, выбрать «остановиться» и описать в отчёте.
4. **`release.ps1` ждёт `migrate`.** `app` новой версии стартует только после завершения `migrate` с кодом 0 (через `depends_on: condition: service_completed_successfully` или явное ожидание в скрипте); при ненулевом коде — «Выпуск остановлен: migrate завершился с ошибкой», журнал `migrate` (последние строки, без секретов) и подсказка отката. «Готово» — только когда новая версия отвечает и миграции применены.
5. **Runbook:** раздел 7 — что делать, если облако не отвечает при выпуске, и как выпустить с `skip`.

**Готово, когда:** модульные тесты — тайм-аут облака (фиктивный `restic`, который висит), `skip` не вызывает облако, локальная копия при этом делается; проверка `release.ps1` на отдельном compose-проекте `homecrm-test-release` (своя база и тома, не рабочие): миграция с ошибкой → выпуск остановлен, `app` старой версии работает; `pnpm check` и CI проходят.

**Общие правила:** секреты и значения `.env` не выводить; коммиты `DATA-3: …`; PR открыть, не сливать; отчёт — до 15 строк по шаблону `AGENTS.md`.
