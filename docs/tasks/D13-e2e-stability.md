# Бриф D13. Стабильность сквозных тестов CI

- **Задача:** убрать общую причину случайных падений сквозных тестов (Playwright) в CI, чтобы зелёный прогон не требовал перезапусков. Один PR. Исполнитель — Codex.
- **Почему:** в каждом прогоне падают 1–3 разных сценария, не связанных с изменением: `radar-summaries.e2e.ts:195` (смена A → B), `tasks.e2e.ts:698` (назначение ребёнку), `shopping-offline.e2e.ts:418` w412 (H1 «Очередь изменений» после reload), `task-edit-coherence`, `tasks-review` B2, `files-ui.e2e.ts:558` (вёрстка, исправлено в PR #60). Прогоны: main `d645174` — 38681014170; PR #60 — 38704499045 (попытки 1–3). Матрица доступа и модульные тесты стабильны; также известен дедлок 40P01 в access-matrix «удаление в корзину» на `note_items`. **Локально нестабилен и `pnpm check`:** 15 октября перед push дважды за час падал Vitest — один раз `packages/db/src/birthdays-matrix.test.ts` с `53200 out of shared memory` (подсказка `max_locks_per_transaction`) при миграциях тестовой базы в `createTestDatabase`. Закрыть и это: тестовый PostgreSQL с достаточным запасом блокировок или меньше параллельных миграций; пять подряд `pnpm check` на Windows без падений.
- **Ветка:** `test/e2e-stability`, в своём worktree от свежего `main`. Сервер разработки — `PORT=8347`, `WEB_PORT=5209`.

## Сделать

1. **Собрать картину:** по журналам последних 15 прогонов CI (`gh run list`, `gh run view --log-failed`) — таблица «сценарий × сколько раз упал × на чём ждал». Найти общие причины: общая база и порядок между параллельными `workers: 2`, ожидания по времени вместо состояния, гонки сервис-воркера и офлайн-старта, нехватка ресурсов раннера, дедлок 40P01.
2. **Исправить причины, а не симптомы:** изоляция данных между параллельными тестами, ожидание готовности (ответ API, `document.fonts.ready`, активный сервис-воркер) вместо таймаутов; для 40P01 — повтор транзакции в тестовой обвязке или порядок блокировок в тесте, не в коде приложения. Если причина в коде приложения (гонка при старте) — исправить и описать в отчёте.
3. **Нельзя:** включать `retries`, повышать таймауты без доказанной причины, удалять или ослаблять проверки доступа, axe и вёрстки, помечать тесты `skip`/`fixme`.
4. Неустранимое — записать в отчёт с доказательством; карантин тестов только с решения ведущего.
