# Бриф D51. Проверка документа личности: блокировать только явные, решение — за человеком

- **Задача:** владелец 14 ноября 2026: фото во «Входящие» ушло, но разбор отказал с «Документ личности — заполните вручную», хотя это не паспорт. Сейчас перед каждым разбором фото и скана PDF ИИ отвечает `yes/no/unsure`, и любой ответ, кроме `no`, блокирует разбор (`apps/server/src/ai/providers.ts`, `photo()`, ошибка `AI_PRIVATE_DOCUMENT`). Решение владельца: «Блокировать только явные и после давать возможность человеку на принятие решения». Исполнитель — Codex.
- **Требования:** AI-4 (меняется), AI-5, AI-9, INBOX-2, INBOX-4; PRD, раздел 13 (журналы без содержимого).
- **Ветка:** `fix/ai-4-identity-confirm`, отдельный worktree, свой compose-проект `homecrm-test-fix-ai-4-identity-confirm`.
- **Область:** `docs/02-prd.md` (AI-4, сначала), `apps/server/src/ai/**`, `apps/server/src/inbox/**` (только путь разбора), `apps/web/src/ai/PhotoCapture.tsx`, `apps/web/src/charges/ReceiptCapture.tsx`, `apps/web/src/inbox/**`, `packages/shared` (схема запроса разбора, если нужно поле подтверждения), тесты, `apps/web/e2e/**`.
- **Не трогать:** миграции, `packages/shared/src/access.ts`, политики RLS, рабочее окружение `homecrm`, `E:\HomeCRM-data`, чат (CHAT-3 не меняется).

## Сделать

1. **PRD, AI-4** — уточнение 14 ноября 2026 одним абзацем: перед разбором фото или скана ИИ проверяет, не документ ли это личности. Разбор останавливается только при уверенном ответе «да». При сомнении («unsure») разбор идёт как обычно. При «да» человек видит «Похоже на документ личности. Распознать всё равно?» с кнопками «Распознать» и «Заполню вручную». «Распознать» отправляет этот же файл на разбор один раз, только для этого запроса, без запоминания. «Заполню вручную» — как сейчас. Фото в любом случае остаётся вложением.
2. **Сервер:** в `photo()` блокировать только `identity === 'yes'`; `unsure` — продолжать разбор. В запрос разбора (фото, «Входящие», PDF-скан, квитанция) добавить явное поле подтверждения человека, например `identityConfirmed: true` (схема zod на границе). С ним проверка личности пропускается для этого запроса. Ошибка 422 `AI_PRIVATE_DOCUMENT` сохраняется для `yes` без подтверждения, чтобы клиент показал вопрос. Подтверждение не сохраняется в базе и не действует на другие файлы.
3. **Клиент:** при `AI_PRIVATE_DOCUMENT` во «Входящих», в `PhotoCapture` и `ReceiptCapture` — вопрос из п. 1, цели от 44 px, фокус на вопросе, экранный диктор читает текст. «Распознать» повторяет тот же запрос с подтверждением; «Заполню вручную» — текущее поведение.
4. **Журналы:** не писать текст, поля и ответ ИИ; можно — что проверка вернула `yes/unsure/no` и было ли подтверждение (без содержимого).
5. **Тесты:**
   - модульные или интеграционные с подставным ИИ: `no` → разбор; `unsure` → разбор; `yes` → 422; `yes` + подтверждение → разбор; подтверждение одного запроса не влияет на следующий;
   - e2e: фото во «Входящие» → подставной ИИ отвечает «да» → вопрос → «Распознать» → черновик; второй путь — «Заполню вручную». Ширины 360 и 412 px с axe, только вымышленная семья;
   - существующие проверки eval (`apps/server/src/ai/eval/**`) обновить под новое правило, не ослабляя проверку на уверенное «да».
