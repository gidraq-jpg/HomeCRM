# Бриф D42. Покупки вводятся списком

- **Задача:** владелец 1 ноября 2026: «основные покупки — это продукты, их можно вносить списком». Решения владельца: только ввод списком и подтверждение списка при разборе ИИ; набранный список добавляется сразу, с «Отменить»; по умолчанию — в общий список семьи. Отделы магазина, частые покупки и режим «в магазине» — не делать. Исполнитель — Codex.
- **Требования:** SHOP-1…4, AI-2 (разбор в покупки); PRD, раздел 13 (тексты, формы множественного числа).
- **Ветка:** `feat/shop-3-list-input`, worktree `../HomeCRM-d42`, порты `PORT=8470`, `WEB_PORT=5330`, compose-проект `homecrm-test-feat-shop-3-list-input`.
- **Область:** `docs/02-prd.md` (SHOP-3, сначала), `apps/web/src/shopping/**`, `apps/web/src/voice/shopping-dictation.ts`, серверные маршруты покупок `apps/server/src/shopping/**` — только если без них не сделать пакетное добавление или отмену, тесты, `apps/web/e2e/**`, `docs/screenshots/d42/`.
- **Не трогать:** миграции и `packages/shared/src/access.ts`, другие экраны, `apps/web/src/shell/**`, анимации.

## Сначала разобраться

`ShoppingScreen.tsx`: `add()` без диктовки создаёт одну позицию из всей строки; только надиктованное идёт через `dictatedDrafts()` и лист `ShoppingDrafts`. Проверить, куда сейчас попадает результат кнопки «Разобрать» (`AiCapture`) в покупках и как работает `alreadyListed` (`duplicates.ts`).

## Сделать

1. **PRD, SHOP-3** — уточнение 1 ноября 2026 одним абзацем: строка ввода принимает список; позиции делятся по запятым, точкам с запятой и переводам строки (и по «и», как в SHOP-4); количество разбирается из текста («хлеб 2», «2 л молока», «яйца 10», «3 батона»). Набранный список добавляется сразу, без листа черновиков; одно сообщение «Добавлено 5 покупок» с кнопкой «Отменить» убирает всю пачку. Дубли открытых позиций не добавляются, сообщение называет, сколько пропущено. Одна позиция без разделителей — как раньше. Количество меняется кнопками «−» и «+» прямо в строке списка. Разбор ИИ показывает список для подтверждения. Новые позиции по умолчанию — в общий список семьи, если дом есть.
2. **Разбор набранного текста:** тот же разборщик, что у диктовки (`shopping-dictation.ts`), дополнить разделителями `;` и перевод строки и количеством после названия («хлеб 2», «яйца 10 шт»). Модульные тесты на примеры выше и на текст без разделителей; «молоко 3,2%» не должно делиться по запятой внутри числа.
3. **Строка ввода:** многострочное поле, растёт до 4–5 строк, Enter на компьютере добавляет, Shift+Enter — новая строка; на телефоне кнопка «Добавить». Предел длины — достаточный для списка (например 2000 символов без ИИ). Вставка списка из буфера (строки из заметки или мессенджера) работает.
4. **Добавление пачкой:** все позиции одним действием, с ключами идемпотентности; офлайн — как у одиночного добавления (очередь). «Отменить» в течение времени показа сообщения переносит добавленные позиции в корзину или удаляет только что созданные — как принято для отмены в приложении; повторное нажатие безопасно.
5. **Количество в строке:** «−» и «+» у позиции с числовым количеством (и «+» у позиции без количества → «2»); цели нажатия от 44 px, подписи для экранного диктора («Уменьшить количество: молоко»). Нечисловое количество («пачка») не ломается: кнопки скрыты или меняют только число.
6. **Разбор ИИ («Разобрать»):** результат — тот же лист подтверждения, что у диктовки (`ShoppingDrafts`): позиции можно поправить или убрать, добавляются одним нажатием с проверкой дублей. Ничего не добавляется без подтверждения.
7. **Список по умолчанию:** новая позиция идёт в общий список семьи, если у участника есть дом; «Только я» выбирается как сейчас. Убрать повтор переключателя «Вся семья / Только я», если он показан дважды, — оставить один, рядом со строкой ввода.
