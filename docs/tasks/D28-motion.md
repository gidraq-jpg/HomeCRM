# Бриф D28. Язык движения: сдержанные анимации в духе iOS

- **Задача:** UI-8 по [ADR-0045](../adr/0045-motion-language.md). Один PR, две части по порядку, каждая — отдельный коммит; исполнитель — Codex. **Начинать после слияния D27 в `main`**: обе задачи меняют главный экран и общие стили. Решение владельца 25 октября 2026 — сдержанное «нативное» направление по живому примеру.
- **Требования:** UI-8 (PRD 14), TASK-4/6, раздел 13 PRD (доступность); [контракт Studio](../design/studio.md); AGENTS «Интерфейс».
- **Ветка:** `feat/ui-8-motion`, worktree `../HomeCRM-d28`, порты `PORT=8390`, `WEB_PORT=5252`.
- **Область:** `apps/web/src/styles/**`, `apps/web/src/shell/**`, `apps/web/src/ui/**` (лист, плашка, заглушки), `apps/web/src/tasks/**` (строки и свайп), навигация `react-router` в клиенте, e2e клиента, [контракт Studio](../design/studio.md) — новый раздел «Движение». **Не трогать:** сервер, базу, `packages/shared`, правила доступа, отдельную сборку прототипа 0.5, рабочее окружение `homecrm`.

## Часть 1. Основа

1. **Токены** `--motion-fast/base/screen/sheet`, `--ease-out`, `--ease-sheet` — по таблице ADR-0045, в общих стилях Studio. Существующие 160 и 200 мс в `shell.css` перевести на токены. Других длительностей в коде нет.
2. **Смена экрана:** View Transitions. Вглубь — новый экран справа, прежний сдвигается на 30 % влево; «Назад» и кнопка браузера — обратно. Вкладки dock и вкладки раздела — без сдвига. Нижнее меню (dock) и боковое меню стоят на месте — своё `view-transition-name`, едет только содержимое. Без поддержки API — мгновенно. Фокус, заголовок страницы и объявление для экранных чтецов — как сейчас.
   - Клиент на `HashRouter` (декларативный режим, `src/main.tsx`). Сначала проверьте, работает ли в нём `viewTransition` у `Link`/`navigate`: в документации React Router он заявлен для режимов data/framework. Если не работает — **роутер не переводить** на `createHashRouter`, а сделать небольшой общий помощник: `document.startViewTransition` + `flushSync` вокруг навигации, направление — атрибутом на `<html>`. Кнопка «Назад» браузера/Android — анимировать, если получается надёжно, иначе мгновенно; описать в отчёте.
3. **Листы:** выезд снизу с затемнением фона за `--motion-sheet` / `--ease-sheet`; смахивание вниз за ручку и шапку (порог 30 % высоты или скорость больше 0,6 px/мс, иначе лист возвращается). Escape, затемнение, «Отмена» и ловушка фокуса Radix не меняются. Полноэкранные формы (Studio 2, п. 10) — не листы, их не трогать.
4. **Нажатие:** строки — подсветка тоном фона без задержки; кнопки — `scale(.97)` и затемнение; ссылки шапки — тускнеют.
5. **Плашка снизу** (`.toast`) — выезд на 16 px с проявлением, уход так же.
6. **Заглушки загрузки** — общий компонент формы строк списка со спокойным мерцанием. Подключить к спискам «Сегодня», «Все дела», «Дом», «Документы», «Люди» вместо пустого блока. Ошибка и пустое состояние — как сейчас; заглушка не выдаётся за нули.

## Часть 2. Дела и списки

7. **Галочка:** прорисовка `stroke-dashoffset`, через ~0,5 с строка схлопывается по высоте, соседние подтягиваются. Существующие «Отменить выполнение» и выполненные в своей группе (TASK-6, D17) сохраняются.
8. **Свайп строки дела** в «Сегодня», «Плане» и «Всех делах»: влево — «В корзину», вправо — «Выполнено». Длинный свайп (больше 50 % ширины или резкий) — действие сразу; короткий (больше 56 px) открывает кнопку 104 px. Действия — только существующие API и только где они разрешены сейчас (`canTrash` и права выполнения); где нельзя — та сторона не открывается. Для повторяющегося дела в корзину уходит только это дело. После «В корзину» — плашка «Дело в корзине» с «Отменить» через существующий `restore`. **«Отменить» — только если есть `canRestore`:** он строже `canTrash` (в общем пространстве восстанавливает администратор или взрослый-автор), поэтому взрослый, удаливший чужое общее дело, видит плашку без «Отменить». Тест на этот случай. Нужен новый серверный путь — остановиться и описать в отчёте.
9. **Конфликт жестов:** строка забирает жест только после явно горизонтального направления (как в `swipeDirection`) и если он начался на строке; иначе работает существующий свайп между вкладками. Края экрана остаются системе. Логика порогов — чистые функции с модульными тестами рядом с `swipe.ts`.
10. **Списки:** добавленная строка раздвигает список, удалённая схлопывается — общий помощник для лент дел и «Покупок».
11. **Доступность:** у свайпа есть замена без жеста — существующие кнопки в строке и на карточке. Кнопки, открытые свайпом, доступны с клавиатуры и экранному чтецу, пока открыты.

## «Уменьшить движение»

Всё движение — внутри `@media (prefers-reduced-motion: no-preference)`. При `reduce` — без сдвигов, масштабирования и схлопывания по высоте; появление и исчезновение — затуханием за `--motion-fast`; жесты работают без инерции. Проверить e2e с `reducedMotion: 'reduce'`.

**Готово, когда:** токены — единственный источник длительностей; переходы вглубь и назад, листы со смахиванием, нажатие, плашка, заглушки и обе части дел работают на 360 и 412 px с axe; e2e: «вглубь → назад», «смахнуть лист», «галочка → строка схлопнулась», «свайп влево → в корзину → Отменить», «свайп вправо → выполнено», «короткий свайп открывает кнопку», «свайп по строке не переключает вкладку», «ребёнок на общем деле — сторона „В корзину“ не открывается», «взрослый удалил чужое общее дело — плашка без „Отменить“», те же сценарии с `reducedMotion: 'reduce'`; снимки для сравнения — с отключёнными анимациями, axe — после `animation.finished`; модульные тесты порогов жестов; раздел «Движение» в контракте Studio; `pnpm check` и CI зелёные.

**Общие правила:** вымышленная семья; новых зависимостей не нужно (Motion отклонён в ADR-0045); коммиты `UI-8: …`; PR открыть, не сливать; к PR — скриншоты 360 и 412 px и короткая запись экрана перехода и свайпа; отчёт до 15 строк по шаблону `AGENTS.md`. Настоящие iPhone и Android — проверка владельца при выпуске.
