# Бриф R1a.6b. Сроки коммуналки в радаре и на «Сегодня»: экраны

- **Задача:** клиентская часть R1a.6 на готовом API (PR #38; [ADR-0033](../adr/0033-utility-deadlines.md), [контракт API](../utility-deadlines-api.md)) — **к окну показаний 20–25 ноября**. Радар (R0.8b), блок на «Сегодня», настройки уведомлений (R0.7b), экраны счетов и показаний (R1a.1b, R1a.5b) уже есть — расширять их. Исправления R1a.6c (PR #39) слиты: виды уведомлений по отдельности, окно счёта без счётчиков с подсказкой и отметкой `POST /api/deadlines/occurrences/:id/complete-readings` — см. контракт.
- **Требования:** UTIL-7 (карточка окна на «Сегодня»), UTIL-13, DEAD-3, DEAD-4, DEAD-5, NOTIF-3, NOTIF-4; PRD разделы 13 и 14; итог прототипа 0.5: в карточке окна название объекта идёт первым, статус («живём», «сдаётся») рядом — в тесте посторонний ошибся квартирой.
- **Ветка:** `feat/util-13-utility-radar-ui`, в своём worktree от свежего `main`. Сервер разработки — `PORT=8337`, `WEB_PORT=5199`.

## Сделать

1. **Пункты радара** по `sourceKind`: объект с названием и статусом первым, затем лицевой счёт или счётчик; основное действие из `primaryAction` — «Внести показания» (экран показаний объекта), «Отметить оплату» (с отменой), «Поверка проведена» (дата, следующая дата по умолчанию от интервала). Управляемые сроки не правятся и не удаляются из радара — вместо этого «Открыть счёт» или «Открыть счётчик».
1a. **Окно без счётчиков** (решение владельца 8 октября): пункт радара и карточка с подсказкой «Добавьте счётчики» (ведёт во вкладку «Счётчики») и кнопкой «Передано» (`complete-readings`).
2. **Карточка «Открыто окно показаний» на «Сегодня»** (UTIL-7): по объекту — название крупно, статус, «до 25 окт.», сколько счётчиков ещё без показаний, кнопка «Внести показания». На экране «Показания» «Другой объект» ведёт сначала к объектам с открытым окном.
3. **Настройки уведомлений:** виды «Открылось окно показаний», «Окно закрывается завтра», «Последний день окна», «Оплата через 3 дня», «Оплата сегодня», «Подходит срок поверки» отдельными переключателями; прежний общий «Сроки» не теряет выбор пользователя (как в ADR-0033).
4. **Push:** переход по `notificationKind` на нужный экран (окно показаний — экран показаний объекта).
5. **Догнать API PR #38 в готовых экранах:** «Поставщик скрыт» по `supplierHidden`; личная организация через id личного пространства из `/me`; корзина счетов — один `GET /api/accounts?trash=true`; режим «Всё · Общее · Личное» у организаций — через `scope`.
6. **Журналы и кэш:** ни названий, ни номеров счетов в консоли, адресах страниц, localStorage и кэше сервис-воркера.

## Готово, когда

- Playwright на 360 и 412 px с axe: радар с тремя видами коммунальных сроков и их действиями; карточка окна на «Сегодня» с двумя объектами («живём» и «сдаётся»); отметка оплаты с отменой; поверка; настройки видов уведомлений; без горизонтальной прокрутки, цели от 44 px; скриншоты — в `docs/screenshots/R1a.6b/` и в PR.
- Сквозной тест на вымышленной семье: ребёнок не видит коммунальные сроки объекта «Взрослые» ни в радаре, ни на «Сегодня».
- Тексты по PRD 13 («до 25 окт.», формы множественного числа: «2 счётчика без показаний»); `pnpm check` и CI проходят. Чего не хватает в API — сервер не менять, записать в отчёте.
