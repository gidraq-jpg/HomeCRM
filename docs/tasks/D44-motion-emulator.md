# Бриф D44. Анимации заново: боковой выезд и окна снизу, подбор в эмуляторе Android

- **Задача:** владелец 2 ноября 2026: анимация после D39 «всё равно плохая»; нравятся только выезд окна снизу (как у «+» на главной) и сдвиг при свайпе лент в «Делах» и «Покупках». Вернуть боковой выезд для перехода вглубь, всё добавление и выбор — окнами снизу. Подбирать вместе с владельцем в эмуляторе Android на вымышленных данных, без тестов на каждую итерацию; тесты — в конце, когда владелец одобрит. Исполнитель — Codex.
- **Требования:** UI-8 (движение интерфейса) и решения D39 — уточнить; WCAG 2.2 AA, `prefers-reduced-motion`.
- **Ветка:** `fix/ui-8-motion-side-sheet`, worktree `../HomeCRM-d44`, порты `PORT=8490`, `WEB_PORT=5350`, compose-проект `homecrm-test-fix-ui-9-motion-side-sheet` (своя база).
- **Область:** `docs/02-prd.md` (UI-8, сначала), `apps/web/src/shell/**`, `apps/web/src/ui/**` (Sheet и переходы), `apps/web/src/styles/motion.css`, точки открытия форм в экранах `apps/web/src/**` — только замена способа показа, без изменения логики; сценарий вымышленных данных `scripts/` или `apps/server/src/dev/`; тесты и снимки — на шаге 4.
- **Не трогать:** сервер (кроме сценария данных для разработки), миграции, `packages/shared/src/access.ts`, рабочее окружение `homecrm` и порты 8300/8301/8309, `E:\HomeCRM-data`.

## Что должно получиться (предложение ведущего, одобрено как основа)

**Боковой выезд — «открыть и вернуться».** Карточка (дело, объект, заметка, контакт, документ, счётчик) и разделы с главного (Дом, Документы, Контакты, «Входящие», Настройки): новый экран выезжает справа, прежний сдвигается влево примерно на 30% и слегка темнеет. Назад — стрелка, системная кнопка «назад» Android, свайп от левого края — обратное движение вправо.

**Окно снизу — «добавить, изменить, выбрать».** Меню «+», «Сказать ИИ», все формы создания и «Изменить» в карточке, выбор срока / ответственного / пространства, фильтры, черновики ИИ и «Изменить» у черновика (лист поверх листа), подтверждения «Удалить?». Закрытие — свайп вниз, «назад», нажатие на затемнение. Длинные формы — во весь экран, но тоже снизу.

**Оставить как есть:** сдвиг при свайпе лент в «Делах» и «Покупках»; вибрацию; «Анимации медленнее ×4».

**Убрать:** раскрытие окна из строки и значка (`clip-path`), предзагрузку по pointerdown ради раскрытия, затемнение и размытие при раскрытии — код, CSS и настройки, которые больше не нужны.

**Не решено владельцем — сделать переключателями** в «Настройки → Для проверки», чтобы владелец выбрал в эмуляторе:
1. Разделы с главного: сбоку (по умолчанию) или снизу.
2. Нижние вкладки: мгновенно (по умолчанию) или лёгкое затухание 150 мс.
3. Длинные формы: снизу во весь экран (по умолчанию) или сбоку как экран.

Движение плавное, без скачков строк и пустого кадра: целевой экран рисуется до начала выезда (данные из кэша или скелет), прежний остаётся видимым под ним. Одна кривая и длительности около 300–350 мс для бокового выезда и 280–320 мс для листа; подобрать в эмуляторе. `prefers-reduced-motion` — без сдвигов, короткое затухание.

## Как работать

1. **Стенд с вымышленными данными.** Сценарий `pnpm dev:demo` (или аналог, описать в `docs/runbook.md`): поднимает свою базу проекта `homecrm-test-fix-ui-9-motion-side-sheet`, применяет миграции, заполняет вымышленную семью (2 взрослых и ребёнок, дом с дачей, 3–4 объекта, по 10–20 дел, покупок, заметок, контактов, документов, счётчики с показаниями, несколько черновиков во «Входящих»), запускает сервер и клиент на `PORT=8490`, `WEB_PORT=5350` с доступом из эмулятора. Пароли вымышленных участников — сгенерированные, только в локальном файле стенда вне git (например `.demo/credentials.txt`, в `.gitignore`); в чат, PR и журналы не выводить. Данные — только вымышленные (AGENTS.md).
2. **Эмулятор.** Существующий AVD владельца (`Dnevnik_API_36` или `StrengthPlanner_API_36`; новый не создавать без нужды), Chrome в эмуляторе на `http://10.0.2.2:5350`. Если для входа или PWA нужен HTTPS или особый адрес — решить в пределах dev-сервера, без изменения рабочего окружения, и описать в runbook. Проверить, что системная кнопка «назад» и свайп от края работают.
3. **Итерации с владельцем.** Сделать движение по разделу выше, показать владельцу в эмуляторе, править по его словам. На этом шаге тесты не обязательны: коммиты в ветку, PR черновиком (draft) с пометкой «подбор с владельцем», CI может быть красным по e2e, сливать нельзя. После каждого круга — короткий список, что изменилось.
4. **Закрепление** — только после слов владельца «нравится, закрепляем»: убрать переключатели, оставив выбранные варианты (или оставить в «Для проверки», если владелец попросит); записать решение в PRD; обновить e2e, затронутые движением, на 360 и 412 px с axe; снимки в `docs/screenshots/d44/`; `pnpm check:changed` и CI зелёные; PR из черновика — в готовый.

**Общие правила:** `AGENTS.md` обязателен. Требование меняется сначала в PRD (на шаге 4 — окончательно). Новых зависимостей нет без обоснования в PR. Коммиты `UI-8: …`. **Служебный compose-файл, `.codex` и `.demo` в репозиторий не коммитить.** PR не сливать. Отчёт до 15 строк по шаблону `AGENTS.md` — в описании PR.
