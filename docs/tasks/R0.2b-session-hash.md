Задача: R0.2b Хэши токенов сессий и отзыв по id
Требования: AUTH-6 (список устройств, «Выйти на всех устройствах»), PRD раздел 13 (секреты не в открытом виде); бэклог — пункт «Отчёт R0.2» про токены сессий

Сейчас:
- токены сессий лежат в таблице `sessions` открытым текстом (cookie подписана `BETTER_AUTH_SECRET`, так что одной утечки таблицы мало, но это второй замок, а не первый);
- `list-sessions` отдаёт клиенту открытые токены всех сессий участника, а экран безопасности отзывает сессию по токену.

Готово, когда:
- в столбец `token` пишется `h1:<SHA-256 открытого токена в hex>`; поиск сессии по cookie идёт по хэшу; наружу (cookie, ответ входа) по-прежнему уходит открытое значение. Делается обёрткой адаптера Better Auth в `apps/server/src/auth/auth.ts`, без форка библиотеки;
- клиент нигде не получает токены других сессий: список устройств отдаёт id, устройство, время, признак «это устройство»; отзыв одной сессии — по id и только своей (чужой id → 404, без признака существования);
- работают: вход, выход, «выйти на других устройствах», смена пароля (отзыв остальных сессий), сброс пароля, вход по приглашению, повторная проверка (step-up), очистка просроченных сессий;
- старые открытые токены считаются недействительными (рабочего окружения ещё нет — миграция данных не нужна, без новых миграций базы);
- тесты: в таблице нет открытого токена; подмена cookie чужим хэшем не даёт входа; отзыв чужой сессии по id — 404; список устройств не содержит токенов; e2e экрана безопасности на 360 и 412 px с axe;
- закрытый пункт бэклога вычеркнут, в ADR-0005 (Better Auth) — абзац о хэшировании.

Область: `apps/server/src/auth`, `apps/web/src/auth/SecurityScreen.tsx`, их тесты и e2e; не трогать: `packages/db` (миграции, политики), `packages/shared/src/access.ts`, `apps/server/src/household` и `notes`, `deploy`, рабочий compose-проект `homecrm`, `E:\HomeCRM-data`.
