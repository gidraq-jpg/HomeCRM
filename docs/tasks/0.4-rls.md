# Бриф 0.4. Проверка RLS

- **Задача:** 0.4 из [плана](../03-dev-plan.md) — убедиться, что PostgreSQL сам не отдаёт чужое личное, даже если в коде забыт фильтр ([ADR-0004](../adr/0004-access-code-and-rls.md)).
- **Требования:** SPACE-3, SPACE-4, G4. Эталон правил — `packages/shared/src/access.ts`.
- **Ветка:** `spike/0.4-rls`, в своём worktree ([AGENTS.md](../../AGENTS.md), «Изоляция»).

## Сделать

1. **`packages/db`:** Drizzle и `pg`. Схема:
   - учётные записи — заглушка без входа, вход появится в 0.3;
   - пространства — личные и дом;
   - участники дома с ролью;
   - три таблицы-примера с общими полями доступа: заметки (личные и общие), покупки (ребёнок может писать), дела (с исполнителем).
2. **Роли базы:** `homecrm_owner` — владелец и миграции; `homecrm_app` — без `BYPASSRLS` и не владелец таблиц; `homecrm_worker`. На таблицах-примерах — `FORCE ROW LEVEL SECURITY`.
3. **Контекст:** помощник `withAccount(accountId, fn)` — транзакция с `set_config('app.account_id', id, true)`.
4. **Политики RLS** на чтение, вставку, изменение и удаление — по эталону `access.ts`.
5. **Матрица доступа:** тест перебирает роли × пространства × аудитории × операции и сравнивает ответ базы с `access.ts`. PostgreSQL 18 в Docker, своя база на каждый прогон; способ — отдельный compose-проект или Testcontainers, на выбор исполнителя, с обоснованием в отчёте.
6. **CI:** PostgreSQL 18 в `.github/workflows/ci.yml`, чтобы матрица шла на каждом запросе на слияние.

## Готово, когда

- Матрица проходит без расхождений. Если убрать одну политику, тест падает — проверено, записано в отчёте.
- Под `homecrm_app` без контекста не видна ни одна строка.
- Запрос без фильтра в коде всё равно не возвращает чужое личное.
- Выводы записаны в ADR-0004; `pnpm check` проходит.

## Не трогать

`apps/web`, `tools/access-probe`, рабочее окружение: compose-проект `homecrm`, порты 8300, 8301 и 8309.

Отчёт — по шаблону из `AGENTS.md`.
