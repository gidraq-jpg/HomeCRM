- **Задача:** R1c.3 и серверная часть R1c.4 из [плана](../03-dev-plan.md), одним PR, на модели дел из PR #49 ([контракт API](../api-tasks.md)). Экраны R1c.1–4 — следующей задачей. Исполнитель — Codex.
- **Требования:** TASK-3, TASK-4…7, TASK-9…11; PRD 7.3.4, 7.3.9, разделы 12 и 13; [ADR-0028](../adr/0028-deadline-engine.md), [ADR-0038](../adr/0038-tasks-quickline-api.md).
- **Ветка:** `feat/task-3-repeats`, в своём worktree от свежего `main`.

## Сделать

### R1c.3 Повторы

1. **Правила** (TASK-3): ежедневно, по дням недели, ежемесячно (число или последний день месяца), ежегодно, каждые N дней, через N дней после выполнения. Даты считаются в часовом поясе дома; 31-е и 29 февраля — по правилу «последний день месяца», как в ADR-0036.
2. **Серия:** у дела с повтором — серия и текущий экземпляр; выполнение создаёт следующий ровно один раз (повтор запроса и гонка двух устройств не дают двух экземпляров). Правка «только это» или «это и следующие»; удаление серии — в корзину.
3. **Политики просрочки:** перенести на следующий день, отметить «не сделано», оставить просроченным. Применяет обработчик фоновых задач раз в сутки после полуночи дома, идемпотентно; история фиксирует, что сделал обработчик.

### R1c.4 Сервер для экранов

4. **Ленты** (TASK-4…6): «Сегодня» — главное дело (одно, выбирается вручную), дела на сегодня и просроченные, открытые окна и срочное из радара; «План» — дни от сегодняшнего с курсором подгрузки, дела без даты отдельно, повтор — одной серией; «Все дела» — фильтры из PR #49. Один запрос на экран, без N+1.
5. **Отмена выполнения** (TASK-7): в течение 7 секунд по id события выполнения; отмена убирает и созданный следующий экземпляр серии; повтор нажатия не создаёт двойных записей.
6. **Назначение** (TASK-9, TASK-11): исполнитель при создании; если он не видит дело — `409` с предлагаемой аудиторией, повтор с подтверждением расширяет аудиторию по правилу 7.3.4 (ребёнку — только «Вся семья»); «Передать…» меняет исполнителя, история хранит, кто кому передал; уведомления новому исполнителю и автору при выполнении — через существующие push, без текста при «Скрывать текст на экране блокировки».
7. **«Взять в работу»** (TASK-10): пункт радара → дело только явным запросом, со связью с источником; повтор не создаёт второе дело.
8. **Ответственный** (TASK-11, 7.3.9): смена ответственного у объекта, документа и срока — через API с уведомлением новому ответственному; ответственный должен видеть запись.

### Для каждой новой сущности и поля (AGENTS.md)

9. RLS ENABLE + FORCE, двойник в `access.ts`, строки матрицы, история, корзина, перенос, поиск, экспорт; в журналах нет названий и текстов дел; `redactUrl` знает новые маршруты.

- Миграции безопасны для рабочей базы; ADR; контракт API в `docs/`; `pnpm check` и CI проходят.
