# Бриф D24. Подготовка ИИ: шлюз, речь, разбор, оценка качества

- **Задача:** первая задача R2 «Захват» — основа для голоса и фото, без пользовательских сценариев. Один PR, исполнитель — Codex. Начинать после слияния D23a (обе задачи меняют миграции).
- **Требования:** AI-1…AI-8 (PRD 16.1), [ADR-0043](../adr/0043-ai-gateway.md) — прочитать целиком; PRD 13; AGENTS «Безопасность и данные».
- **Ветка:** `feat/ai-1-gateway`, worktree `../HomeCRM-d24`, порты `PORT=8379`, `WEB_PORT=5241`.
- **Область:** `apps/server/src/ai/` (новый), регистрация заданий в `worker`, `packages/shared` (схемы черновиков), `packages/db` (одна миграция), настройки дома в `apps/web` (только переключатель и состояние), `deploy/compose.yaml` (переменные окружения и `extra_hosts`), `docs/runbook.md`. **Не трогать:** `access.ts` и политики RLS существующих таблиц, рабочее окружение, `E:\HomeCRM-data`.

## Что сделать

1. **Модуль `apps/server/src/ai/`** по ADR-0043: интерфейсы `SpeechToText` и `Extractor`, поставщики `local-stt`, `openai-compatible`, `fake`; выбор поставщика — переменными окружения, проверенными zod (`AI_STT_PROVIDER`, `AI_STT_URL`, `AI_EXTRACT_PROVIDER`, `AI_EXTRACT_URL`, `AI_EXTRACT_KEY_FILE`, `AI_EXTRACT_MODEL`, `AI_HTTPS_PROXY`, `AI_DAILY_LIMIT`). Без настроек ИИ выключен, приложение работает как раньше.
2. **`local-stt`:** клиент службы транскрибации (`GET /health`, `POST /transcribe`; формат запроса и ответа — по `E:\LifeOS_Codex_Project\experiments\transcribe_cpp_api.py`, только чтение, в репозиторий не копировать). Принимает `webm/ogg/m4a/wav` до 2 минут и 10 МБ; тайм-аут 60 с.
3. **`openai-compatible`** (вместо отдельного OAuth — дополнение ADR-0043 от 23 октября): разбор текста и изображения в черновик через OpenAI-совместимый `POST /v1/chat/completions` по адресу `AI_EXTRACT_URL` с ключом из файла `AI_EXTRACT_KEY_FILE`, модель `AI_EXTRACT_MODEL`.
   - Первая цель — API-сервер Hermes Agent на компьютере владельца (`http://host.docker.internal:8643/v1`, модель `hermes-agent`; за ним провайдер `openai-codex` по подписке ChatGPT). Тот же адаптер должен работать с `https://api.openai.com/v1` и ключом API.
   - Схема ответа: если сервер поддерживает `response_format: json_schema` — передавать её; в любом случае ответ ищется как JSON, проверяется zod, при неверной схеме — один повтор с сообщением об ошибке, затем «не удалось разобрать».
   - Изображения — как `image_url` с data-URI (JPEG, сжатие до 1600 px по длинной стороне на сервере).
   - **Отдельный экземпляр Hermes для HomeCRM** (решение владельца 23 октября, ADR-0043) — скрипт `deploy/scripts/hermes-ai.ps1`:
     - `-Install`: создаёт `HERMES_HOME` в `E:\HomeCRM-data\hermes`, конфиг экземпляра — все инструменты и наборы инструментов выключены, память, навыки, cron и сохранение разговоров выключены, API-сервер только на `127.0.0.1:8643`; генерирует `API_SERVER_KEY` прямо в файл секретов HomeCRM (значение не печатается); регистрирует задачу планировщика «HomeCRM Hermes» при входе в систему, как у службы речи LifeOS;
     - `-Login`: подсказывает владельцу команду входа `openai-codex` для этого `HERMES_HOME` (вход по коду устройства делает владелец сам);
     - `-Status`: `GET /health` экземпляра и признак, что вход выполнен, — без ключей;
     - личный Hermes владельца (`~/.hermes`, порт 8642) скрипт не трогает и не читает.
     - Исполнитель проверяет скрипт только на временном `HERMES_HOME` и временном порту и удаляет за собой; на настоящих путях скрипт запускает ведущий или владелец после слияния. Настройки Hermes сверить с официальной документацией (профили, API-сервер, наборы инструментов) и привести ссылки в PR.
   - Значения ключей не выводятся никогда — ни в журналы, ни в ошибки, ни в тесты. Исходящие запросы — через `AI_HTTPS_PROXY`, если задан. Тайм-аут 90 с, один повтор при сетевой ошибке.
   - Проверка доступности из контейнера: служба речи (9000) и Hermes HomeCRM (8643) слушают только `127.0.0.1` компьютера — убедиться, что `host.docker.internal` до них доходит в Docker Desktop; если нет — описать в отчёте и предложить решение, ничего на хосте не меняя.
4. **Схемы черновиков** в `packages/shared`: `TaskDraft` (название, дата, время, ответственный, объект — как в разборе быстрой строки TASK-2), `ShoppingDraft[]` (название, количество), `NoteDraft` (заголовок, текст). У каждого поля — признак уверенности. Схемы — общие для сервера и клиента.
5. **API** (только для участника, у которого ИИ включён в доме):
   - `POST /api/ai/transcribe` — multipart со звуком → `{ text }`; звук не сохраняется.
   - `POST /api/ai/extract` — `{ kind: 'task' | 'shopping' | 'note', text, spaceId }` → черновик; контекст для модели — только названия объектов и имена участников, которые этот человек видит.
   - `GET /api/ai/status` — включён ли ИИ, доступны ли речь и разбор, сколько осталось из дневного предела.
   - Длинные операции — через задания pg-boss в `worker` или синхронно с тайм-аутом; выбор описать в отчёте.
6. **Настройка дома** (миграция): `ai_enabled` (по умолчанию выключено) и счётчик дневного предела; переключатель — только у администратора в настройках дома, с пояснением, куда уходят данные (AI-3, AI-4). Состояние речи и разбора — в разделе состояния системы у администратора.
7. **Приватность:** вид черновика `document` и любые изображения с признаком паспорта или медицинского документа во внешнего поставщика не уходят (AI-4); журналы — только вид операции, поставщик, длительность, размер, код (AI-5). Тест, что журнал не содержит текста запроса и ответа.
8. **Оценка качества `pnpm ai:eval`** (AI-8): набор вымышленных образцов в `apps/server/src/ai/eval/samples/` (тексты фраз для дел и покупок; 3–5 коротких звуковых файлов, синтезированных или записанных с вымышленным текстом), запуск против выбранного поставщика; отчёт — точность по полям и время, без содержимого. Параметр `--samples <папка>` для настоящих образцов вне репозитория.
9. **Compose и runbook:** переменные в `deploy/compose.yaml` для `app` и `worker`, `extra_hosts: host.docker.internal:host-gateway`; раздел runbook «ИИ»: установка экземпляра Hermes (`hermes-ai.ps1 -Install`, `-Login`, `-Status`), как проверить `/api/ai/status`, что делать, если служба речи не отвечает.

**Готово, когда:** модульные тесты на поставщиков с поддельными HTTP-серверами (успех, тайм-аут, неверная схема ответа, отказ авторизации без утечки ключа, отказ при выключенном ИИ, запрет документов); матрица доступа для новой настройки; `pnpm ai:eval` проходит на `fake`; e2e переключателя ИИ на 360 и 412 px с axe; `pnpm check` и CI проходят без обращений во внешние службы.

**Общие правила:** вымышленная семья; секреты не выводить; новая зависимость — только с обоснованием в PR (предпочтительно `fetch` Node без SDK); коммиты `AI-1: …`; PR открыть, не сливать; отчёт — до 15 строк по шаблону `AGENTS.md`.
