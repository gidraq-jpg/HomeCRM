# Клиент дел R1c.4b и исправления R1c.4c

PR #51 продолжен от `00547b5` в отдельном worktree, ветка `fix/task-4-review`. Все прежние коммиты, согласованные фиксации Date и общий лимит CI сохранены. R1c.4c закрывает B1–B4 и A1–A5 точечными изменениями API и клиента, миграцией 0060. Общая модель доступа, зависимости, рабочее окружение и новые модули не менялись. Требования: TASK-1…11, SPACE-7 в пределах обоих брифов.

| Адрес | Экран |
|---|---|
| `#/today` | Сегодня, главное, выполненное, окна показаний и срочное |
| `#/today/plan` | План с подгрузкой и блоком без даты |
| `#/today/all` | Все дела, фильтры и страницы по 50 записей |
| `#/today/new` | Создание |
| `#/today/tasks/:id` | Карточка, правка, файлы, связи, история и действия серии |
| `#/open/:id` | Открытие из уведомления, включая отложенный переход после входа |

Выбранный дом передаётся идентификатором `householdId` между вкладками и созданием. Список `/tasks` не принимает этот параметр: клиент фильтрует полученные страницы по дому и сохраняет подгрузку; старые личные дела без привязки к дому остаются доступны. Карточки лент не загружаются отдельными запросами. Служебные блоки и справочники независимы.

Повторы, преемников и просрочку вычисляет сервер. Клиент отправляет `repeatScope`, полный чек-лист с прежними UUID и `expectedUpdatedAt`. При конфликте черновик сохраняется, а текущая версия показывается для сравнения. Скрытый адресат ожидания не пересылается как намеренное удаление. Назначение с `suggestedPlacement` подтверждается отдельно; отказ сохраняет форму. При подтверждении меняется тело и ключ, при транспортном повторе неизменённого действия — прежний ключ.

Окно отмены рассчитывается по `doneAt`, HTTP `Date` и монотонным часам с поправкой на транспорт и секундную точность заголовка. Решение об отмене всегда принимает сервер. Действие «Возобновить» отделено от отмены. Клиент показывает точную серверную причину `UNDO_EXPIRED`, `COMPLETION_CHANGED` или `NEXT_TASK_CHANGED`; неизвестный конфликт сохраняет общее сообщение. Подтверждённая мутация освобождает кнопку до фонового refetch, отменяет старые GET и сохраняет действие отмены при исчезновении строки.

После изменений дел, сроков, начислений, объектов, документов и счётчиков обновляется агрегат «Сегодня». Тексты не сохраняются в URL, localStorage, Cache API или журналах. Ключи запросов содержат участника, дом и фильтры; смена `me.id` синхронно размонтирует пользовательское дерево вместе с локальным состоянием и тостами; поздние ответы прежней сессии блокируются. Повторный `/me` того же участника сохраняет черновик.

## Исправления R1c.4c и доказательства

API-исправления и основные сквозные сценарии проверяются настоящим API с отдельным PostgreSQL и вымышленными участниками. Только неизвестный общий CONFLICT в дополнительном клиентском тесте задаётся контролируемым HTTP-отказом; три точные причины отмены проверены настоящим сервером. `tasks-review.e2e.ts` дополняет прежние `tasks.e2e.ts`, не ослабляя сценарии серий, отмены, приватности и экспорта.

| Пункт | Исправление и проверяемый результат |
|---|---|
| B1 | Ключ границы приложения — `me.id`, поздние мутации проверяют актуальную сессию. Соседняя вкладка меняет A → B без logout: форма, чипы, подтверждение и undo исчезают; поздний POST A не открывает карточку/тост B. Повторный refetch A сохраняет форму. |
| B2 | Блокируется только отправка мутации; GET обновляется в фоне. Задержанный refetch списка/карточки не мешает одному `/undo`, статус возвращается в open, преемник убирается. Отказ после перехода в другую ленту остаётся в тосте; двойной клик даёт один запрос. |
| B3 | Сужение доступа показывает имена действующих участников дома записи, блокирует подтверждение до загрузки состава, поясняет изменение серии. Отказ ничего не меняет; ребёнку-исполнителю нельзя выбрать «Взрослые». |
| B4 | Объект, документ и ручной срок H2 получают участников H2. После успешной передачи подтверждённое значение обновляется, поле блокируется на время отправки; несовместимые участники H1 не появляются. |
| A1 | PATCH привязывает старое личное дело без дома вместе с датой/ожиданием атомарно. API проверяет план, срок, ожидание, версию, идемпотентность и запрет смены привязанного дома. UI сохраняет черновик после HOUSE_REQUIRED и повторяет правку плана, крайнего срока и ожидания с выбранным домом успешно. |
| A2 | Производный видимый срок возвращает EDIT_SOURCE до UPDATE-блокировки; скрытый/удалённый — 404, читающий без прав ручного срока — 403. Сквозные ссылки ведут к делу, документу и коммунальному источнику. |
| A3 | Миграция 0060 различает три причины отказа; атомарность и связь события с преемником сохранены. API проверяет 6/8 секунд, другое событие, идемпотентность, изменённого преемника, PATCH/status open/waiting и возобновление после окна. UI показывает NEXT_TASK_CHANGED после ухода строки, UNDO_EXPIRED и COMPLETION_CHANGED на настоящих отказах. Обновление 0059 → 0060 не меняет строки, историю, сроки, очередь, RLS и права функции. |
| A4 | Обязательный hasOtherContributions учитывает чек-лист и вложения, включая удалённые; сервер повторяет проверку при переносе. Автор без чужого вклада переносит общее дело в личное, теряющие доступ перечислены; чужая отметка/файл и вклад между чтением и переносом блокируют действие. Администраторское личное не раскрывается. |
| A5 | Today/plan отдают проверенные householdId/timeZone; быстрый ввод, формы и радар используют контекст выбранного дома. API фиксирует момент 10:30 UTC для Los Angeles/Kiritimati: местные даты различаются; чужой/ушедший участник получает 404. UI переключает дома туда-обратно, очищает чипы/назначение, сохраняет завтра 10:00 в H2. |

B1 и B2 сначала упали на исходных компонентах `00547b5`: текст A сохранялся, undo не отправлялся/кнопка оставалась заблокирована. B3/B4 также проверены на исходных клиентских компонентах: отсутствовали имена теряющих доступ и участник второго дома. После исправлений те же сценарии проходят. Прочие долги, включая N1, в эту задачу не включены.

Первый CI исправлений подтвердил 1576/1576 и матрицу 104652/104652; e2e — 415/417. Два отказа в существующей регрессии A → B (`deadlines.e2e.ts:542`) ожидали сохранения выбранного A режима радара «Весь дом». B1 намеренно сбрасывает его в «Моё». Тест теперь дополнительно проверяет сброс и явно выбирает «Весь дом» уже для B; прежние проверки скрытых записей и числа доступных сроков сохранены. Это уточнение регрессии границы сессии B1, остальные сценарии сроков и их тайм-ауты не менялись.

Повторный pre-push остановился на двух deadlock `40P01` матрицы доступа при удалении документов/вложений (1570 успешно, 4 пропуска, 2 отказа). Отдельная диагностика в случайной тестовой базе воспроизвела одинаковый цикл блокировок на 0059 и 0060: изменение вложения ждёт родительский документ в `app.file_lifecycle`, изменение документа ждёт вложение. Каталог определений, владельцев, прав и настроек безопасности функций вне модуля дел совпал до и после 0060. Это унаследованный долг, не исправляемый в R1c.4c; проверки матрицы, SQL жизненного цикла файлов, число воркеров и тайм-ауты не менялись. Повторная отправка проходит через полный штатный hook; её результат и CI окончательного HEAD фиксируются в PR.

Целевые сценарии работают с настоящим сервером и PostgreSQL: отдельная случайная база на сценарий, вымышленная семья, свободные порты, временный ключ файлов. Для окна отмены тест меняет возраст сохранённого события в своей базе вместо ожидания по часам браузера. Проверяется содержимое кэшированных ответов и консоль, включая смену участника и скрытые связи.

Linux-окружение: `apps/web/e2e/tasks-review/compose.yaml`, проект `homecrm-test-task-4-review`, PostgreSQL 18, официальный Playwright 1.63.0, Node 24 и pnpm 12.9.1. Для нового окружения используется существующий `apps/web/e2e/Dockerfile`.

### Календарный блокер штатной проверки

11 октября 2026 штатный pre-push `pnpm check` подтвердил кодировку, линтер и типы; из 1565 тестов прошли 1557, пропущены 4, отказали 4. Отправка остановлена hook. Все четыре отказа в неизменённых относительно `origin/main` серверных тестах:

- `contacts/import-birthdays.test.ts`: строки 200, 239 и 316 ожидают событие дня рождения 10 октября 2026, но получают `undefined` или пустой список.
- `deadlines/radar.perf.test.ts`: строка 172 ожидает 1000 дней рождения 10 октября 2026, но получает 0; до измерения порога скорости тест не доходит.

Маршрут `deadlines/routes.ts` фильтрует прошедшие дни рождения через `x.endsAt >= new Date()`. Тесты задавали дату расчёта движку, но не текущий `Date` маршрута. Владелец разрешил точное исключение из брифа: `Date` зафиксирован только в этих четырёх тестах, `afterEach` восстанавливает часы даже после отказа. API, SQL, `performance.now` и пороги не менялись. Отказ и доказательства переданы ведущему; остальные серверные файлы не затронуты.
