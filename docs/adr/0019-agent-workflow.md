# ADR-0019. Как работают агенты

- **Статус:** принято, 5 октября 2026. Заменяет правило «код пишет один агент за раз» из первой версии плана
- **Связано:** план, разделы 3 и 6; `AGENTS.md`, раздел «Как идёт работа»

## Контекст

Код HomeCRM пишут ИИ-агенты, а владелец тратит на проект около часа в день. Из LifeOS пришло правило «код пишет один агент за раз»: параллельные агенты затирали правки друг друга.

Опыт другой команды агентов добавил ещё пять источников потерь:

- долгоживущий агент перечитывает контекст в сотни тысяч токенов каждым ходом — это главная статья расходов;
- агенты без изоляции стирают друг другу тестовые данные и откатывают чужие правки;
- если коммитит только ведущий, каждая правка делает лишний круг;
- ревью без ограничений порождают новые ревью, и выпуск ждёт;
- полные визуальные прогоны на машине владельца мешают работе, а длинные отчёты не читаются.

## Решение

1. **Одна задача — один свежий агент.** Агент получает бриф, делает задачу, отчитывается и завершается. Память проекта — в репозитории, а не в переписке.
2. **Изоляция.** У каждого исполнителя свой `git worktree` и своя ветка. Тесты не занимают постоянных портов, база — своя на каждый прогон. Рабочее окружение агенты не трогают. Изоляция снимает причину правила из LifeOS, поэтому параллельно можно вести до двух задач в непересекающихся областях. Миграции базы и правила доступа — по одной задаче за раз.
3. **Исполнитель коммитит сам,** ведущий только сливает и ставит метки версий.
4. **Одно ревью на изменение.** Исправляются только блокеры (список — в `AGENTS.md`), остальное уходит в бэклог. После исправления ведущий проверяет только блокеры.
5. **Тесты по затронутому.**
   - Локально — затронутые тесты и экраны.
   - Матрица доступа и интеграционные тесты — в CI на каждом запросе на слияние.
   - Полный визуальный прогон — ночью в CI и перед выпуском; на компьютере владельца — никогда.
6. **Отчёт до 15 строк:** сделано, файлы, проверки с цифрами, риски, что нужно от владельца.

## Последствия

- Таблица хода работ в плане (раздел 10) становится обязательной: по ней свежий агент понимает, где проект.
- Ночной прогон расходует минуты CI: около 10–15 минут за ночь, 300–450 минут в месяц из 2000 бесплатных. Сценарий появится вместе с первыми сквозными тестами в R0.
- Матрица доступа не переносится в ночной прогон: она дешёвая, а утечка личного — худшая ошибка продукта.
- Бэклог ведёт только ведущий, поэтому в нём не бывает конфликтов слияния.

## Отклонённые варианты

- **Один исполнитель за раз без изоляции** — медленнее, а причину правила изоляция уже убирает.
- **Ревью до чистого результата** — бесконечные круги; качество держат проверки и матрица доступа.
- **Полный прогон на каждом изменении** — дорого по минутам CI и по времени ожидания.
