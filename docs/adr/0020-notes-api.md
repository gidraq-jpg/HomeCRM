# ADR-0020. Заметки, перенос и история вклада

- **Статус:** принято; 6 октября 2026
- **Связано:** R0.4a, NOTE-1…3, SPACE-7, PRD 7.3.3, 5–8, 11, 13; ADR-0004

## Решение

Заголовок и исходный текст заметки хранятся отдельно. Формат текста — Markdown: абзацы, заголовки, списки, выделение, ссылки. Это переносимый текст, не HTML и не структура конкретного редактора. Будущий клиент обязан отключить сырой HTML и проверять протоколы ссылок; сохранение исходника API не делает его безопасным HTML. Обязателен только непустой заголовок: до 200 символов, текст — до 100 000, чек-лист — до 200 пунктов. Чек-лист хранится в существующей дочерней таблице `note_items`, с порядком и отметкой выполнения. Закрепление относится к записи и доступно тем, кто может её править.

Сгенерированная колонка `search_text` содержит заголовок и Markdown. Поисковый запрос, ранжирование, индекс и объединение с другими сущностями появятся в R0.5. Файлы, связи и теги — отдельные сущности будущих модулей, связанные с id заметки: массивы фиктивных файлов или непроверенные id в заметку не добавляются. Формат заметки не мешает добавить такие дочерние таблицы через `attach_record_table`.

Контекст создания из карточки определяет пространство и максимально допустимую аудиторию. Пока в тестах и API объектом-примером служит `tasks`: его строка читается и блокируется под RLS. Это контекст создания, а не постоянная связь; API связей и настоящих объектов будет добавлен вместе с их модулями. Чек-лист — постоянные дочерние записи, его пространство и аудитория обеспечиваются внешними ключами и каскадом базы.

`canMove` отличает перенос от обычной правки. Поделиться может владелец личного, сделать личной — автор общего без чужого вклада. Перенос между домами или между личными владельцами запрещён; для этого нужна копия. Копировать может любой читатель, в том числе ребёнок. Новые id и автор у копии, история и удалённые пункты не копируются. Аудиторию меняет взрослый; ответственный-ребёнок препятствует сужению до «Взрослых» благодаря внешнему ключу.

У каждой записи есть защищённый признак `has_other_contributions`: необратимый итог событий истории с актором, отличным от автора. При вставке база сбрасывает его, обычный UPDATE не позволяет его сбросить или подделать. Чужой вклад в чек-лист отмечает и родительскую заметку, даже если пункт потом удалили или перепривязали. Служебные поля не попадают в историю и ответы API. События системы без актора не считаются чужим вкладом. Старые данные получают признак из истории в новой миграции: только на время её транзакции снимается FORCE и отключаются триггеры нормализации, истории и защиты, после заполнения они возвращаются. Содержимое, ответственные, даты и история существующих записей сохраняются; обновление с данными проверяется отдельно.

Так не нужно давать участнику доступ к старым событиям, скрытым прежней аудиторией или пространством, чтобы проверить возможность переноса. Проверка в коде использует этот итог и дочерние записи; проверка SQL — триггером, поскольку обычная политика UPDATE не имеет одновременно OLD и NEW. RLS по-прежнему проверяет оба места. Функции выполняются с правами вызывающего; `SECURITY DEFINER` не используется. Блокировка родителя сериализует изменение пункта с переносом; редкие взаимные блокировки прямого SQL откатывают одну транзакцию, API возвращает конфликт.

Предпросмотр сужения сначала читает заметку под `homecrm_app` и проверяет право действия. Только затем служба входа читает публичное имя и действующее членство **этого дома** для списка теряющих доступ: эта роль уже обслуживает состав дома (ADR-0005), но не имеет прав на заметки и тексты. Чужое личное, количество чужих записей и события не читаются и не возвращаются. Полноценный каталог участников остаётся задачей R0.9. Перенос в личное и сужение аудитории требуют подтверждения API.

Корзина — 30 дней, дату ставит база. Удалённое не правят и не копируют; восстановление — по `canRestore`. Удалённые пункты сохраняются при переносе родителя, со своей датой. Личный экспорт содержит всё своё личное, включая корзину, Markdown и чек-лист; общий — записи администрируемого дома, прошедшие RLS, без чужого личного. Полный ZIP с файлами и версия формата — R0.10. Существующий JSON-экспорт уже включает содержимое заметок.

## Последствия

API и SQL проверяются отдельно, матрица сравнена с `access.ts`. Сбой базы не пишет исключение Drizzle: оно содержит параметры запроса. В журнале остаются английское сообщение и SQLSTATE, без заголовка, текста и технического запроса; параметры URL заметок также удаляются.

UI, полноценный поиск, файлы, связи, теги и офлайн-синхронизация не входят в R0.4a. Новых зависимостей нет. Опциональный `expectedUpdatedAt` даёт клиенту возможность обнаружить устаревшую правку; протокол офлайн-конфликтов уточняется в R0.8.
