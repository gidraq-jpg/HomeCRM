# ADR-0038. Дела, производные сроки и быстрая строка

- **Статус:** принято для реализации R1c.1–2; 10 октября 2026
- **Связано:** TASK-1, TASK-2, TASK-8; ADR-0028, ADR-0024, ADR-0030

## Контекст

В базе уже есть минимальная таблица `tasks`. Нужны полноценное дело, ожидание ответа и разбор русской строки для будущего клиента. Рабочие записи и прежняя история должны сохраниться; правила личного пространства и аудитории остаются общими для всех модулей.

## Решение

Расширяем существующую таблицу: описание, календарные даты плана и крайнего срока, необязательное время, пять статусов, чек-лист в JSON с UUID пунктов и порядком, ссылка ожидания и дата проверки. Чек-лист меняется атомарно вместе с делом; отдельная сущность для его пунктов не нужна. Прежние `due_at` и `done_at` сохраняются. Старый ненулевой `done_at` превращается в статус `done` без изменения прежних полей и истории.

Связи используют `record_links`; файлы — `task_files`, существующее шифрование, реестр блоков, корзину и каскад пространства. Для таблиц и истории включены ENABLE и FORCE RLS. Ребёнок меняет назначенные ему дела и файлы с тем же ответственным; сервер загрузки назначает файлу исполнителя дела. Имя и описание дела попадают в поисковый индекс; файлы экспортируются вместе с метаданными и оригиналом, отдельного поискового индекса файлов не создаём.

У дела до трёх производных правил `deadlines`: `task_plan`, `task_due`, `task_waiting`, уникальных по делу и виду. Календарная дата и время разворачиваются существующим движком в поясе дома. Без точного времени предупреждение приходит в 09:00; с ним — в указанное время. Правила создаёт только триггер дела. Прямые записи приложения запрещены; закрытый каскад передаёт пространство и ответственного, worker получает лишь технические колонки, без названия и описания. Закрытие дела или корзина выключают правила, открытие или восстановление снова включает их. Сроки не имеют независимой выполненности: источник истины — статус дела.

Доставка повторно проверяет текущий доступ. Настройка скрытия текста использует существующий общий текст push. Скрытый контакт или участник ожидания возвращается как `null`; UUID не попадает в историю и экспорт другого пространства. Неявный `null` скрытой ссылки при обычной правке сохраняет ссылку. Новые связи проверяются под RLS.

Создание, правка и смена статуса используют существующий журнал идемпотентности: ключ, хеш запроса и UUID результата, без пользовательского текста. Блокировка ключа предшествует блокировке дела. При повторе возвращается текущее доступное состояние; несовпадающий запрос с тем же ключом получает 409. Повторная установка текущего статуса не добавляет историю.

`parseQuickline` — чистая функция общего пакета. Дата, пояс, списки участников и объектов передаются явно. Позиции фрагментов — UTF-16 исходной строки, диапазон `[start,end)`. Неоднозначные имена, неверные даты и неизвестные метки остаются в названии; «в 5» означает 05:00, дата без года в прошлом — следующий год. Для каждого вида берётся один фрагмент; повторные указания остаются видимыми в названии. Корпус из 127 фраз фиксирует контракт.

## Последствия

Контракт готов для отдельного клиента R1c.4. Повторов и исполнения TASK-7 пока нет; закрытые статусы различаются явно, сохраняя основу для следующих задач. Миграции выполняются общей транзакцией; временное отключение триггеров и RLS касается только backfill прежних дел и заканчивается ENABLE + FORCE. Тест обновления сравнивает все прежние поля, проверяет корзину, старые UUID и индекс; старые тесты миграций исключают только добавленные колонки. Общая матрица и замеры радара проверяют расширение без рабочего окружения.

## Отклонённые варианты

- Новая таблица вместо `tasks`: потребовала бы переносить UUID и историю.
- Ручные правила сроков для дел: позволили бы расходиться статусу и напоминаниям.
- Разбор на сервере или с ИИ: добавил бы задержку и зависимость от сети.
