# ADR-0033. Коммунальные источники общего движка сроков

- **Статус:** принято для реализации R1a.6; 8 октября 2026.
- **Связано:** UTIL-13, DEAD-2/4/5/6, NOTIF-2/3, ADR-0028, ADR-0029, ADR-0031, ADR-0032.

## Источники и жизненный цикл

Используется существующий движок, таблицы наступлений и диспетчер. У `deadlines` добавлены `source_kind` (`record`, `readings`, `payment`, `verification`) и FK на счёт или счётчик с каскадной окончательной очисткой. `object_id` остаётся родительским объектом и границей RLS. Пара «источник — вид» уникальна. Название, статус недвижимости и реквизиты счёта читаются под RLS в одном запросе радара.

Триггеры счетов и приборов вызывают закрытый от прямого исполнения помощник с правами вызывающего. Помощник доступен приложению, но вне триггера отклоняет вызов; защитный триггер срока также запрещает прямое создание или изменение управляемого правила. Служебные настройки контекста сами по себе права не дают: требуется вложенный триггер. Изменения календаря, самостоятельная корзина и восстановление пересчитывают правило; перенос, аудитория и ответственность следуют объекту. Автор счёта или счётчика не подменяет ответственного объекта. В личном используется выбранный ранее дом или первый по UUID действующий дом автора; без дома и ранее рассчитанного пояса срок не создаётся до следующей правки источника с доступным домом.

Миграции 0032–0034 идут после 0031. 0032 закрывает выбранные замечания PR #35. 0033 добавляет производные поля, FK, ограниченные политики, триггеры и первоначальные правила для существующих источников. Для первоначального заполнения политика владельца действует только в транзакции миграции и удаляется до её фиксации. Пользовательские записи, даты и история при заполнении не обновляются. 0034 расширяет CHECK допустимых видов уведомлений, сохраняя прежние настройки.

## Закрытие и действия

Окно проверяется непосредственно при чтении радара, постановке предупреждения и перед сетевой отправкой. SQL-функция очереди и диспетчера исполняется с правами вызывающего; радар применяет те же условия к материализованным видимым наборам, чтобы не повторять планы RLS на каждое окно: у каждого живого активного прибора счёта должно быть живое переданное показание с календарной датой внутри включительного окна в поясе дома. При отсутствии активных приборов окно закрыто. Корзина показания или новый активный прибор снова открывает окно; отдельно сохранённой отметки выполнения нет. `automatic` и `not_required` выключают правило окна.

Worker получает SELECT только на дополнительные служебные поля: ссылку прибора на счёт, вычисляемый `is_active`, дату показания и момент передачи. Дополнительные политики чтения ограничены деревом объектов с коммунальными сроками. Значения показаний, комментарии, `data`, названия и номера ему недоступны. Приложение использует прежний RLS. Вычисляемый `is_active` исключён из истории, проверки вклада и экспорта.

Оплата пока отмечается вручную на наступлении; повторная отметка сохраняет первое время, отмена снимает её. UPDATE разрешён только для `completed_at` платежа с доступным живым объектом; защитный триггер не допускает изменения календарных полей. Worker по-прежнему не имеет UPDATE `completed_at`. Поверка проводится через отдельное действие с новой `verifiedOn`: следующая дата пересчитывается календарно или явно задаётся владельцем записи.

## Предупреждения

Общий формат DEAD-1 расширен необязательными `warningTime` и `endWarnings` (дни до конца окна). Старые правила сохраняют прежнюю семантику. Коммунальные умолчания: 09:00 дома, открытие окна и за 1/0 дней до его конца; оплата за 3/0 дней; поверка за 60/30/7 дней. Пустой прежний `warnings` в счёте трактуется как отсутствие настройки и получает коммунальное умолчание. `endWarnings: []` выключает предупреждения конца; у прибора `verificationWarnings: []` выключает предупреждения поверки. Остальные значения настраиваются теми же полями правил и `verificationWarningTime`.

Диспетчер использует прежние тихие часы, бюджет, защиту от дублей и скрытие текста. Добавлены виды `readings_open`, `readings_closing`, `readings_last_day`, `payment_upcoming`, `payment_due`, `verification`. Прежний `deadline` совместимо включает всю группу сроков; для отдельного выбора API принимает список конкретных видов без `deadline`. В push сохраняются `kind: deadline` и `recordId` объекта для существующего клиента, добавляется `notificationKind`. При скрытии текста остаётся «В HomeCRM есть новое»; иначе сообщается только вид события, без названий и номеров.

Поиск новых текстов не получает. ZIP версии 1 сохраняет ссылки управляемого правила и ручные отметки выполнения; производные даты восстанавливаются движком. Новых зависимостей нет. Клиентские экраны, выпуск, рабочая база и реальная Web Push доставка на устройствах в эту задачу не входят.
