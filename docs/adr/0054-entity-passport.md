# ADR-0054: Паспорт сущности

Статус: принято (D53f, 23 ноября 2026)

## Контекст

`AGENTS.md` требует: новая сущность с пользовательскими данными появляется только вместе с полями
доступа, политикой RLS, строками матрицы доступа, решением о поиске, экспортом и поведением
корзины. До D53f это держалось на внимательности исполнителя и ревьюера. Таблицы описаны в десяти
файлах схемы, матрицы — в двух десятках тестов, экспорт — в коде сервера. Пропуск одного пункта
не ронял ни одну проверку.

## Решение

1. **Реестр `packages/db/src/entities.ts`.** Для каждой таблицы с пользовательскими данными —
   паспорт: модель доступа (свои поля, «наследует от родителя» или особое правило со ссылкой),
   политика чтения RLS, файл матрицы, поиск, раздел архива экспорта, корзина. Таблицы без
   пользовательских данных — вход, очереди, журналы операций, производные индексы — перечислены
   в `SERVICE_TABLES` с пояснением.
2. **Явные исключения.** «Не ищется», «не выгружается» и «без корзины» записываются как
   `{ no, ref }`: причина и ссылка на требование PRD или ADR. Пробел без записанного решения —
   `{ gap }`; такие пробелы перечислены в тесте поимённо, чтобы новый не появился незаметно.
3. **Тест полноты `entities.test.ts`** на свежей базе после всех миграций проверяет:
   - каждая таблица базы, включая служебные схемы, есть в реестре или в служебном списке —
     иначе «таблица X добавлена без паспорта»;
   - для паспорта: колонки доступа существуют, RLS включён с FORCE, названная политика есть;
   - файл матрицы существует и упоминает таблицу; записи общего механизма `recordTable`
     покрывает `access-matrix.test.ts` через `RECORD_TABLES`;
   - «индексируется» — у таблицы есть триггер `app.sync_search_entry`, «не ищется» — его нет;
   - «выгружается» — раздел есть в `ExportRecords`, таблица встречается в
     `apps/server/src/export/archive.ts` (история — в `HISTORY_TABLES`); «не выгружается» —
     не встречается;
   - корзина «мягкое удаление» — есть `deleted_at`, «вместе с родителем» — есть внешний ключ;
   - каждая ссылка `ref` существует в PRD или в `docs/adr`.

   Тест самого теста создаёт во временной транзакции таблицы без паспорта и снимает FORCE RLS
   и триггер поиска с `notes` — проверка обязана их найти.
4. В `AGENTS.md` перечень шести пунктов заменён правилом: «добавьте запись в `entities.ts`;
   тест полноты проверит остальное».

## Дополнение от 24 ноября 2026 (D57)

Два пробела, найденные реестром, закрыты решением владельца; открытых `{ gap }` в реестре нет.

- История «Входящих» (`inbox_items_history`, `inbox_files_history`) входит в `HISTORY_TABLES`
  архива с теми же правилами области, что и остальные истории; «Входящие» только личные, поэтому
  в архив дома они не попадают.
- Явно «не ищутся»: аккаунты и профили (людей в семье немного, они видны в списке участников,
  внешние люди ищутся через «Контакты»), пространства и участники (их единицы, их выбирают),
  настройки уведомлений (нечего искать), связи записей (видны из найденной записи).

Механизм `{ gap }` остаётся для будущих пробелов; тест `открытые пробелы перечислены явно`
ожидает пустой список.

## Последствия

- Новая таблица без паспорта роняет CI. Закрытие пробела тоже роняет тест: исключение
  приходится убрать, и реестр не устаревает.
- Тест читает код архива сервера как текст. Если архив изменится без изменений в
  `packages/db`, выборочный `pnpm test:changed` тест не запустит; его поймает полный прогон CI.
- Проверка поиска и экспорта — по наличию, а не по содержанию: что именно попадает в индекс
  и архив, по-прежнему проверяют тесты модулей.
