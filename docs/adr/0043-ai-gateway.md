# ADR-0043. Шлюз ИИ: речь на своём компьютере, разбор через OpenAI

- **Статус:** предложено; 23 октября 2026
- **Связано:** PRD 16.1 (AI-1…AI-8), R2 «Захват», [идеи R2](../04-ai-capture-ideas.md), ADR-0006 (pg-boss), ADR-0010 (файлы), ADR-0021

## Контекст

Владелец решил 23 октября 2026: распознавание речи — на своём компьютере, где уже работает служба транскрибации LifeOS (GigaAM v3 через transcribe.cpp, Vulkan, `http://127.0.0.1:9000`: `GET /health`, `POST /transcribe`); разбор текста и фото в черновики — пробуем через OpenAI со входом по OAuth (учётная запись ChatGPT), а не по ключу API.

Ограничения: из России OpenAI напрямую недоступен; рабочее окружение сейчас на компьютере владельца и позже переедет на VPS (план, 7.4); данные семьи личные (PRD 7, 13).

## Решение

1. **Модуль `apps/server/src/ai/`** — единственное место обращения к ИИ. Два вида поставщиков за интерфейсами:
   - `SpeechToText.transcribe(audio, { lang: 'ru' }) → { text, durationMs }`;
   - `Extractor.extract({ kind, text?, image?, context }) → Draft` — разбор в черновик по строгой zod-схеме вида (`task`, `shopping`, `note`, позже `reading`, `charge`, `document`).
2. **Поставщики:**
   - `local-stt` — служба транскрибации по адресу из `AI_STT_URL` (из контейнера — `http://host.docker.internal:9000`); после переезда на VPS — через туннель до компьютера или локальная копия модели на VPS (отдельное решение);
   - `openai-compatible` — любой сервер с OpenAI-совместимым `POST /v1/chat/completions`: адрес `AI_EXTRACT_URL`, ключ из файла секретов (читается во время работы, не логируется). Первая цель (решение владельца 23 октября 2026, дополнение) — **API-сервер Hermes Agent** на компьютере (`127.0.0.1:8642`, из контейнера — `host.docker.internal:8642`), у которого за спиной провайдер `openai-codex`: вход по ChatGPT OAuth и подписка ChatGPT — путь, который Hermes поддерживает официально. Тот же адаптер без изменений работает с ключом API OpenAI (запасной вариант, оплата по токенам), YandexGPT/GigaChat через совместимые шлюзы и локальной моделью (llama.cpp, Ollama);
   - для Hermes обязательно: отдельный профиль **без инструментов** (никаких файлов, терминала, сети и памяти) — иначе текст с фотографии может стать командой агенту; ответ всё равно проверяется zod-схемой;
   - `codex-exec` (позже, если Hermes не подойдёт) — `codex exec` с `--output-schema` и картинками в режиме только чтения, тоже по подписке ChatGPT; работает на компьютере, где выполнен вход в Codex CLI;
   - `fake` — детерминированный поставщик для тестов и CI; CI никогда не ходит во внешние службы.
3. **Только черновики.** Ответ модели проходит zod-схему; неверный ответ — ошибка «не удалось разобрать», а не запись. Сохраняет человек (PRD, принцип «ИИ предлагает, человек подтверждает»).
4. **Приватность.**
   - Наружу уходит только то, что человек сам отправил на разбор, и только из записей, которые он видит.
   - Классы, которые не уходят во внешнего поставщика никогда: фото паспортов и удостоверений, медицинские документы (по умолчанию; владелец может изменить). Для них — только локальная обработка или ручной ввод.
   - В журналах — вид операции, поставщик, длительность, размер, код результата; без текста, звука, изображений и черновиков (AGENTS, правило 4).
   - Звук и фото после разбора хранятся только как файлы записи, если человек их приложил; иначе удаляются вместе с заданием.
5. **Выполнение — фоновые задания pg-boss** в `worker`: тайм-ауты (речь 60 с, разбор 90 с), один повтор при сетевой ошибке, ограничение одновременных заданий, дневной предел запросов к OpenAI на дом.
6. **Включение по дому.** Администратор включает ИИ для дома; без включения кнопки разбора не показываются, локальная речь работает отдельно.
7. **Оценка качества — `pnpm ai:eval`:** прогоняет набор образцов через выбранного поставщика и печатает точность по полям. В репозитории — только вымышленные образцы; настоящие образцы владельца лежат вне репозитория (`E:\HomeCRM-data\ai-samples`), отчёт без содержимого.

## Последствия

- Поставщики меняются без изменения экранов: при отказе OAuth переключаемся на ключ API, YandexGPT или локальную модель на видеокарте компьютера (RX 7900 XTX, 24 ГБ).
- Компьютер владельца становится зависимостью для голоса: если он выключен, голос через сервер недоступен, остаётся распознавание браузера (TASK-2).
- **Подписка вместо ключа:** приложение не работает с токенами ChatGPT само — вход держит Hermes (или Codex CLI). Прямое обращение к внутренним адресам ChatGPT по OAuth из приложения отклонено как неофициальное. Если Hermes перестанет пускать по подписке, меняется только адрес и ключ — на ключ API OpenAI.
- Hermes на каждый запрос запускает агента: задержка и расход больше, чем у прямого вызова модели; замерить `pnpm ai:eval`.
- Компьютер владельца нужен и для разбора, пока Hermes работает на нём.

## Отклонённые варианты

- Вызовы ИИ прямо из браузера — секреты и приватность не контролируются.
- Хранить распознанное как готовые записи без подтверждения — противоречит PRD.
- Сразу российское облако — владелец выбрал OpenAI для разбора; адаптер можно добавить позже.
