# ADR-0030. Личный и общий экспорт в ZIP версии 1

- **Статус:** принято, 7 октября 2026; миграция отдельного журнала разрешена владельцем.
- **Связано:** DATA-2, PRD 7.2–7.3, 13; R0.10; ADR-0020, 0022–0029.

## Решение

«Ещё» → «Мои данные» запускает отдельную личную выгрузку или выгрузку выбранного дома. Личное доступно всем ролям; общее — только действующему администратору этого дома. Роль повторно проверяется в снимке выгрузки. Все данные читаются через `withAccount` ролью `homecrm_app` под FORCE RLS. Служба входа проверяет только сессию и пароль: `verifyPassword` Better Auth 1.7.7 использует `sensitiveSessionMiddleware`. Обязательный второй фактор администратора проверяет общий читатель учётной записи. Попытки неверного пароля используют прежнюю блокировку учётной записи (пять попыток, затем 15 минут), лимит запросов — прежние 120 за 60 секунд по IP и участнику. Тело проверяется общей схемой zod, необходимо явное `confirmed: true`.

| Сущность | Личное | Общее дома | Решение |
|---|---|---|---|
| Заметки, Markdown, закрепление, пункты чек-листа | Свои личные | Обе общие аудитории выбранного дома | Включая корзину, даты, авторов и ответственных |
| Объекты, тип и данные типа, свои поля | Свои личные | Обе общие аудитории | Включая корзину; значения без преобразования |
| Ручные события объекта | Видимые события личных объектов | Общие события с общим исходным местом того же дома | Нынешний доступ и снимок происхождения; личное событие после открытия объекта не попадает в архив дома |
| История записей и автоматическая лента | Видимая история личных записей с личным снимком | Видимая история общих записей с общим снимком | RLS проверяет нынешнее и историческое место; история личных событий также исключена из общего архива |
| Связи | Хотя бы один личный конец, оба видимы | Оба конца в выбранном доме | Включая корзину; другие записи не копируются, сохраняются только ссылки |
| Ссылки на контакты в событиях | Только видимые | Только видимые общие в выбранном доме | Иначе `contact: null`, без старого id; поля контактных ссылок исключены из истории |
| Вложения заметок и объектов | Своих личных родителей | Общих родителей выбранного дома | Метаданные и расшифрованные оригиналы, включая корзину; повторная проверка родителя |
| Фото профиля | Только свои, включая снятые | Не включаются | ADR-0026; чужое семейное фото не является общими данными дома |
| Профиль «Обо мне», имя входа, собственная почта | Только свой | Не включается | Без пароля, признаков входа и второго фактора; служебная почта ребёнка заменяется `null` |
| Настройки уведомлений | Только свои, при отсутствии — действующие defaults | Не включаются | ADR-0029; тихие часы, бюджет, виды, скрытие текста |
| Пространство дома, состав | Не включаются | Выбранный дом; семейное имя, роль, даты членства и ухода | Без почты, логинов и чужих профилей; бывшие участники сохраняются |
| Правила сроков | Свои личные | Общие выбранного дома | Включая корзину; исходное правило и календарные даты |
| Наступления сроков | Только отметки выполнения видимых наступлений | То же для общего | Расчётные наступления восстанавливаются из правил; выполненность сохраняется отдельно |
| Таблицы-примеры дел и покупок | Свои личные | Общие выбранного дома | Экспортируются уже существующие строки; интерфейсы этих модулей этим решением не вводятся |
| Журнал экспорта | Предыдущие личные выгрузки владельца | Предыдущие выгрузки выбранного дома | Только актор, момент, вид, счётчики и размер |
| Сессии, пароли, TOTP, резервные коды, приглашения, сбросы пароля, журнал входа | Нет | Нет | Данные авторизации и техническое состояние; экспорт не переносит доступ |
| Push-подписки, доставки, попытки, очередь предупреждений | Нет | Нет | Адреса/ключи и техническое состояние доставки, ADR-0029 |
| Индексы поиска и членств, реестр файлов, конверты, storage keys, превью, очередь pg-boss | Нет | Нет | Производные или служебные данные; исходные записи и оригиналы файлов уже включены |

## Формат

`manifest.json`: `format: "homecrm"`, `version: 1`, `exportedAt` UTC, `timeZone` выбранного дома (для личного — первого действующего дома, иначе прежний HOME_TIME_ZONE), `scope`, `includesTrash: true`, `counts` по каждому JSON. Остальные файлы — JSON-массивы по видам, с именами колонок БД (`snake_case`); настройки уведомлений сохраняют общий контракт `camelCase`. Пустые виды имеют пустой массив; профиль/настройки отсутствуют в общем, состав/дом — в личном. Манифест и каждая строка проверяются zod в `packages/shared/src/export.ts`. Неизвестные поля отклоняются: новое поле требует явного решения формата. Версия ZIP независима от прежних JSON API.

Папка `files/` содержит оригиналы после принятой загрузкой нормализации изображений. Путь — UUID файла и безопасное имя, без каталогов из пользовательского имени; он указан в `archive_path`. Конверты и ключи не выдаются. Даты `date` сохраняются строками, `timestamptz` — с часовым смещением и точностью PostgreSQL; деньги — целые копейки. Общая схема проверяет безопасный диапазон чисел JavaScript.

## Сборка и очистка

`yazl` создаёт ZIP потоками с обратным давлением. JSON читается страницами по 100 с курсором UUID, каждый файл расшифровывается отдельно (предел загрузки 25 МиБ); весь архив и все оригиналы одновременно в память сервера не загружаются. Список членов дома — небольшой отдельный JSON. Для согласованности используется одна транзакция REPEATABLE READ; разделяемая блокировка очистки файлов защищает блоки до конца сборки.

ZIP записывается в случайный каталог системного временного хранилища контейнера, файл создаётся с правами `0600`. Отдельные расшифрованные файлы на диск не записываются. Готовый архив отдаётся файловым потоком с `no-store`, `nosniff`, фиксированным attachment-именем. Ошибка сборки, записи отметки или COMMIT удаляет архив; закрытие ответа/потока также запускает удаление, включая обрыв соединения. Отказ удаления пишет только фиксированное сообщение. Аварийное завершение процесса может оставить временный ZIP до удаления контейнера: рабочие тома и резервные копии его не содержат. Браузер собирает скачиваемый Blob в памяти устройства; для очень больших выгрузок понадобится отдельный протокол нативного скачивания.

## История и миграция

Миграция 0027 добавляет только `export_events` с ENABLE/FORCE RLS. У приложения есть чтение и вставка ограниченных колонок: автора задаёт запрос, RLS требует текущего участника; UUID и время задаёт БД. Прав UPDATE/DELETE и доступа auth/worker нет. Чужое личное событие закрыто даже администратору; общее видно только действующим администраторам этого дома. Матрица проверяет правила с `access.ts`, подмену автора/момента и запрет изменения. Журнал технический: без поиска и корзины, включён в экспорт своей области.

Отметка создаётся после успешной сборки и до выдачи, в той же транзакции; ошибка журнала закрывает выдачу. Это «архив подготовлен», а не доказательство сохранения или прочтения. Текущая отметка не входит в уже собранный архив. Журнал сервера содержит только вид, счётчики и размер; ошибки — фиксированный код без SQL, названий и текстов.

## Последствия и отклонённые варианты

Новая runtime-зависимость `yazl` нужна для потокового стандартного ZIP и автоматического ZIP64 без собственного двоичного формата. `yauzl` — только dev-зависимость для независимого чтения архивов и проверки хешей; типы нужны строгому TypeScript. API yazl сверено с [официальным README](https://github.com/thejoshwolfe/yazl).

Сборка большого JSON/массива файлов в памяти отклонена из-за DATA-2 и объёма вложений. Прямая вставка в историю записей отвергнута: это другой смысл и потребовало бы ослабить защиту триггеров. Отдельный журнал согласован владельцем. Прежний `/api/export` остаётся совместимым JSON API; экран использует `/api/export/archive`.
