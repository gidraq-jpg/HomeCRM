# ADR-0009. Web Push с ключами VAPID

- **Статус:** принято, 5 октября 2026
- **Связано:** план, T9 и раздел 2.8; PRD D7, NOTIF, критерий 22

## Контекст

У всей семьи Android (D13). Chrome на Android доставляет Web Push через сервис Google FCM. Доставку в России нужно проверить на настоящих телефонах до основной разработки (этап 0).

## Решение

- **Библиотека `web-push`** и ключи VAPID.
- **Ключи** создаются один раз на этапе 0 и хранятся в `E:\HomeCRM-data\secrets`. При переезде на VPS они переносятся вместе с данными: если их потерять, все подписки придётся оформлять заново.
- **Подписка хранится на каждое устройство:** адрес, ключи, название устройства, дата последней успешной доставки.
- **Ошибки доставки:** ответы 404 и 410 удаляют подписку; остальные — повтор с увеличением паузы.
- **Содержимое push — минимальное:** вид, идентификатор записи, короткий текст. Тихие часы, дневной бюджет и скрытие текста — в диспетчере (R0.7).

## Последствия

- Каналы уведомлений — за общим интерфейсом; Telegram, e-mail и ntfy добавятся в R2 (D14).
- Подписки привязаны к адресу приложения, поэтому адрес закрепляется до первых настоящих подписок (ADR-0018).

## Отклонённые варианты

- **Firebase SDK напрямую** — нужен проект в Firebase и учётная запись Google; Web Push — открытый стандарт.
- **Telegram как основной канал** — из России Telegram API почти недоступен; остаётся дополнительным каналом в R2.
