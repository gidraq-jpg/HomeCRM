# ADR-0017. GitHub и проверки

- **Статус:** принято, 5 октября 2026
- **Связано:** план, T17 и раздел 3.4; ответ владельца 5 октября

## Контекст

В LifeOS не было git (H3). Нужны история изменений вне этого компьютера и автоматические проверки на каждом изменении.

## Решение

- **Приватный репозиторий на GitHub.** Ветка по умолчанию — `main`.
- **GitHub Actions** (`.github/workflows/ci.yml`) запускает `pnpm install --frozen-lockfile` и `pnpm check` на каждый запрос на слияние и на каждую отправку в `main`. Устаревшие прогоны отменяются.
- **Ловушка перед `git push`** (`.githooks/pre-push`) запускает тот же `pnpm check`; её подключает `pnpm install`.
- **Сливает в `main` только ведущий агент** — при зелёных проверках и пройденном ревью (ADR-0019).
- **Ночной прогон** — отдельный сценарий по расписанию с полным визуальным набором; появится вместе с первыми сквозными тестами в R0.
- **Секретов в репозитории нет;** секреты GitHub Actions пока не нужны.

## Последствия

- **Бесплатный тариф** не позволяет в приватном репозитории запретить слияние без зелёных проверок. Поэтому правило держится на ловушке и на `AGENTS.md`, который запрещает `--no-verify`, принудительную отправку в `main` и слияние с красными проверками.
- **2000 минут CI в месяц** на приватные репозитории. Проверки должны оставаться быстрыми: долгие сквозные тесты запускаются при слиянии, а не на каждой отправке.

## Отклонённые варианты

- **Только локальный git** — история живёт на одном диске, проверки зависят от дисциплины.
- **Платный тариф GitHub** — из России оплатить сложно.
