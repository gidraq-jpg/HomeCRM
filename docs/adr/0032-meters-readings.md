# ADR-0032. Счётчики, точные показания и замена

- **Статус:** принято для реализации R1a.4–5; 8 октября 2026
- **Связано:** UTIL-3…8, UTIL-14, OBJ-3, OBJ-5; ADR-0023, ADR-0028, ADR-0030, ADR-0031.

## Модель и точность

`meters` — дочерние записи объекта, `meter_readings` — дочерние записи счётчика. Обе таблицы подключены через `recordTable` и `attach_record_table`: общие поля доступа, ENABLE/FORCE RLS, история, ответственность, корзина, восстановление и матрица `access.ts` ↔ SQL. Счётчик может быть заведён только с ресурсом, как в S1; необязательный лицевой счёт проверяется на принадлежность тому же объекту и доступность. Зоны, разрядность и ресурс после первого показания не меняются: для другого прибора служит замена.

Значения и расход хранятся в PostgreSQL как `numeric[]`. API принимает и возвращает строки; точка и запятая принимаются на входе. Сервер считает минимальные доли через `bigint`, без преобразования значений в `Number`. JSON истории, лента и ZIP также используют строки: преобразование `numeric[]` в JSON-числа потеряло бы точность при чтении JavaScript. Документация [Drizzle о PostgreSQL numeric](https://orm.drizzle.team/docs/column-types/pg#numeric) и массиве проверена через Context7; используется установленный Drizzle 0.45.3, без `mode: number`.

Дата следующей поверки вычисляется календарно по приложению А, с ограничением 29 февраля последним днём месяца. Явная `nextVerificationOn` имеет приоритет; отсутствие поля пересчитывает дату, `null` снимает её. Сроки радара и уведомления не создаются: это R1a.6.

## Ввод и замена

Запись показаний, пакет по объекту и замена идут одной транзакцией. Сначала блокируется объект, затем счётчик. Все запросы для объекта сериализуются, поэтому два одинаковых ввода не используют одно прошлое показание. Обычный ввод дописывает историю строго по датам; повтор даты — 409. Конечное показание при замене допускается в день уже сохранённого отсчёта. Понижение требует явного `rollover`; предел равен десяти в степени числа целых разрядов.

Предупреждение сравнивает расход отдельно по зонам с арифметическим средним завершённых интервалов, заканчивающихся за последние шесть календарных месяцев. Если истории меньше, используется имеющаяся; при одном начальном показании среднего ещё нет. Порог включает ровно 40%; положительный расход после нулевого среднего также предупреждает. Предупреждение не блокирует сохранение. При замене история предшественников с тем же числом зон участвует в среднем, даже при другой дробной разрядности.

Замена сохраняет конечное показание, переводит старый прибор в `replaced`, создаёт новый прибор с начальным показанием и ссылкой `previous_meter_id`. Ресурс сохраняется, начальная и конечная даты совпадают. Начальный отсчёт нового прибора не расход: его расход `null`. История цепочки содержит конечный расход старого и последующий расход нового, без искусственного скачка между их шкалами. FK сохраняет существование предшественника; его окончательная очистка обнуляет только ссылку нового прибора, не переписывая его содержимое, время и историю.

Передача показывает последний ещё не переданный отсчёт каждого счётчика, сгруппированный по живому лицевому счёту с номером, способом и ссылкой. Отметка передачи пакета атомарна. Повторная отметка сохраняет первоначальные дату и способ. Никакой автоматической передачи нет; закрытие пункта радара подключается R1a.6.

## Фото и жизненный цикл

Фото загружаются существующим API файлов объекта и связываются с показанием через `record_links`, роль `reading_photo`. При вводе проверяются видимость, живое состояние, формат изображения и тот же объект. Блоки, шифрование, удаление, скачивание и ZIP используют R0.5. Корзина показания сохраняет связь и оригинал; отдельно удалённое фото не выдаётся в `photoIds`.

Перенос объекта переносит счётчики и показания, включая их самостоятельную корзину. Восстановление возвращает строки, удалённые именно каскадом, независимо от автора. Содержательный вклад в показание отмечает счётчик и объект; сделать такой общий объект личным нельзя. Копия объекта включает живое дерево с новыми id, автором и ссылками на скопированные счета и фото. Лента показаний общего использует историю со снимком доступа; открытие «Взрослые» всей семье не открывает прежние события.

Самостоятельная корзина и восстановление показания допускаются для последнего отсчёта: удаление середины ряда потребовало бы менять уже сохранённый расход следующих отсчётов. Исправление последнего значения — корзина и повторный ввод; восстановление прежнего после нового отсчёта отклоняется 409. Корзина всего счётчика/объекта действует на весь ряд.

Поиск индексирует название и заводской номер счётчика под RLS и ведёт в объект. Показания не индексируются отдельно. ZIP версии 1 дополнен `meters.json`, `meter_readings.json` и их историей; фото входят в `object_files.json`/`files`, связи — в `record_links.json`. Старые JSON API сохраняют контракты.

## Миграции и проверки

0029 добавляет CHECK вида контакта по замечанию PR #34; 0030 создаёт новые таблицы и расширяет функции; 0031 подключает жизненный цикл и точную историю. Нет очистки, переписывания содержимого или истории существующих объектов, контактов и счетов. Проверка обновления с заполненной 0028 сравнивает эти записи и историю целиком. Проверяются числовая точность, многозонность, переход через ноль, аномалии, замена, атомарность, гонка ввода, поиск, приватность, ZIP, перенос и очистка. Новых зависимостей нет.
