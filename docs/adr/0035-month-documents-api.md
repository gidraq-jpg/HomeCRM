# ADR-0035. Месячная коммуналка, аналитика и версии документов

- **Статус:** принято для реализации R1a.9 и R1b.1; 8 октября 2026.
- **Связано:** UTIL-11/12, DOC-1/2/5/6/7, PRD 7.2, 12, приложение Б; ADR-0023/0024/0032/0034.

## Решение

Месячный обзор собирается одним SQL под RLS: видимые объекты, счета, начисления расчётного месяца и действующие оплаты этих начислений. Поздняя оплата уменьшает долг исходного расчётного месяца. Остаток суммируется по начислениям с ограничением снизу нулём, переплата одного начисления не погашает другое. Статус передачи требует показаний каждого действующего счётчика внутри окна в поясе дома; без приборов учитывается ручная отметка окна. Автоматическая передача и отсутствие правила означают «не требуется».

Аналитика возвращает последние 12 месяцев и те же месяцы предыдущего года. Начисления группируются по расчётному месяцу, оплаты — по календарной дате оплаты. Расход суммируется из сохранённого точного `consumption` показаний, включая заменённые приборы: начальное значение нового прибора не становится расходом. Значения PostgreSQL `numeric` выдаются строками, без преобразования в `Number`; деньги складываются в `bigint` и проверяются на безопасный диапазон HTTP-числа.

`documents` — корневая запись `recordTable`, `document_files` — дочерние зашифрованные файлы существующего механизма R0.5. Обе сущности имеют ENABLE/FORCE RLS, матрицу, историю, корзину, перенос и экспорт. Каталог 20 типов и схемы реквизитов находятся в `packages/shared/src/documents.ts`. Реквизиты хранятся в JSONB, даты — календарные строки, не моменты UTC. Номер, серия, заметка и теги не входят в общий поисковый индекс; индексируются только название и русское название типа. Файлы доступны из документа; отдельные результаты общего поиска файлов не добавляются.

Владелец задаётся одним из трёх неизменяемых полей: участник, контакт или объект. Участник и объект имеют FK. Контакт связан обычной `record_links` с ролью `document_owner`; поле `owner_contact_id` служит внутренним указателем для фильтра. Оно намеренно без FK: очистка чужого контакта не требует обхода RLS документа. После скрытия или очистки контакта API и экспорт не выдают его UUID; история не содержит этот указатель. Новая запись требует живого видимого контакта; продление сохраняет внутренний указатель, но переносит лишь видимые связи. Карточка документа не пересказывает данные контакта.

Документ взрослого и контакта по умолчанию личный у создающего, документ ребёнка — в общем доме «Взрослые». Удостоверения ребёнка защищены дополнительно в `canViewDocument` и SQL: смена роли владельца уже общей записи не открывает её другим детям. Файлы, история, сроки, ссылки и индекс проверяют видимость исходного документа. Документы объекта следуют его месту, аудитории и корзине. Независимо удалённые документы и страницы остаются в корзине при восстановлении родителя. Содержательный вклад в документ объекта блокирует приватизацию объекта по общему правилу вкладов.

«Продлить» блокирует старую запись, помечает её недействительной, создаёт новую с `previous_id`, переносит ответственного и доступные живые связи в одной транзакции. Уникальный индекс предшественника запрещает две параллельные новые версии. Старая версия сохраняет прежние реквизиты и файлы; файлы новой версии загружаются отдельно. Возврат статуса в действующий запрещён. Цепочка версий и история выдаются под RLS; UUID скрытого предшественника не выдаётся. Физическая очистка предшественника обнуляет ссылку, не удаляя новую версию.

Срок документа — источник `document` в существующем движке. Триггер согласованно создаёт/обновляет срок из даты окончания, переносит место и ответственного, скрывает срок недействительной или бессрочной версии. Набор предупреждений — из приложения Б, либо явно выбранный `warnings`. Горизонт документов — 365 дней, поэтому предупреждение загранпаспорта за 180 дней не теряется. Радар получает название документа тем же SQL без N+1; активное предупреждение дальше 90 дней выдаётся в дополнительной группе `later` («Позже»). Существующие группы сохранены, `later` появляется только при наличии таких документов. Группа включена в общий RADAR_GROUPS; клиент принимает источник document и показывает «Позже» после 90 дней. Просроченные документы не отсекаются нижней границей from. Правила паспорта РФ по возрасту остаются R1b.2.

Worker получает только служебный вычисляемый признак `is_identity` и UUID участника-владельца. Проверка получателя перед постановкой в очередь и перед отправкой использует тот же SQL-барьер, что RLS. Worker не получает JSONB реквизитов, названий или номеров. Производный признак не включается в историю и экспорт.

## Обновление и проверка

Миграции 0038–0042 создают новые таблицы и индексы, добавляют nullable `document_id` к срокам и расширяют функции/политики жизненного цикла. Значения существующих записей, история, ручные отметки и настройки не переписываются. Проверка обновления стартует с отдельной заполненной базы 0037 и сравнивает её данные после миграций. Проверяются каталог SQL, матрица, роли, версии/гонка, фильтры, поиск, сроки, перенос, файлы и ZIP. Замеры месяца и радара проверяют один SQL данных и p95 <300 мс на 500 записях.

Поправки ревью (миграция 0043): роль владельца проверяется во всех действующих домах. Узкая SECURITY DEFINER-функция `app.document_owner_is_child(uuid)` возвращает только boolean из `household_access`, без UUID домов и персональных полей. FORCE RLS сохранён; владельцу схемы добавлена только SELECT-политика на строки child служебного индекса в пределах вызова функции (локальный SET app.document_owner_lookup), runtime-роли не получают доступ к чужим строкам индекса. Это закрывает случай, когда ребёнок не состоит в доме документа, а его членство скрыто от зрителя. API, RLS, триггер и предупреждения используют один факт. Продление наследует запрет приватизации через `has_other_contributions` независимо от автора новой версии. Список и версии получают поля представления одним SELECT, без запросов на каждую строку. Начало расчётного месяца вычисляется как местная полночь в поясе дома.

Новых зависимостей нет. Рабочее окружение и данные семьи не используются. Формат ZIP v1 дополнен документами, страницами и историей; номера в пользовательском архиве разрешены, в журналах сервера их нет.

## Отклонённые варианты

Хранить владельца только в произвольных связях — усложняет неизменяемость, наследование места объекта и защиту детских удостоверений. FK на контакт — создаёт зависимость очистки контакта от видимости чужого документа. Обновлять реквизиты на месте при продлении — теряет предыдущую версию. Вычислять месячные суммы отдельным запросом для каждого объекта — нарушает критерий без N+1. Считать расход разностью первых и последних показаний — даёт ложный скачок при замене или переходе через ноль.
