# ADR-0003. PostgreSQL 18 и Drizzle ORM

- **Статус:** принято, 5 октября 2026
- **Связано:** план, T3; PRD, раздел 12

## Контекст

Данные связанные: объекты, связи, сроки, история. Нужны транзакции, политики доступа на уровне строк (ADR-0004), полнотекстовый поиск по-русски (ADR-0011) и очередь задач в той же базе (ADR-0006).

## Решение

- **PostgreSQL 18** в Docker. Идентификаторы записей — UUID v7: они упорядочены по времени, функция `uuidv7()` встроена в PostgreSQL 18.
- **Drizzle ORM:**
  - схема — в TypeScript, в пакете `packages/db`;
  - запросы — типобезопасные и близкие к SQL;
  - политики RLS описываются прямо в схеме.
- **Миграции:** drizzle-kit создаёт SQL-файлы, они лежат в git. Миграции — только вперёд; перед каждой — резервная копия (PRD, раздел 13).
- **Драйвер** — `pg` (node-postgres), общий с pg-boss.

## Последствия

- SQL миграций виден при проверке: политики RLS и индексы можно прочитать глазами.
- Сложные запросы (радар, поиск) пишутся на SQL через Drizzle — это нормально, а не обход.

## Отклонённые варианты

- **Prisma** — политики RLS в схеме не описываются, контекст пользователя в транзакции даётся хуже.
- **Kysely** — хороший построитель запросов, но без схемы и генерации миграций.
