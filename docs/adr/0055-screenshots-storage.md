# ADR-0055: Снимки экранов не копятся в репозитории

Статус: принято (D53e, 23 ноября 2026). Удаление старых папок — по решению владельца.

## Контекст

`docs/screenshots` — 66 папок, 2034 файла и около 303 МБ рабочего дерева; по разбору 16 ноября 2026
это 302 МБ из 369 МБ папки `.git`. Каждый запрос на слияние с изменением интерфейса добавлял новую
папку снимков. Автоматических эталонов (`toHaveScreenshot`) в проекте нет: снимки смотрят люди —
владелец, ведущий и ревьюер. CI уже прикладывает `apps/web/test-results` (там `screens/360`,
`screens/412`) как материалы запуска, отдельно для каждой части браузерных сценариев.

Большая папка `.git` замедляет клонирование и создание worktree для каждого исполнителя, а снимки
закрытых задач больше не открывают.

## Решение

1. В репозитории хранятся только:
   - утверждённые макеты — `docs/screenshots/approved-design` и картинки контрактов в `docs/design`;
   - эталоны для сравнения — снимки, на которые прямо ссылается действующий контракт оформления
     или ADR как на образец текущего вида. Новый эталон добавляется только вместе с таким документом.
2. Снимки к запросу на слияние — материалы CI (`apps/web/test-results/screens`). В описании запроса
   на слияние — ссылка на запуск CI и список проверенных экранов. Папки `docs/screenshots/<задача>`
   больше не коммитятся.
3. Новые сценарии пишут снимки только в `apps/web/test-results/screens`. Сценарии, которые сейчас
   пишут в `docs/screenshots` (`chat`, `dock-motion`, `motion-whole`, `pilot-fixes`, `sheet-motion`,
   `today-rows`, `voice-compact`, `voice-input` и отдельные compose-прогоны в `apps/web/e2e/*/compose.yaml`),
   переводятся на `test-results` отдельной задачей; до этого их вывод в `docs/screenshots` не коммитится.
4. Историю git не переписываем: `git push --force` в `main` запрещён. Папка `.git` не уменьшится,
   правило только останавливает её рост.
5. Папки закрытых задач удаляются из рабочего дерева только по решению владельца (список ниже).
   После удаления снимки остаются в истории git: `git show <коммит>:docs/screenshots/<путь>`.

## Последствия

- Запрос на слияние с интерфейсом больше не добавляет мегабайты в `.git`; снимки живут столько,
  сколько хранятся материалы CI (`retention-days: 14` в `.github/workflows/ci.yml`). Ревью и решение
  владельца укладываются в этот срок; для долгой памяти остаются утверждённые макеты и эталоны.
- Ссылки на снимки из старых брифов, хода работ в плане и runbook после удаления папок перестанут
  открываться в рабочем дереве. Их не правим: это история, снимки достаются из git.
- Ловушка git и CI не меняются: `docs/screenshots/**` по-прежнему считается кодом и требует полного
  набора проверок, если кто-то всё же меняет эталон.

## Отклонённые варианты

- Переписать историю (`git filter-repo`) — запрещено правилами и ломает все worktree и запросы на слияние.
- Git LFS — новая зависимость и квота на бесплатном тарифе ради снимков, которые не открывают.
- Хранить снимки в отдельной ветке — та же папка `.git`, только менее заметно.
