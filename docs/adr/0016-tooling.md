# ADR-0016. Инструменты: pnpm 12, TypeScript 7, Biome, TypeScript в Node без сборки

- **Статус:** принято, 5 октября 2026
- **Связано:** план, T16 и задача 0.1

## Контекст

Чем меньше инструментов и шагов сборки, тем меньше точек отказа и тем быстрее проверки. Проверки идут на каждом изменении, а бесплатных минут CI мало (ADR-0017).

## Решение

- **pnpm 12.** Версия закреплена в `package.json` (`packageManager`). Ставятся только версии пакетов старше суток (`minimumReleaseAge`) — защита от свежих вредоносных выпусков.
- **TypeScript 7** — нативный компилятор, только для проверки типов (`noEmit`). Режим строгий, плюс `noUncheckedIndexedAccess`.
- **Сервер запускает `.ts` прямо в Node 24** — встроенное удаление типов, без tsx и сборщика. Проверено 5 октября на Node 24.14.1, включая импорт внутреннего пакета через ссылку pnpm. Отсюда правила кода:
  - только стираемый синтаксис: без `enum`, `namespace` и свойств-параметров конструктора; включён `erasableSyntaxOnly`;
  - относительные импорты — с расширением `.ts`.
- **Клиент** собирает Vite.
- **Biome** — формат, линтер и порядок импортов одним быстрым инструментом.
- **`pnpm check`** = кодировка + Biome + типы + тесты. Это же запускают ловушка перед `git push` и CI.

## Последствия

- В образе Docker нет шага сборки сервера: копируются исходники и ставятся зависимости.
- Если понадобятся правила линтера с проверкой типов (например, о забытых `await`), можно добавить typescript-eslint отдельным решением.

## Отклонённые варианты

- **ESLint + Prettier** — два инструмента, медленнее, больше настроек.
- **tsx или сборка tsdown** — лишний шаг. tsdown остаётся запасным вариантом, если встроенного удаления типов перестанет хватать.
