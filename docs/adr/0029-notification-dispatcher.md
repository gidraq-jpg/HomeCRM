# ADR-0029. Диспетчер уведомлений и состояние доставки

- **Статус:** принято для R0.7, 7 октября 2026.
- **Связано:** NOTIF-1, 2, 4, 6, 7; ADR-0009, ADR-0006, ADR-0028.

## Решение

Подписка — технические сведения устройства с владельцем `account_id`, а не запись дома. Составной внешний ключ `(session_id, account_id)` ссылается на сессию и её владельца: нельзя привязать чужую сессию, удаление сессии каскадно удаляет подписку. Уход из любого дома удаляет все подписки участника; после нового входа устройства подписываются снова. Закрытый триггер `remove_member_push` выполняет только эту очистку, не выдаёт runtime-ролям права на чужие подписки и не вызывается ими напрямую. Политика владельца действует только внутри триггера, как у индекса поиска. Настройки и журнал тоже имеют только владельца; ENABLE и FORCE RLS обязательны на всех новых таблицах.

Первый и единственный источник R0.7 — `deadline`, предупреждение движка сроков. Другие виды появятся вместе с соответствующими источниками. Worker получает дополнительно только `audience` заметок и объектов: названия, содержимое и поля источника ему не выдаются. Перед сетевым вызовом повторно проверяются действующее членство в доме, ответственный и текущая аудитория источника, корзина, выполненность, актуальность правила и пояса. Для личного источника ответственный всегда владелец — это инвариант БД. Повторная проверка выполняется после устойчивого резервирования доставки; саму подписку worker блокирует до результата отправки, чтобы отзыв сессии не оставил подписку после завершённого отзыва. Уже переданный внешней службе push отозвать нельзя.

Тихие часы по умолчанию 22:00–08:00 рассчитываются календарно в поясе дома, включая переходы DST; одинаковые начало и конец выключают интервал. Дневной бюджет по умолчанию 5 считает разные предупреждения участника в локальную дату дома, включая зарезервированные попытки. Одно предупреждение на двух устройствах тратит одну единицу. Повтор в другую дату проходит бюджет этой даты снова. Нулевой бюджет, превышение и предупреждения старше 24 часов отправляются в состояние `summary`; сами сводки реализует NOTIF-5 позже. Отключённый вид отменяет доставку. По умолчанию текст только «В HomeCRM есть новое»; при выключенном скрытии — «Подходит срок записи в HomeCRM». Текст источника не нужен даже для этого режима.

Диспетчер запускается очередью pg-boss раз в минуту, после расчёта предупреждений и при старте worker. Advisory lock на отдельном соединении сериализует диспетчеры одной базы. `push_deliveries` хранит уникальную пару «строка предупреждения + устройство»; сама строка предупреждения уже уникальна по наступлению, получателю и моменту. Успешные устройства не отправляются повторно, пока другие повторяют ошибку. 404/410 удаляют подписку, прочие ошибки повторяются через 30, 60, 120 секунд до предела в час; после суток предупреждение переходит в сводку. Web Push TTL — 5 минут, таймаут — 10 секунд, стабильный `topic` вычисляется из UUID доставки.

Внешняя отправка и PostgreSQL не образуют общую транзакцию. Перед вызовом фиксируется `sending`; после ответа фиксируется результат. Если процесс погиб между ними, через десять минут неизвестная попытка получает журнал `uncertain` и состояние `summary`, без слепого повтора. Это защита от возможного дубля ценой пропуска push при аварии до сетевого вызова; предупреждение сохраняется в системе. `topic` дополнительно объединяет ещё не доставленные сообщения у push-службы, но не доказывает показ на телефоне. `sent` означает принятие службой, не прочтение человеком.

В журнале попыток только момент, вид, UUID устройства, результат и числовой HTTP-код; адрес, ключи и ответы push-службы не сохраняются. Worker очищает строки старше 90 дней. Подписки, очередь и журнал — техническое состояние, не входят в поиск и экспорт, не имеют корзины; отписка немедленная. Настройки входят в личный экспорт и не индексируются. Очередь удаляется каскадно вместе с наступлениями; журнал остаётся без текстов источника.

## API для R0.7b

- `GET /api/push/key` → `{publicKey}`, 503 до настройки VAPID; это публичный ключ.
- `GET /api/push/subscriptions` → свои `{id,deviceName,createdAt,lastSuccessAt}`, без адресов и ключей.
- `POST /api/push/subscriptions` → `{endpoint,keys:{p256dh,auth},deviceName}`, 201; повтор в своей сессии обновляет устройство с прежним UUID. Занятый endpoint даёт 409 без сведений о владельце.
- `DELETE /api/push/subscriptions/:id` → 204, для чужого/неизвестного UUID — 404.
- `GET /api/notifications/settings`, `PATCH /api/notifications/settings` → `{quietStart,quietEnd,dailyBudget,enabledKinds,hideText}`. PATCH принимает частичный объект, бюджет 0–100, вид пока `deadline`.
- `GET /api/notifications/deliveries` → последние 100 своих попыток.

Все закрытые API используют общую проверку сессии, обязательного второго фактора и Origin. Адрес push ограничен HTTPS-хостами FCM, Mozilla, Apple и Windows Push: произвольный адрес превратил бы worker в средство запросов к внутренней сети. Для нового провайдера нужен отдельный проверенный домен в схеме.

## Ключи и проверка

`new-app-secrets.ps1` повторно использует `secrets/vapid.env` этапа 0. App получает только публичный ключ, worker — пару и subject; существующие несовпадающие ключи не заменяются. Для предпросмотра используется та же сохранённая пара, но подписки разделены адресами приложений и базами. Потеря пары требует переподписки устройств (ADR-0009).

`web-push` реализует ADR-0009, типы нужны строгому TypeScript. Сервер явно использует уже принятые `date-fns` и `@date-fns/tz` для часов дома. Тесты отправляют только в подменённый транспорт и используют одноразовые базы. Проверка на настоящих телефонах, Wi-Fi/мобильной сети и разрешения PWA остаются владельцу при R0.7b и выпуске.
