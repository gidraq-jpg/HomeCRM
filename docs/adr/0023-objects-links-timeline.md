# ADR-0023. Объекты, связи и лента под RLS

- **Статус:** принято; 6 октября 2026
- **Связано:** R0.5a, OBJ-1…3, OBJ-5, OBJ-6, SPACE-4, SPACE-6, PRD 7.3; ADR-0004, ADR-0020

## Решение

Объект, своё поле и ручное событие подключаются через `recordTable` и `attach_record_table`: общие поля доступа, ответственный, история, корзина, политики и матрица. Тип объекта — закрытый список `property`, `car`, `appliance`, `other`; обязательное поле только `title`. Пустой `type_data` оставляет место для полей типа в UTIL и DOC; API R0.5a его не принимает. Название до 200 символов. Свои поля — до 50 живых строк, название до 100, значение до 4000, порядок в массиве API.

Связь хранит два конца «таблица — id» и подпись роли до 200 символов. Её пространство, аудитория и ответственность определяются концами: самостоятельного пространства у связи нет. Чтение требует видимости обеих записей. Создание, смена подписи, корзина и восстановление требуют чтения обеих и права правки хотя бы одной живой записи. Это уточнение OBJ-2 по PRD 7.3.2: ребёнок может связать своё личное с общей квартирой, а также связать назначенное ему дело с квартирой; одно чтение двух общих объектов не даёт права менять связь. Проверки есть в `access.ts`, сервере и RLS. SQL разрешает только таблицы с триггером `record_defaults`, то есть подключённые через `attach_record_table`; имена экранируются как идентификаторы, значения параметризованы. Функции выполняются с правами вызывающего, без `SECURITY DEFINER`. Скрытый и отсутствующий конец дают одинаковый отказ без id, счётчиков и подробностей ошибки.

Ручное событие хранит календарную дату, текст до 10 000 символов, целую сумму в копейках в безопасном диапазоне JavaScript, оценку 1–5 и необязательную ссылку на видимую запись. Ссылка на другое ручное событие запрещена, чтобы избежать циклов проверок доступа. Файлы добавятся дочерней сущностью R0.5b, без фиктивных файловых id сейчас. Автоматические события собираются из истории объекта и его полей. История и ручные события требуют и нынешнего доступа, и доступа к зафиксированному месту события: открытие «Взрослые» всей семье не раскрывает прошлое. У ручного события снимок ставит база, он неизменяем. Контакт, ставший невидимым, скрывает всё событие, включая id контакта. Удалённый физически контакт также скрывает событие; это сохраняет приватность, текст события остаётся в базе. Управление контактами и отсоединение перед окончательным удалением уточняются в модуле CONTACT.

Скрытое прежним снимком событие тоже должно наследовать смену места и корзину родителя. Триггер родителя устанавливает локальный контекст его id, операции и времени корзины, затем меняет только служебные колонки, без чтения содержимого. Дополнение UPDATE-политики ограничивает каскад этим родителем, глубиной триггера и правом восстановления; обычный UPDATE по-прежнему требует снимок и видимый контакт. Триггер события запрещает каскаду менять содержимое или снимок. Прямой SQL, включая UPDATE без WHERE и поддельный контекст, не даёт писать скрытое событие. Для миграционных и тестовых ролей без RLS каскад явно ограничен `parent_id`.

Список ленты — один SQL-запрос с `UNION ALL`, упорядочиванием по времени, источнику и id. Дата ручного события даёт полночь UTC как ключ сортировки, без преобразования календарной даты пользователя. Автоматические события используют время истории. Курсор хранит точное строковое время базы и оба ключа, поэтому одинаковые времена не теряют записи. Будущие показания, начисления, документы и дела добавят свои источники в объединение с теми же проверками доступа.

Дочерние поля и события наследуют место объекта, переносятся и уходят в корзину с ним. Отдельное удаление поля или события — своя корзина на 30 дней. Восстановление родителя возвращает только те дочерние записи, которые удалены его каскадом, и только по правам восстановления. Связь имеет свою корзину; корзина конца скрывает её из обычного списка, восстановление конца возвращает неудалённую связь. Физическая очистка конца убирает связи триггером до FK-каскада, включая связи всех дочерних строк; новые таблицы получают его через `attach_record_table`. Обработчик получает чтение `parent_id` дочерних таблиц в дополнение к прежним служебным колонкам; тексты ему по-прежнему не выданы. Создание и изменение связи берут разделяемую транзакционную advisory-блокировку каждого конца, очистка — исключительную по тому же ключу. После ожидания видимость проверяется снова: гонка с DELETE не оставляет осиротевшую связь, даже если участник может только читать удаляемый конец. Обход дерева использует каталог FK и только таблицы, подключённые через `attach_record_table`, с правами вызывающего и действующими политиками корзины.

Вклад в общий объект — изменение названия либо содержимое дочерних записей. У дел — название; у покупок — название, количество и отметка покупки. Смена ответственного, аудитории, места, корзина и восстановление вкладом не считаются. Добавление и содержательная правка дочерней строки отмечают родительский объект необратимо, под блокировкой родителя. Старые признаки дел и покупок пересчитываются только по содержательной истории; данные и сами события сохраняются. До отложенного FK проверяется видимость родителя: ребёнок не различит чужой id и отсутствующий по SQLSTATE.

Поиск R0.6 получит `search_text`: название объекта, название и значение поля, текст события. Самого поиска и индексов ранжирования в этом этапе нет. Экспорт R0.10 включает своё личное и общее администрируемого дома под RLS: объекты, поля, события, историю общих записей и видимые связи, включая корзину. API этого модуля отдаёт такой JSON отдельно; сборка ZIP и включение в единый экспорт будут в R0.10. Копия объекта получает новые id и автора, живые поля и видимые живые ручные события; связи и прежняя история не копируются.

Журнал содержит только английское сообщение и SQLSTATE, без SQL, параметров, текстов и значений полей. Адреса новых API очищаются от пользовательского текста и query-параметров. Новых зависимостей нет.

## Последствия

Новые пользовательские сущности проверяет прежняя матрица записей; связи — отдельная матрица пар, снимки событий — точечные проверки. Ослабление политики должно давать расхождение. Миграции проверяются на базе со старыми записями и историей. Файлы, интерфейс и выпуск не входят в R0.5a.
