# ADR-0037. Импорт vCard, дни рождения и дополнения API

Статус: принято для реализации R1b.4–5. Связано: CONT-6/7, ADR-0028, ADR-0034–36.

## Решение

Импорт принимает vCard 3.0/4.0, до 512 КиБ и 500 карточек. Разбор выполняется целиком перед записью; ошибки не содержат значений файла. UTF-8, quoted-printable, складки строк, даты без года поддерживаются; PHOTO и неизвестные свойства пропускаются. Сетевые ссылки из файла не открываются. Предпросмотр можно загрузить multipart или JSON; применение повторно передаёт файл, хэш предпросмотра и выбор для каждой карточки. Файл на сервере не сохраняется.

Совпадения — только среди живых видимых людей, по телефону без оформления; российский начальный 8 сопоставляется с 7. Предпросмотр возвращает доступность объединения. Применение проверяет права, версию и совпадение под блокировкой контакта. Поля дополняются: телефоны и e-mail объединяются, адрес и дата заполняются только при пустом значении, заметки дописываются. Имя, подписи старых телефонов и настройка напоминания сохраняются. Организация создаётся в месте контакта либо используется видимая организация того же места с тем же названием; существующая связь не заменяется. История контакта получает отметку импорта, включая личные контакты, под прежней RLS истории. Общие изменения сохраняют обычную историю полей.

Техническая таблица `api_operations` содержит участника, UUID ключа, вид операции, SHA-256 нормализованного запроса и UUID результата. Файлы, имена, даты и суммы туда не копируются. ENABLE/FORCE RLS, только собственное SELECT/INSERT, без UPDATE/DELETE у runtime-ролей. Ключ блокируется до записей; результат сохраняется одной транзакцией с изменениями. Другой запрос с тем же ключом — 409. Повтор читает результат под текущей RLS; утраченный доступ не обходится. Ключи сохраняются, чтобы поздний повтор не создавал дубль; это служебное состояние, вне поиска, корзины и пользовательского экспорта.

Дни рождения — производные `deadlines.source_kind=birthday` с FK на контакт или профиль. Флаг в данных человека — `birthdayEnabled`, в профиле — `birthday_enabled`; старые значения остаются выключенными. Контакт наследует своё место, корзину и ответственного; профиль использует личное пространство владельца и выбранный действующий дом для пояса. RLS срока профиля проверяет видимость самого профиля, как доступ к дате рождения в паспортном правиле, а не открывает другие личные записи. Правило содержит только месяц и день, ежегодный повтор, предупреждения 7/1 день в 09:00 дома. 29 февраля ограничивается 28 февраля в невисокосном году. Возраст вычисляется только в API из видимой полной даты; без года — null.

Триггеры создают, пересчитывают и выключают производный срок; прямые изменения запрещены. Перенос и смена ответственного используют общий закрытый каскад. Сужение доступа, корзина и выключение флага скрывают старые наступления немедленно, до прохода worker. Даты и флаги экспортируются вместе с источниками; доступные правила входят существующим экспортом сроков. Поиск использует прежний индекс названия контакта; даты и правила не индексируются.

Worker не получает SELECT текстов контактов и профилей. Узкая SECURITY DEFINER-функция возвращает имя лишь для текущего ответственного, включённого источника и текущего доступа. FORCE RLS сохраняется: три отдельные политики владельца ограничены контекстом этой функции, runtime-роли её контекстом таблицы не открывают. Проверка повторяется при постановке и перед отправкой. В push используется прежний вид уведомления `deadline`; скрытый текст — «В HomeCRM есть новое», открытый — имя дня рождения.

Радар ограничивает обычные сроки 90 местными днями, документы и дни рождения — 365. Дальше 90 дней возвращаются только начавшиеся предупреждения; запрос клиента на 366 дней остаётся допустимым. Истёкшие дни рождения не становятся долгами. Суммы начисления и действующих оплат агрегируются наборами под RLS, деньги проверяются на безопасный целочисленный диапазон. В транзакции радара отключены JIT и nested loop: на больших наборах источников вложенные политики выгоднее соединять наборами; порог замера остаётся 300 мс.

## Обновление

Пункт 7a: `null` при правке скрытой ссылки сохраняет её; пропущенное поле не меняет ссылку. Видимую организацию/объект можно снять. Владелец документа остаётся неизменяемым, но сервер принимает возвращённый скрытый `owner=null` при правке текста. Граница `passportYears` хранится вместе с производным паспортным окном, а не вычисляется заново по доступной редактору дате: это сохраняет одно правило при последующем закрытии источника. Миграция 0053 дополняет только метаданные совпавшего открытого аудитории окна и восстанавливает временные политики и защитный триггер в той же транзакции. Лента отдаёт текущее видимое название контакта; глобальный поиск использует существующий индекс названий под RLS.

Миграции 0050–0052 продолжают 0049. Добавляются nullable ссылки, выключенный флаг профиля, служебная таблица, политики и триггеры. Исходные контакты, документы, денежные записи, история, UUID наступлений и доставки не переписываются. Новых зависимостей нет. Рабочее окружение и клиент не изменяются.

## Отклонённые варианты

Сохранять файл предпросмотра или полный ответ для повторов — лишняя копия чувствительных данных. Перетирать контакт при совпадении — потеря ручных полей. Читать worker все имена или даты — расширение доступа без необходимости. Дублировать дни рождения отдельным движком — расхождение по календарю и уведомлениям.
