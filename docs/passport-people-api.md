# API людей, взаимодействий и паспортных сроков

R1b.2–3, DOC-3–4, CONT-1–5. Решения: [ADR-0036](adr/0036-passport-people-api.md). Все маршруты требуют сессию; чужое личное и «Взрослые» скрыты RLS. Даты — строки без времени, суммы — целые копейки.

## Контакты

`POST /api/contacts`: `title` (ФИО/название), `kind` (`person` или прежний `organization` по умолчанию), `data`, необязательные `organizationId`, `placement`. Вид нельзя изменить. Человек по умолчанию личный; категория `craftsperson` — «Вся семья». Для организации сохранён прежний контракт CONT-2: тип, телефоны с подписями и аварийностью, сайт, адрес, часы работы, заметка.

Пример `data` человека:

```json
{
  "categories": ["doctor"],
  "phones": [{ "number": "+7 (900) 000-00-00", "label": "Рабочий", "emergency": false }],
  "emails": ["doctor@example.test"],
  "messengers": [{ "label": "Мессенджер", "url": "https://example.test/doctor" }],
  "address": "Вымышленная улица, 1",
  "birthday": "--02-29",
  "note": "Вымышленный контакт"
}
```

Категории: `family`, `friend`, `craftsperson`, `doctor`, `tutor`, `neighbor`, `tenant`, `other`. День рождения: `YYYY-MM-DD`, `--MM-DD` либо `null`. Ссылки мессенджеров принимают HTTP(S). Неуказанные поля получают пустые значения.

`GET /api/contacts`: фильтры `kind`, `category`, `organizationType`, `scope`, `q`, `trash`, пагинация `limit`/`offset`; возвращает массив карточек. `GET /api/contacts/:id` — одна карточка. Ответ содержит поля записи, `kind`, `data`, видимые `organizationId`/`organization`, а также `actions`: нормализованные телефоны `tel:`, адреса `mailto:`, ссылки мессенджеров и адрес для карты. Скрытая/удалённая организация возвращается как `null`.

`PATCH /api/contacts/:id` принимает `expectedUpdatedAt` и изменяемые поля; `data` передаётся целиком. Конфликт версии — 409. `POST /:id/move` меняет место по общим правилам; `DELETE /:id` помещает в корзину; `POST /:id/restore` восстанавливает; `GET /:id/history` возвращает историю. Все сокращённые пути имеют префикс `/api/contacts`.

Связи OBJ-2 принимают человека как контакт; роль-подпись и блок объекта `peopleAndOrganizations` работают для обоих видов.

## Взаимодействия

`GET /api/contacts/:id/interactions` — лента контакта, `POST` на тот же путь — создание. Поля: `kind` (`call`, `visit`, `message`, `work`), `occurredOn` (`YYYY-MM-DD`), `text`, необязательные `amountCents` (неотрицательное безопасное целое либо `null`), `callAgain` (boolean либо `null`), `objectId` (UUID либо `null`). Место и родитель задаются контактом.

`PATCH /api/contacts/:id/interactions/:interactionId` принимает полные поля взаимодействия и `expectedUpdatedAt`. `POST .../trash` — корзина, `POST .../restore` — восстановление, `GET .../history` — история. Перенос и корзина контакта распространяются на взаимодействия; независимая корзина дочерней записи сохраняется при восстановлении родителя.

Ответ содержит видимый объект либо `null`; UUID скрытого/удалённого объекта не выдаётся. В ленте объекта источник `interaction` появляется только при одновременном доступе к объекту, контакту и взаимодействию. Поиск находит ФИО и названия организаций; чувствительные поля и тексты взаимодействий не индексируются. Экспорт содержит доступные контакты, взаимодействия и историю, удаляя ссылки на скрытые цели.

## Сроки документов

`GET /api/document-types` отдаёт предупреждения по типам. `data.warnings` документа переопределяет их, включая `[]`. В ответе документа `warnings` — эффективные предупреждения, `expiryRule` — производное правило срока либо `null`; фильтр срока списка учитывает вычисленное окончание окна замены.

У паспорта РФ `data.expiresOn` важнее возраста; `indefinite` выключает срок. Иначе полная дата рождения берётся из профиля владельца-участника либо контакта-человека, только если она видна всем читателям документа. Граница 20/45 лет образует окно на 90 дней, предупреждения приходятся на 60/30 дней до дня рождения. 29 февраля в невисокосный год считается 28 февраля. Часовой пояс берётся у дома срока. Без полной доступной даты рождения новый срок ожидает данные без активных наступлений; изменение даты пересчитывает правило и обновляет радар через существующий обработчик сроков. Если контакт стал закрытым для части читателей документа либо профиль владельца им недоступен, сохраняется последнее известное правило при смене даты и любой правке документа, независимо от доступа редактора к источнику даты. Этот же барьер применяется при заполнении новых сроков миграцией 0049.
