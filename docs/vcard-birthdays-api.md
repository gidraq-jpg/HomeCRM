# R1b.4–5. Контракт vCard, дней рождения и дополнений API

## Импорт

`POST /api/contacts/import`, авторизованный участник, ответ 200, без кэширования.

Предпросмотр: JSON `{fileName:"contacts.vcf",content:"BEGIN:VCARD…",placement?:{spaceId,audience?}}`. Либо multipart с одной файловой частью `.vcf`; место — query `spaceId`, `audience`. Только предпросмотр, без дополнительных частей. Ограничения: 512 КиБ, 500 карточек; vCard 3.0/4.0, UTF-8 и quoted-printable. Фото пропускаются. Личные контакты по умолчанию — личное пространство; явно выбранное общее без аудитории — «Вся семья».

Ответ: `{previewHash,placement:{spaceId,spaceKind,audience},items:[{index,title,data,organization,matches:[{id,title,updatedAt,canMerge}]}]}`. Телефоны нормализуются без пробелов, скобок, точек, дефисов и `+`; российский префикс 8 заменяется на 7. Скрытые и удалённые контакты не участвуют.

Применение: тот же JSON файла и места плюс `{mode:"apply",previewHash,idempotencyKey,choices}`. Для каждой карточки ровно один выбор:

- `{index,action:"create"}` — создать отдельно.
- `{index,action:"merge",contactId,updatedAt}` — объединить с выбранным совпадением из предпросмотра.

Все записи применяются одной транзакцией. Непустые имя, адрес, дата, связь с организацией и настройка напоминания сохраняются; телефоны/e-mail дополняются, заметка дописывается. Ответ `{contactIds:[…],replayed:boolean}`, в порядке карточек. Повтор того же запроса с тем же ключом возвращает UUID без новых записей. Другой выбор/файл/место с тем же ключом — `409 IDEMPOTENCY_CONFLICT`; изменённый контакт — `409 STALE_VERSION` или `IMPORT_TARGET_CHANGED`. Недоступная цель — 404/403; частичных изменений нет.

Битая карточка — `400 INVALID_VCARD` с понятным сообщением без содержимого. Неправильная граница — `400 INVALID_INPUT`; неверный выбор — `INVALID_IMPORT_SELECTION`; превышение лимитов частей/файла — 413. Слишком много итоговых телефонов/e-mail или слишком длинная заметка при объединении — `409 IMPORT_FIELD_LIMIT`.

## Дни рождения

У человека `data.birthday` — `YYYY-MM-DD` либо `--MM-DD`, `data.birthdayEnabled` — boolean, по умолчанию false. Обычный PATCH контакта передаёт полный объект `data`, как прежде. В профиле: `PATCH /api/me/profile {birthDate,birthdayEnabled}`; GET профиля и участники дома включают `birthdayEnabled`.

`GET /api/deadlines?from=YYYY-MM-DD&to=YYYY-MM-DD` дополняет пункты:

- `sourceKind:"birthday"`, `contactId` либо `profileAccountId`, название видимого источника.
- `birthday`, `age`: null без года, иначе возраст на дату наступления.
- `date`, `warningsAt`, `rule`: ежегодное наступление и предупреждения 7/1 день в 09:00 дома. 29 февраля → 28 февраля в невисокосном году.

Наступление видно только при доступе к дате источника. Выключение, корзина или утрата доступа скрывают его сразу. Просроченные дни рождения не выдаются. Радар обрезает горизонт от сегодняшней даты в поясе наступления: 90 дней для обычных источников, 365 для документов/дней рождения. Группа `later` дальше 90 дней требует начавшегося предупреждения. Клиент может продолжать передавать 366 дней или более широкий диапазон.

Push использует существующую настройку вида `deadline` и ответственного источника. При скрытом тексте — «В HomeCRM есть новое», иначе — «День рождения: <имя>». Текущий доступ проверяется при постановке и перед отправкой.

## Дополнения API

- Создание начисления `/api/accounts/:id/charges` и оплаты `/api/charges/:id/payments` принимает необязательный `idempotencyKey` UUID в JSON. Старые запросы допустимы. Повтор ключа возвращает ту же запись под текущими правами; другой запрос/родитель/вид с этим ключом — 409. Возвращается актуальное состояние записи, включая отмену.
- `POST /api/deadlines/occurrences/:id/complete-payment` возвращает `paymentId` новой оплаты либо null, если оплата не создана. Ответ по начислению сохраняет `chargeId`; повтор уже погашенного начисления не создаёт оплату.
- Пункт радара начисления получает `totalCents`, `paidCents`, `remainingCents` — целые копейки; у других пунктов null. Остаток ограничен снизу нулём; отменённые оплаты исключены.
- Объекты `/api/utilities/month` получают `spaceId`, `spaceKind`, `audience`.
- Карточка и список документов получают `objectTitle`, `ownerContactTitle`; недоступный/удалённый источник — null. `GET /api/documents/:id` также возвращает `files` — живые файлы с метаданными существующего `/api/documents/:id/files`. Указатель и название скрытого контакта не выдаются.

## Данные и проверка

Флаг контакта, флаг профиля и ссылки доступных сроков включены в ZIP v1; служебные ключи повторов не экспортируются. История импорта хранит отметку, сам файл не сохраняется. Поиск, корзина и перенос контакта используют прежний механизм записей. Миграции после 0049 не включают уведомления старым участникам автоматически.

Тесты проверяют три карточки, видимость совпадений, атомарность, сохранение полей и конкурентный повтор, multipart-границы, 29 февраля, возраст/неизвестный год, выключение, push, матрицу ролей и домов, обновление 0049, долги API и прежний порог радара.
