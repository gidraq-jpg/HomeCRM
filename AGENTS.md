# Правила для ИИ-агентов в HomeCRM

HomeCRM — семейное веб-приложение (PWA): дом и коммуналка, документы, контакты, дела, заметки. У каждого участника своё личное пространство, у семьи — общее пространство дома.

Перед работой прочитайте:

- [PRD](docs/02-prd.md) — что строим. Требования пронумерованы: AUTH-1, SPACE-3, UTIL-5…
- [План разработки](docs/03-dev-plan.md) — архитектура, этапы, процесс.
- [ADR](docs/adr/README.md) — принятые технические решения и их причины.

Владелец продукта пишет по-русски. Документы, комментарии в коде и тексты интерфейса — на русском. Сообщения в журналах сервера — на английском: так их без искажений показывает любая консоль.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm install` | Ставит зависимости и подключает ловушку git перед `git push` |
| `pnpm dev` | Сервер (`127.0.0.1:8310`) и клиент (`127.0.0.1:5173`) в режиме наблюдения |
| `pnpm check` | Всё, что проверяет CI: кодировка, формат и линтер, типы, тесты |
| `pnpm format` | Исправляет формат и порядок импортов |
| `pnpm test`, `pnpm test:watch` | Тесты Vitest |

Окружение: Node 24, pnpm 12 (версия закреплена в `package.json`). У владельца — Windows 10 и PowerShell 7, в CI — Linux.

## Карта репозитория

| Путь | Что там |
|---|---|
| `apps/web` | Клиент: React 19 + Vite, PWA |
| `apps/server` | Сервер: Fastify; API и, позже, обработчик фоновых задач |
| `packages/shared` | Общее для клиента и сервера: правила доступа, схемы, типы |
| `tools/access-probe` | Временная заглушка для замеров этапа 0 |
| `deploy` | Compose, туннель, настройка VPS, скрипты эксплуатации |
| `docs` | Исследование, PRD, план, ADR, замеры этапа 0, runbook |

## Обязательные правила

### Безопасность и данные

1. Никогда не выводите, не записывайте в журналы и не коммитьте секреты: пароли, токены, ключи, значения `.env`, содержимое `E:\HomeCRM-data\secrets`. Если секрет нужен программе, он читается из файла окружения во время работы.
2. Работайте только внутри репозитория. Папка `E:\HomeCRM-data` с рабочими данными — только через скрипты из `deploy/scripts`.
3. В тестах, фикстурах и на скриншотах — только вымышленная семья. Настоящие данные семьи в репозиторий не попадают.
4. В журналах нет названий, номеров и текстов записей (PRD, раздел 13).
5. Выпуск в рабочее окружение, изменения на VPS и в DNS — только по прямой команде владельца.

### Личное остаётся личным

- Правила доступа — в `packages/shared/src/access.ts`. Политики RLS в базе и проверки на сервере обязаны давать тот же ответ; матрица доступа в CI сравнивает их с этим модулем.
- Администратор не видит чужое личное. Никаких служебных обходов проверки доступа в коде приложения.
- Новая сущность с пользовательскими данными добавляется только вместе с:
  - полями доступа: пространство, аудитория, автор, ответственный, отметка удаления;
  - политикой RLS;
  - строками в матрице доступа;
  - решением о поиске;
  - экспортом;
  - поведением корзины.

### Код

- TypeScript в строгом режиме. Сервер запускает `.ts` прямо в Node, поэтому синтаксис только стираемый: без `enum`, `namespace` и свойств-параметров конструктора. Вместо `enum` — массив `as const` и объединение типов.
- Относительные импорты пишутся с расширением: `./app.ts`, `./App.tsx`.
- Данные на границах — HTTP, переменные окружения, импорт, очереди — проверяются схемами zod.
- Деньги — целые копейки. Моменты времени — UTC (`timestamptz`). Даты без времени — отдельный тип. Сроки считаются в часовом поясе дома.
- Ошибки не проглатываются: либо обработка, либо проброс с контекстом.
- Новая зависимость — только с обоснованием в описании изменения; заметное решение — с ADR в `docs/adr/`.

### Тексты и кодировка

- Все файлы — UTF-8 без BOM, переводы строк LF.
- После правки русских текстов запустите `pnpm check:encoding`. Он ловит следы поломки кодировки: `????`, `�`, `Рџ`, `Ð`. <!-- encoding-check: ignore-line -->
- Пишите из PowerShell 7: он сохраняет UTF-8 по умолчанию. Windows PowerShell 5.1 не используйте.
- Тексты интерфейса — по PRD, раздел 13: правильные формы множественного числа, даты вида «5 окт.», суммы в рублях.

### Интерфейс

- Изменения интерфейса проверяются в Playwright на ширине 360 и 412 px вместе с axe; скриншоты прикладываются к задаче.
- WCAG 2.2 AA, цели нажатия от 44 px, без горизонтальной прокрутки на 360 px.

### Процесс

- Требования меняются сначала в PRD, потом в коде.
- Порядок: ветка → коммиты → `pnpm check` → запрос на слияние → слияние в `main` при зелёных проверках.
- Имя ветки: `<тип>/<требование>-<кратко>`, например `feat/util-5-meter-validation`.
- Сообщение коммита начинается с номера требования PRD (`UTIL-5: проверка показаний`) или задачи плана (`0.2: заглушка для замеров`).
- Запрещено: `git push --no-verify`, `git push --force` в `main`, слияние с красными проверками. На бесплатном тарифе GitHub технически этого не запрещает — правило держится на вас.
- Код пишет один агент за раз. Параллельно — только исследование и проверка.
- Задача готова, когда выполнены условия раздела 3.2 плана.
